# 双模式工作区（云 + 本地）

> **定位**：给每次协作一个持久项目空间；云与本地**平等**——**不给用户云/本地开关**，模式跟着「文件在哪」走。
>
> **边界**：Backend / 绑定 / Sidecar / 共享空间 / 案卷目录。记忆注入 → [记忆系统](/docs/03-AI核心/Agent记忆与知识系统.md)；文件树 UX → [前端 UX §九](/docs/04-前端/前端UX设计.md)。
>
> → 见代码: `apps/server/agentcore/workspace/`

---

## 一、两种模式平等

- **内核**：多 Agent 在同一张「桌子」上靠文件协作；「在不在本地磁盘」是第二层偏好。
- **云** = 零前提起点（打开即用、可隔离协作）；**本地** = 平等的另一种（开发者内环改真实仓）。
- **无开关**：模式由绑定自动决定；「云优先 / 本地优先」只是构建顺序。

## 二、三正交轴与拒绝实时同步

| 轴 | 取值 |
|---|---|
| 轴1 执行位置 | server / local |
| 轴2 文件源头 | server dir / local dir |
| 轴3 持久化 | S3 快照 / 仅本地盘 / ~~实时同步~~ |

「云 / 本地模式」= 轴1+轴2 一整套。所谓「本地默认云储存」= `local + local + cloud`——**不是第三种模式**，而是 LOCAL 的存储策略：

- ✅ 接受快照 / 交接（git-push 式）：本地唯一真相源，按需经 `StorageProvider` 快照到 S3。
- ❌ **拒绝实时双向同步**（Dropbox 式）：双真相源 + 冲突，在并行 Agent 并发写下尤其致命。

## 三、`WorkspaceBackend` 抽象原则

沿用 Protocol + 实现 + 工厂（同 `LLMProvider` / `SandboxProvider`）。引擎与工具只对接口编程。

- **护栏·瘦接口**：持久化（snapshot/restore）**不进 backend**——属轴3，归独立 `StorageProvider`。backend 只管「文件 + 执行」这对必须同源的能力。
- **为何 P0 引入**：本地是已承诺路线；接口先行使加 `LocalWorkspace` 时工具/引擎零改动。
- **唯一接缝**：`ToolContext.workspace_dir` → `backend: WorkspaceBackend`；`code_execute` 收编进 `backend.execute`（与文件同目录）。

→ 见代码: `apps/server/agentcore/workspace/`

`ServerWorkspace`：服务端目录 + 同进程沙箱。`LocalWorkspace`：用户真实本地目录 + 桌面执行；传输不另造——把审批门「挂起 + HTTP 回填」泛化为 `WorkspaceChannel`。Sidecar 文件 op 直连本机（不经 channel），但后台进程仍交主进程代持（sidecar 生命周期短于 dev server）。

## 四、案卷目录约定

多幕协作副产物落工作区约定目录。**否决**另建「会话级团队案卷」实体——复用既有项目/工作区文件心智。全部挂在 `AgentCore/文档/`（产品心智 = AI 文档统一入口；**不**进 `<rules>` 注入）。

| 目录 | 谁写 | 谁读 |
|---|---|---|
| `AgentCore/文档/research/` | MLR / 自由讨论 / 竞品笔记（`form=files`） | 后续辩论 + 主持人索引 |
| `AgentCore/文档/debate/` | 辩论收场机制 | 用户 / 后续回合按需读 |
| `AgentCore/文档/reviews/` | 审查类 `form=files` | CEO 汇总 / 用户按需 |

落盘与 handoff 摘要正交：结构化 handoff 走委派通道；完整报告叠加写文件。`<workspace_context>` 只陈述布局，不注入正文。案卷类委派由运行时按 `stage_dirs` 填默认 `artifact_dir`。

**否决**：案卷与 `AgentCore/{规则,记忆}`「两根并存」——改为统一挂 `AgentCore/文档/`；规则/记忆仍仅 documents 注入。

机制 → [编排器 · MLR](/docs/03-AI核心/编排器与CEO主Agent.md)、[辩论编排](/docs/03-AI核心/辩论编排设计.md)；根夹 → [记忆 §5.0](/docs/03-AI核心/Agent记忆与知识系统.md)。

## 五、绑定：项目即工作区 · 裸聊默认云

- **项目 = 工作区**：Folder 必声明 `mode`；绑定不可改；会话归入项目则继承；**出生定终身**（无中途改 folder）。
- **打开文件夹 = 本地项目**：所选目录 → `mode=local`、`local_subpath` 空、根=该目录；建/复用 Folder + **新会话**挂 `folder_id`。**禁止**把当前裸聊 auto-promote 成 Folder（不写现会话 `folder_id`）。
- **`bind_local_folder` ≠ 打开项目**：仅把裸聊 scratch 绑到本机执行环境（`conversations/<id>`）；文案与产品心智不得冒充「打开仓库 / 打开项目」。
- **裸聊**：默认云 `conv:<id>` scratch；桌面新建默认云执行；显式绑本地才用容器根下 `conversations/<id>/`。
- **路由**：读生效绑定 → Local / Server；无云/本地开关。
- **用户心智**：「你的文件在哪，AI 就在哪干活；没给文件，就在云上干」。

**裸聊默认云的理由**：① 关桌面任务停是 Multi-Agent 长任务硬伤（云可续跑）；② 大众交付形态是「云预览 + 一键导出」；③ 多端可见；④ 混合态下对话本就回写云，隐私论点不支持 local-first。开发者「指着本地文件干活」由**打开本地项目**完整保留；本会话临时要本机跑通仍可用 bind。

**否决**：auto-promote 裸聊为 Folder；会话中途改 folder；桌面裸聊 local-first（被默认云替代，容器根与显式本地绑定仍保留）。

云 scratch 产物导出 = 预览 + 一键导出（git-pull 式单向 checkout，与 §二 快照语义对称）。免费档**不为云执行新增配额维**——推理配额天然封顶；真实负载后再议。

## 六、关键边界

| 项 | 约束 |
|---|---|
| 路径 | 相对工作区根 POSIX；裸 `/` 与 `\` → `.`；其它绝对路径拒。禁止工具私有 `if path=="/"` |
| 归属变更 | **不支持**事后移入项目；文件搬运是显式动作、MVP 不做 |
| 删除 | 软删可逆（本地回收站 / 云 `.agentcore/trash/`）；超保留期物理清 |
| 本地并行团队 | 单桌面通道是瓶颈；正解 = 本地内环 + snapshot 交接云端跑并行 |
| 引用区外文件 | 单文件复制进 `attachments/`；**否决**区外绝对路径直读。对话级目录授权（readonly / organize）与绑定**正交**：桌面在线即可授权（云端 scratch 亦可），挂载为 `external/<别名>/…`，经桌面通道按 `root_id` 履行；不改 binding。看本机目录只走 grant，不走 open_project/bind。**对话级持久**：重启不丢；服务端只存 alias/root_id/mode，桌面持绝对路径（`fs-session-grants.json`） |
| 多 worker | 锁/审批门/通道/handoff 现为进程内态；多机需 Redis + durable queue ⏳ |

HTTP / `ws_id`（`folder:` / `conv:` / `shared:`）→ 见代码: OpenAPI + `workspace/locate.py`。本地 `location=="local"` 时 REST 写/索引返回 409；只读 snapshot list/download 放行。

## 七、Sidecar 关键约束

比 `LocalWorkspace` 更深一层：引擎本体搬到桌面子进程跑同一 `run_chat_pipeline`，工作区直连本地盘。

- **路由**：绑本机本地文件夹的对话默认走 sidecar（含**打开本地项目**的 Folder 会话，以及裸聊 `bind_local_folder` 后的 scratch）；裸聊未绑 / 云项目 / 带附件走云。「本地引擎」默认开、可关（三态偏好，翻默认不误开显式关过的用户）。启动失败（出输出前）自动降级云；中途失败不降级。**bind ≠ 打开项目**——前者只换本会话执行环境，后者建/复用 Folder + 新会话。
- **健康 ≠ 路由**：健康只决定「要不要拉起」，**不掺进绑定判定**——否则污染续跑 / 列暂停帧。
- **Office 文档能力（云 = 本地）**：附件分流预解析（docx/pdf/pptx 等 → 可读 `*.md`）与确定性 `md_to_docx` 在云 API 与 sidecar **同能力**。依赖在 `pyproject` 主依赖与 `[project.optional-dependencies].sidecar` 对齐；`bundle:sidecar` 冒烟校验 `docx` + markitdown 抽取 + md→docx。**否决**为瘦身砍掉 Office 却仍跑同一管线（缺库 → 整轮 `PIPELINE_ERROR`）。预解析失败仍不阻塞回合（路径提示回落）——那是解析语义，不是「平面缺依赖」。
- **岔路 B（否决 A）**：平台 key 不下放；推理经云代理；计费权威在云、不从客户端上报。
- **持久化**：sidecar → 本机 outbox → 主进程回写云；Renderer 退出回写职责。混合态下对话正文全量回写云——**不得承诺「数据不出本机」**。
- **挂起帧**：settlement 预写即消费帧（决策即事实，不还帧）。**否决**：保留帧 + journal 对账改写 paused[]（双真相源对账 = 补丁绊线禁止形态）。挂起帧与 outbox **不并同一状态机**。
- **恢复面不变量**：本地引擎默认开 ⇒ 恢复面必须与云对齐；任一侧默认路由变更须重估另一侧。路由意向 ≠ 恢复事实——刷新后无条件并行查本地+云。
- **产品对外（档 A · 断线只读）**：断网/服务不可用时可浏览已缓存对话与本机文件（只读）；不能发送、改文件、跑 AI。「本地引擎」= 本机执行更快，**不是**离线模式（推理仍经云）。**完全离线**（本地推理 + 本地消息库）⏳，详细提案不在公开仓。

→ 见代码: `apps/server/agentcore/sidecar/`；打包 `apps/desktop/scripts/bundle-sidecar.mjs`；预解析 `workspace/attachment_parse.py`。

## 八、共享空间 vs 项目工作区

跨用户云端共享文件空间（成员制协作），与「公开分享」（对话只读快照）是两回事；与项目（Folder）**平行、独立实体**。

| | 项目工作区 `folder:` | 共享空间 `shared:` |
|---|---|---|
| 本质 | 会话分组 + 记忆 + 工作区三合一 | 只有「文件」一个面 |
| 归属 | owner 独占 | 成员制（viewer / editor / owner） |
| 挂载 | 会话继承项目绑定 | 会话级挂载为云端第二根 `shared/<别名>/` |
| 本地 | 可绑本地 | **仅云**（否决本地共享 / 双向同步） |

**否决 Folder+成员**：鉴权面圈死在新模块，免在「owner 独占」不变量上开洞；免每个 Folder 功能都要答「成员可见吗」。重启条件：若做「成员对话进项目、共享记忆」的完整项目协作，再交 `folder_members` 治理税。

其它边界：仅定向邀请（不做链接加入）；可编辑成员的 Agent 可直写（角色即授权，不加第二道门）；**仅云执行对话可挂载**（sidecar 无跨运行时双根）。v1 不做：公开文件链接、实时协同、成员对话/共享记忆、组织概念。
