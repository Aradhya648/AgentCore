# 后端架构

> 目标模块体系与分层约定。目录树 → [项目结构](/docs/02-架构/项目结构.md)；契约 → [核心接口](/docs/02-架构/核心接口定义.md)。

## 一、五层分层

`models → schemas → repository → service → router`，单向不可反转。

| 层 | 职责 |
|----|------|
| models | ORM（约定 → [核心接口 §6.2](/docs/02-架构/核心接口定义.md)） |
| schemas | request / detail / list 分层 |
| repository | 纯数据访问，无业务逻辑 |
| service | 多 repo / 编排 / 外部副作用时才设 |
| router | 薄层；**简单 CRUD 可直接注入 repository**（避免空透传） |

## 二、模块边界（代码看不出的）

模块清单 → `apps/server/agentcore/`。易误判：

- 无 `user/` 包 → 实为 `auth/` + `security/`（[认证与会话](/docs/05-平台与运维/认证与会话.md)）
- 导出 / 公开分享内建于 `conversation`（非独立 `share`）
- 审批 / 自治档 → [安全 §三](/docs/05-平台与运维/安全权限与治理.md)；计费队列 → [成本配额](/docs/05-平台与运维/成本配额与计费.md)
- 创作工具产物共用 `file` + `table`，不另起存储
- BYOK key 在 DB per-user，不在 `config/platform.py`

**⏳ 有意未建 / 未完整**：`agent` CRUD（MVP 用动态 `delegate`）、`capability` 市场；`messaging` 内测群 ✅，多 worker 实时 ⏳；`file` RAG ⏳。

**✅ 已接线（勿再标 ⏳）**：站立任务 L1（定时 `scheduler`）+ L2a（Webhook）——`standing_tasks/` + 桌面 Toolbox；mobile/admin 有意未接。详见 [产品路线图摘要](/docs/01-产品/产品路线图摘要.md)。

## 三、runtime 例外

目录即关注点 → `runtime/`。例外：memory 无独立子包（散在 `runs/` + `runtime/context/` + `agentcore/memory/`）；suspend 在 `suspension*.py`；sandbox 在 `tools/sandbox/`；CEO 编排原语在 `tools/builtin/`。三模型 → [运行时三模型](/docs/03-AI核心/运行时三模型与挂起.md)。

## 四、垂直能力开关

`config/features.py` 编译期布尔（非插件贡献点）。`simulation_enabled`（默认开，关→404）；`legal_vertical_enabled`（默认关，开→全员 registry）。路由一律 `include_router`；启停在处理层 / 部署总闸。核心不反依赖垂直。

## 五、评估体系

立场：以**任务结果**为中心，否决「把轨迹手段当门禁」。L0 契约硬门 ✅ · L1 结果质量主轴 ✅ · L2/L3 ⏳。轨迹形状 check 仅诊断（`gating=False`）。**合成 evals ≠ 真实数据**——优化前须声明证据性质。夹具必须 `copytree` 隔离。→ `agentcore/evals/`；跑法 → [本地开发 · evals](/docs/02-架构/本地开发.md)；门禁 → [发布与门禁 §九](/docs/05-平台与运维/发布与门禁.md)。

## 六、日志

How（格式 / 禁止项 / logger API）→ `.cursor/rules/logging.mdc`。排查配方 / 词表 → [对话日志分析指南](/docs/05-平台与运维/对话日志分析指南.md)。本文只留接缝：`trace_id` 是一次用户交互全生命周期键，已落 `messages` / `cost_events` / `run_sessions`；进程内 asyncio 下 `contextvars` 自动随 worker 传播。
