## 2. 启动后端

```bash
cd apps/server
cp .env.example .env
# 必填：生成 ENCRYPTION_KEY（.env.example 中为占位符，勿用于生产）
#   python -c "import secrets; print(secrets.token_hex(32))"
# platform 模式再填 PLATFORM_API_KEY 等；BYOK 默认模式登录后在设置页配 key
uv sync                       # 仅运行依赖；跑测试/lint 需 uv sync --extra dev
uv run alembic upgrade head   # 应用数据库迁移（DEBUG=true 时启动会自动执行，此步可跳过）
```

**Windows 推荐**用清树脚本启动（先按命令行白名单杀掉旧的 `python -m agentcore` / `uv run …` 整棵进程树，确认端口无 LISTEN 再起新实例）：

```powershell
powershell -File apps/server/scripts/start-dev-server.ps1
```

**并行 Agent 纪律**：重启脚本自带真跑保护——杀树前读 `logs/dev.jsonl` 末行时间戳，活跃期内（默认 120s）拒绝重启（非零退出）；`-Force` 强杀须知情。`AGENTCORE_RELOAD=false` 只防 WatchFiles，防不了本脚本的主动清树。

手动启动（端口空闲时）：

```bash
uv run python -m agentcore
```

`python -m agentcore` 从 `.env` 读取 `HOST` / `PORT` / `DEBUG`（默认 `0.0.0.0:8000`，`DEBUG=true` 时热重载）。与 VS Code 自动启动任务一致。启动前会预检目标端口：若已被占用则立即报错退出（非零码），避免 Windows 上多实例静默共存、孤儿 worker 继续服务旧代码。**dev（`DEBUG=true`）启动时自动 `alembic upgrade head`**（`db/migration_check.py`；成功升级打 `db.migrations_upgraded`，失败不阻断启动、回落 drift 告警）——多 worktree 并行下别的分支合入迁移后，本地重启即对齐，无需手动跑；prod 不自动动 schema，迁移仍是显式部署步骤。

**长时间真跑协作场景前，先关热重载**：`.env` 加 `AGENTCORE_RELOAD=false`（独立开关，不必动 `DEBUG`，缺省沿用 `DEBUG` 原逻辑）。WatchFiles 检测到任意 `agentcore/` 文件保存就会重启 worker（宽限期仅 2s），会打断正在跑的多 Agent 回合——多 Agent 并行改码 + 同一台 reload 后端真跑 = 互相残杀。恢复热重载：删掉该行（或改 `true`）再重启。启停均打 `server.started` / `server.shutdown` jsonl 事件，可在 `logs/dev.jsonl` 复盘重启时刻。graceful lifespan 关停会按 `/stop` 语义抢救收口（已有产出落盘、lease 显式释放）；真硬杀 / 崩溃仍走 orphan / sweeper（见 [`执行引擎 · 边界与硬杀韧性`](/docs/03-AI核心/执行引擎架构设计.md)）。

**DEMO_TAPE 与热更新**：开磁带回放 / 录制相关开关时同样会关掉或干扰 WatchFiles 热更新路径——真跑验收前勿与热重载叠开；配方与磁带用法见 [`demos/README.md`](/demos/README.md)。

**手动重启必须杀整棵树**：`taskkill /F /T /PID <pid>`（`/T` 必带）。只杀子进程会留下幽灵 reload worker 继续占端口、跑旧代码；只杀父进程同理。Windows 上旧 server 杀不干净会导致双进程打架（端口看似占用、请求打到旧代码）。清理后应只剩一个 LISTEN 在目标端口上的健康实例。

## 黄金场验收（LV 案两幕 · 常备端到端场景）

多幕团队协作的常备验收场：**LV×茉莉奶白商标案**两幕真跑——幕1 MLR 四透镜调研落盘 `research/` → 阶段推进卡一步开辩 → 幕2 辩论同图生长（证人质询 + 证据台账 + 双产物落盘 `debate/`）。全程约 1–1.5h、数百次 LLM 调用。

- **验收职责边界**：离线六环 `mlr_golden_rings_check.py` = **验收权威**（可复跑门禁）；真跑驱动 `_mlr_two_act_verify.py` **已降级**为仅「把两幕跑起来」的脚手架，不做判定（见脚本头注释 DEPRECATED）。
- **驱动**：`apps/server/scripts/_mlr_two_act_verify.py`（真跑脚手架，会调 LLM）。
- **验收权威 = 离线六环检查器**：`uv run python scripts/mlr_golden_rings_check.py <conversation_id>`（判据模块 `agentcore/conformance/mlr_golden_rings.py`，只读 DB journal + 工作区文件、零 LLM；exit 0 = 六环全 PASS，正 / 负样本 pytest 钉死）。六环 = 宿主附着 / 调研落盘与命题卡保真 / 推进卡结算 / 辩手检索预算 / 证据台账登记 / 双产物与四维收官。
- **判据设计决策**（2026-07-20 定案）：① 环3 以 **journal 为权威**——SSE 全绿 ≠ 落库（settlement 撞键 bug 正是在线全绿、落库丢行，见 [执行引擎 §8.3](/docs/03-AI核心/执行引擎架构设计.md)）；② 环4 检索判据 = **机制对齐**（产品确认）：任一辩手 run **成功完成**的检索数超其机制预算（有案卷 4 次/run）即 FAIL，被引擎拒绝的超发起**不占槽**（那是预算机制在工作）；场级总量 / 分侧数降为观测指标。旧「场级天花板 28」（污染基线 56 的对半裁）废除——与轮次数、子 run 数隐性耦合，56 仅存档。
- **已知数据缺口**（诚实标 gap、不硬造）：机制直起路径 `background_len` 常为 0（以 `dossier_index_len` 代理案卷注入量）；journal 缺 `turn_id` 映射时分幕费用标 None。
- **真跑纪律**：窗口内**禁止重启后端、禁止改 `agentcore/` 代码**（reload 与重启脚本清树都会杀跑，见 §2 真跑保护锁与 `AGENTCORE_RELOAD`）；evals / 批量 probe 等重活**永不与黄金场并行**（共享上游 key 会互相争限速）。

## evals 评测跑法（常备）

离线评估框架（`apps/server/agentcore/evals/`）真跑出数的标准姿势。首轮全量出数已完成（2026-07-21，P1 步 0–7 + 16 用例 compare），此后按需回归。

> **数据性质（优化前必读）**：本目录用例与跑分是**合成 evals**，**≠** 真实用户数据。dogfood 真轨迹 = `logs/dev.jsonl` ⋈ Postgres（查法 → [对话日志分析指南](/docs/05-平台与运维/对话日志分析指南.md) / `conversation-logs.mdc`；join 脚本已有：`log_timeline` + `observability.query`）。目前无真实流量金标准——改行为前先声明证据是合成还是 dogfood。

**防崩配置**（终端会话内设，再起 CLI；不设裁判模型名会发 `deepseek-v4-pro` 被部分中转拒名 → layer≥2 崩溃）：

```powershell
$env:EVAL_JUDGE_MODEL="5.2"; $env:EVAL_DEBATE_MODEL="5.2"; $env:EVAL_DELIVERABLE_FORM_MODEL="5.2"
# EVAL_DEEPSEEK_API_KEY 不用设：凭据缺省自动回落 .env 平台凭据
```

**渐进跑序**（便宜 → 重；`apps/server` 下 `uv run python -m agentcore.evals …`）：`--lint-only`（0 调用）→ `--suite probe --layer 1` → `--layer 1`（core L1）→ `--calibrate`（kappa ≥ 0.6 才可信裁判分）→ `--out`（core L2 含裁判）→ 诊断子命令（`--routing` / `--debate-speech-format` / `--deliverable-form` / `--debate-converge` / `--style`）→ `--suite mast` / `--suite collab_shapes --plan-only` → `--compare`（最重，~2000–3000 次调用）。

**判读纪律**：先裸分 → 校准过门 → 数字合理再 `--update-baseline`（容差 0.05）；禁止拿未校准/大面积 error 的首跑建 baseline。FAIL 分诊三类：环境/配置（429、key、egress）→ 修环境重跑；模型弱（工具参数不稳、JSON 解析失败）→ 记录不修码；框架 bug → 根因修复。裁判 JSON 解析失败 = 优雅降级 0 分，API 调用失败 = 崩溃——症状要分清。裁判与被评同模型时自偏好偏置存在，成对裁判 swap 抵消位置偏置仍有效，`--calibrate` 更必要。

**长跑操作经验**（免费中转环境实测沉淀）：

- 评估批一律**分离进程**跑（`Start-Process` + 状态文件 + 日志重定向），IDE 后台终端会被回收殃及子进程。
- `--compare` 等小时级重活按**单用例粒度**拆（独立 `--cases-dir` + 独立 `--out`），撞限流/502 故障窗只损当前用例；上游恢复探测（连续 2 个 200）后重拉失败用例即可。配额充足时单用例进程可并行，latency 指标互染不采信，win_rate/cost 不受影响。
- 免费中转限流窗常为**小时级**（`Retry after 3600s`），撞上后等窗口而非硬重试。

**探针矩阵**（P2 功能面真跑入口，`apps/server/scripts/`）：`probe_turn.py`（CEO 单聊 + SSE 时序 + 通用手驱）、`probe_egress.py` / `probe_search_engines.py`（联网基础设施，无 LLM）、`probe_shared_spaces.py`（共享空间 REST）、`probe_ask_gate.py`（CEO 第一动作路由门）、`probe_code_execution.py`（代码生成+沙箱）、`run_research_probe.py`（delegate 编排）、`probe_legal_war_room.py`（垂直 skill+辩论+派单 e2e）、`probe_resume_memory.py`（挂起-断线-恢复-记忆）、`probe_free_tier.py`（免费额度计费）、`eval_team_bench.py`（team 指标基准，需 SearXNG 健康）、`probe_sim_tick.py`（AI 小镇，需 `SIMULATION_ENABLED`）。探针不在 CI 门禁内、随主干演进易腐化——跑不起先怀疑探针漂移（历史修复见 git：`_assemble_ceo_toolset` 元组数、`ProfileParams` 去 model 化、resume decision 收紧、falsy-zero）。

## 排障：`read_url` / `web_search` 全失败（本机代理 fake-IP）

**症状**：开发机上 `read_url` 每次瞬间（~1ms）返回 `[ERROR] 链接解析到私有/保留地址，已按 SSRF 防护拦截`，`web_search` 超时或返回英文噪音——即便公网正常、对照域名（`baidu.com` / `gov.cn`）也一样。

**根因**：本机**本地代理 / VPN 的 fake-IP 模式**（Clash / Mihomo / Surge / v2rayN 默认 `fake-ip-range = 198.18.0.0/16`）把**所有**域名 DNS 应答成 `198.18.0.x`（RFC 2544 保留段）；应用「自解析 DNS + Pin IP」的 SSRF 守卫（`core/net.py`）判其为保留段 → **正确拦截**。**非产品缺陷、非 ISP 劫持；生产服务器无此代理、不受影响**（SSRF 保持严格是有意决策、不为 dev 放宽——见 [安全权限与治理 §一](/docs/05-平台与运维/安全权限与治理.md)）。

**诊断**（一条命令，`apps/server` 下）：

```bash
uv run python scripts/probe_egress.py
```

看汇总行 `fake-IP 检出: YES` + 每条 `DNS -> …198.18.x.x(FAKE-IP)…` 即坐实（脚本走应用同路径 `_getaddrinfo` + `classify_url` + 真 `read_url`）。

**解决**（人操作，二选一）：

- **首选·把代理 DNS 从 `fake-ip` 改成 `redir-host`**（保留代理、只换 DNS 策略）：Clash / Mihomo 配 `dns.enhanced-mode: redir-host`（或整体关 `dns.enable`）重载；v2rayN 关「FakeDNS / fake-ip」；Surge 移除 `[General]` 的 `fake-ip` 项或用 `always-real-ip`。
- **或·临时让后端不走代理 DNS**：关 TUN / 系统代理，或只代理 HTTP(S) 不劫持 DNS，让 `getaddrinfo` 落真实公网 IP。

**复验**：再跑 `probe_egress.py`，出现 `=> PASS：DNS 落真实公网 IP、SSRF 放行、read_url 端到端可读` 即恢复。**环境会漂移**，跑辩论 / 用取证前先复验。
