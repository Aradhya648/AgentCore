## 核心定位与重设计动机

辩论是 MVP Day1 范式之一（见 [`Agent协作模式.md §一`](/docs/03-AI核心/Agent协作模式.md)）。旧设计把它压成 `delegate` 上的三个展示标记（`stance`/`group`/`round`，display-only）+ 一段教 CEO 手动展开跨轮 DAG 的 Skill 配方，执行器/调度器完全忽略这些标记。这在「形状是数据不是模式」的技术教条下是自洽的，但**从用户需求倒推，它牺牲了辩论真正的价值**：

| 旧设计的产品级缺陷 | 后果 |
|---|---|
| 「轮次」是技术概念泄漏到产品层 | 让 CEO（甚至用户）去管理「第几轮、谁依赖谁」，把实现细节当成了功能 |
| 产物缺失 | 跑完只有「正反并排卡 + CEO 一段简短概览」，再甩 `ask_user` 让用户**自己**在正反里选——辩论很热闹，却没为用户的决策负责到底 |
| 辩论质量无人把关 | 正反可能各说各话（没真交锋）、强度不对等、轮数到了却没收敛 |
| 二元 pro/con 过度简化 | 真实需求里的「红队单向批判」「多方圆桌」被硬塞进正/反两栏 |
| 老板插不上话 | 辩论一旦开打就是黑盒跑完，用户无法中途掌舵 |

**重设计主张**：辩论需要一个**有状态的主持人层**来承载「发起对抗 → 逐轮判收敛 → 裁决 → 产出过程与结论」。当初否决「独立 Arena 子系统」（独立 SSE / 状态机 / `arena` RunKind）否得对——那是过度工程；但连带把「辩论需要主持人」也否了，是把洗澡水和孩子一起倒了。本设计把主持人加回来，**但它不是独立执行引擎，而是 CEO 之下、辩手之上的一个编排角色**，底层仍用现有的并行委派 + 上游产物注入执行。

> **用户拍板的四条方向**（本设计的地基）：① 辩论的**过程本身也是一等产物**（不为出结论而降级过程）；② 引入主持人/裁判一等角色；③ 支持红队单向 + 多方圆桌（破二元）；④ 轮次由收敛自停、对用户隐藏（用户/CEO 永不设轮数）。

## 一、产品目标与三问

**目标**：用对抗性多视角思考，帮用户得到一个他能信、考虑过反面的**结论或决策**，同时让他能看懂**思想如何交锋**。

| 三问 | 答案 |
|---|---|
| 谁用 | 面向大众的决策者 / 学习者 / 方案作者 |
| 解决什么真实问题 | ① 帮我做决策（选 A 还是 B）；② 压力测试我的方案（红队挑刺）；③ 学懂一个有争议话题（多方观点光谱）；④ 娱乐性思辨（少数） |
| 产品上如何呈现 | 用户只抛「问题」或选一个「形态」，不碰任何参数；产出**过程（交锋叙事线）+ 结论（决策简报）双产物** |

**核心洞察**：用户要的几乎从来不是「轮次」这个过程指标，而是辩论的**产物**——更可信的结论 + 看得懂的交锋。「轮次」是手段，必须对用户隐藏、由系统自调。

## 二、支点：主持人（Moderator）循环

主持人是「**主持 + 裁判 + 书记**」三合一的有状态编排角色。一轮循环四步：

1. **定本轮议题**：首轮把用户问题拆成争议焦点（`_frame`，并产开场白）；后续轮优先采用上轮裁判
   `verdict.next_focus`（assess 兼产、真去重——裁判刚读完本轮发言判未收敛时已从「仍存分歧」压出下轮焦点，
   避免下一轮开头 `_frame` 再读一遍同材料），缺失 / 空串 / 坏 JSON 时才回退 `_frame`；用户掌舵
   `focus_override` 始终最高优先。
2. **派各方发言（形态 profile 分流）**：轮内拓扑由 `form_profile(config)` 派生——**正反 DEBATE** = 全员并行波（`parallel_wave`）+ 自动注入对方上轮产物；**红队** = finding 星型三拍（攻→合并→应→thorough 时复攻）；**圆桌** = 点名串行线程（`nominate_serial` + optional `crux`）。底层仍复用并行委派 / `continue_run` / 材料注入原语（见 [`执行引擎架构设计.md`](/docs/03-AI核心/执行引擎架构设计.md)），不是独立引擎。首轮另可注入 CEO 随 `background` 传入的**案件底料**（以主持人名义、双方共享，见 §7.1）。**缺席轮一等语义**：网关重试耗尽后某方仍无有效发言、但同轮仍有他方成功 → 该方 `sides[*].absent=true`（`ok=false`）；**跳过对缺席方的质询**（仅 DEBATE）、**本轮不做对抗性记分**（清空 `scores`，并丢掉涉及缺席方的 clash），赛程继续不阻断。全员失败仍走 `all_failed` 早停（不标 `absent`）。
3. **质询交锋 beat**（仅正反 DEBATE + `thorough=True`）：立论之后、裁判之前，主持人向**出席各方**发**定向必答质询**；红队以三拍取代通用质询（`cross_exam=False`），圆桌亦关。详见 §四之二·质询回合。
4. **裁判本轮 + 记分 + 写小结**（`_judge_and_summarize`）：一次结构化调用同产三件事——裁判（有没有**真交锋**？是否**还在产生新论点**？可否收场？）＋**逐轮记分**（论点强度 / 回应完整度 / 证据充分度三维 + 谬误·无据硬拗的罚分，读「立论 + 质询问答」一起判；**缺席轮跳过对抗记分**）＋本轮小结（争议焦点 / 已达成共识 / 仍存分歧，「过程产物」骨架）；未收敛时顺带把「仍存分歧」压成 `next_focus` 供下一轮直接采用。三位一体读**同一份本轮发言**，合并成一次调用去掉冗余 LLM round-trip（真去重，非节流）。详见 §四之二·记分裁判 / 举证责任。
5. **决策下一步**：收敛 → 出决策简报收场；未收敛 → 进入下一轮；遇关键分歧 → 可选请老板掌舵（见 §六）。

**收场前的结辩 beat**（仅正反 DEBATE + `thorough=True`；红队 / 圆桌 `closing=False`，`closings` 恒空）：循环收敛后，主持人给每位仍在场的辩手一次 `continue_run` 的**结辩机会**——短而有力地收束自己的胜负手，**禁止**再抛新论点/新证据。结辩与决策简报（`_brief`）**并行**（`asyncio.gather`）。红队复攻拍已含收束语义；圆桌无「对垒收束」诉求。详见 §4-2.4·结辩收束。

> 「轮数」= 这个循环跑了几次，由第 4 步的收敛判断决定。**用户和 CEO 都不再声明轮数**——这是旧「CEO 一次 `delegate` 静态展开 2N 个节点」的根本性改变（旧法轮数先验固定、无法运行期收敛）。

**主持人 ≠ 通用语义裁判**：[`多轮编排与同人续派.md §九`](/docs/03-AI核心/多轮编排与同人续派.md) 决定「暂不做判『写得好不好』的通用 LLM 质量校验，沿用机械 contract」。本设计不触碰该决策——主持人的「裁判」是**辩论领域内的交锋质量与收敛判定**（判「是否针锋相对、是否还在产生新论点」），是辩论这个能力的固有职责，不是给普通 worker 产物做通用质量门。两者语义正交。

## 二之二、庭前取证与辩方团队 ✅（2026-07-21 定案并落地）

> **定案依据**：LV 案两场真跑（`ae73b835` / `34857b6b`）实证——自然路径上 `research_first` 闸从未生效（推荐启发式未亮、用户 5 秒点「开赛」）；同一场里三层取证互不汇流（CEO 开场检索只留在聊天、主持人底料进 prompt 不进台账、辩手首轮各自重搜且工作区为空），重复检索、噪声域名、底料 `#rN` 引用校验失败。根因 = 取证被设计成「用户可选的上游关卡」，案卷管线只对 MLR 一条路开口。**定案主张：取证是辩论质量的内在前提，是系统责任，不是用户选择题——内化为辩论固有阶段。**

### 阶段流（开赛后、首轮立论前）

1. **主辩点单**：各方辩手先产结构化**取证任务单**（每方 ≤3 条）——「带着立场找证据」是辩论本性，点单给主辩真实的队长代理感；
2. **主持人代派**：主持人循环据任务单实例化各队**取证员** run——与辩手同深度的叶子、只带检索/只读工具、无发言 run；`parent_run_id` 指向本方主辩；`group=pretrial:investigators:{side}`——**必须**留在 `debate:` 参与者命名空间之外（协作图布局契约：`debate:*` 且 parent=主辩会把主辩误晋升为独立辩论单元 → fold 双重归属 + ELK 假分带，2026-07-22 实证根治）；协作图呈现 = 辩论 compound 内平铺、经边连到本方主辩（compound 内不再嵌套子队盒）；
3. **并行分工取证**：各队并行执行；产物 = 证据笔记，逐条登记场级证据台账（`side_key=本方`）并落 `research/`；检索走结构化姿态 `search_policy=debate_evidence`——weak 档与商城/词典/医院百科在**工具出口**硬剔，教法不再是唯一防线（✅ 2026-07-22 → [工具与能力 · 检索姿态](/docs/03-AI核心/工具与能力系统.md)）；
4. **定焦开辩**：取证收口 → `_frame` 定焦 → 首轮立论。首轮辩手 speech research 的「从零自搜」由引用台账取代（有案卷残搜预算已校准 4→2：2026-07-22 复测残搜几乎全为噪声域名、正文引用几乎全来自案卷；无案卷路径不动）。

**轮间补证**：轮边界主持人可对取证员 `continue_run` 补证（同辩手续轮原语）；仅裁判判「证据缺口正在决定胜负」时开，默认不开。

### 四条边界（定案约束，违者即走样）

| 边界 | 约束 |
|---|---|
| 发言权不下放 | 取证员永不产生发言；对外输出恒为主辩一人 |
| 预算对称 | 各方取证员数量与检索预算严格同额（复用 per-run `retrieval_budget`；无 mid-run 追加） |
| 台账强制汇流 | 主辩成稿只可引台账 `#eN`；取证笔记走「索引注入 + 自取全文」（沿用案卷消费模式，防变相写剧本） |
| 规模跟档位 | `thorough=False` 不带队（最小取证或秒过）；`thorough=True` 每方 1–2 取证员 |

### 案卷桥对所有路径生效

`preregister_research_dossier` 从「仅消费 MLR 幕产物」扩展为**无条件**：CEO 开场检索的回合台账 `#rN`、`background` 底料、工作区 `research/` 既有产物，开赛一律登记为场级 `#eN`（治「底料进 prompt 不进台账 → 辩手引用必失败」的根因）。取证任务单生成时注入已有案卷索引，取证员只补增量、禁重搜已覆盖项；案卷已充分时主辩可返回空单、阶段秒过。

### 降级路径（赛程永不因取证卡死）

主辩点单超时 / 不合规 → 主持人按 motion + stance 自动派单；取证员全败 → 回退「辩手立论自检索」（现状行为）。

### 入口分流（配套变更）

- `research_first` 开工卡按键**退役**，开工卡回归授权预览 →（[编排器 §五](/docs/03-AI核心/编排器与CEO主Agent.md)）；

- CEO 教法改**按意图分流**：明确点名开辩 / 模拟庭审 → 直调 `debate`；调研 / 研究意图 → MLR →（[工具与能力 · 对抗路由](/docs/03-AI核心/工具与能力系统.md)）。

### 前端（概览）

赛事页新增「庭前取证」区块（各队取证进度 + 台账条目实时计数，对标证人席区块形态）；协作图零/极小改动（通用 `parentRunId` 嵌套路径直接吃）。开赛第一秒即有可见活动，治「卡一过就开跑、看不到准备过程」（场① 开赛 12 秒即被用户停止的体验教训）。

### 就地否决（本节）

- **给辩手发 `delegate` / 提 `MAX_DELEGATION_DEPTH`**——否决：辩手保持 depth+2 硬叶子；「带队」由主持人代派 + `parentRunId` 呈现达成，引擎契约零改动。

- **取证笔记全文注入主辩起点**——否决（沿用 §四之三「变相写剧本」风险）：走索引 + 自取。

→ 见代码：`runtime/debate/pretrial.py`（点单 / 对称补齐 / 代派 / 台账汇流；取证员工具集 = `WITNESS_TOOLS` 只读集，上限与预算见 `constants.py`）；wire `debate_pretrial_{started,orders,progress,completed}`（DURABLE，权威 = completed）；conformance `multi_agent_debate_pretrial_{thorough,fast}`；前端 `arena/PretrialSection`。

## 三、三形态统一模型（破二元）

参与方从 `pro/con` 泛化为「**立场标签**」（支持 / 反对 / 某视角名 / 红队 / 方案方），一套主持人循环经 `FormProfile` 参数化出三形态——**「轮内全员并行波」已降级为 DEBATE 专属形状**，红队 / 圆桌由既有原语组合出星型三拍 / 点名串行。正反攻防为**回归基线**（行为与 wire 形状零回归；共享调度可因 profile 分派重构，DEBATE 并行波 + 质询 + 结辩链路形状不变）。

| 形态 | 参与方 | 交互单元 / 轮内拓扑（as-built） | 质询 / 结辩 | 收敛判据 | 产物侧重 |
|---|---|---|---|---|---|
| **正反辩论** | 正 / 反 2 方 | `side_turn` · `parallel_wave`（+ thorough 时 `cross_exam`） | ✅ / ✅（thorough） | 无实质新论点 / 焦点已澄清为价值之争 | 简报先行 |
| **红队挑刺** | 方案方（被审）+ 1~N 红队 | `finding` · 攻→合并→应（thorough 再加复攻） | ❌ / ❌（`closings` 恒空） | 风险挖尽 / finding 门决 | finding 台账 + 门决先行 |
| **多方圆桌** | 3~N 个视角 | `thread_turn` · `nominate_serial`（+ `crux`） | ❌ / ❌ | 观点光谱已铺满 | 过程 / 共识地图先行 |

**红队三拍（决策理由）**：交互单元从「按方发言」改为 **finding**——攻方并行挖刺 → LLM 合并去重 → 方案方逐条处置（接受/缓解/反驳/挂起）→ thorough 时复攻复核；门决由未关闭的 critical/major finding 派生。复攻拍已含收束，故**移除通用结辩**（O1）。红队之间**不互驳**（分域挖洞是特性，交锋在红队↔方案方）。**圆桌串行（决策理由）**：多边碰撞靠点名串行线程 + 可选 crux 短答铺光谱，不作「全员并行波」——并行波在圆桌上会变成各自独白、对不上话。**wire（O2）**：finding / 线程 turn **只带结构**（id / 状态 / severity / 指向），全文靠 `run_id` 关联。**快速档（O3，`thorough=False`）**：红队 = 单轮两拍（攻→应，无复攻）；圆桌 = 单子题点名串行（仍单轮）。

> **被否**：只加厚跨轮 feedback / 角色 prompt（首轮互不可见时按不住）；为红队/圆桌拆独立引擎或独立 SSE（沿用 §八）；圆桌拉齐攻防加质询结辩（毁「铺光谱、不裁胜负」）；要求红队互驳；全员并行 + 事后 clash 考古（治标）；先完整实测再改码（结构病根已由架构调查证实，先改码后 e2e）。

用户只选「形态」（甚至只抛问题、由 CEO 自动判定是否值得对抗性论证），**永不碰参与方数量 / 轮数 / 依赖**。

> **验收**：正反路径 conformance / 单测已绿；**红队 e2e 真跑验收 ⏳ 待实测**（单元与 phase 组合测已覆盖拓扑，黄金场级端到端尚待）。→ 见代码：`runtime/debate/form_profile.py`、`moderator_phases.py`、`moderator_agenda.py`、`findings.py`。前端 finding 线程 / 门决 / 圆桌地图 → [前端 UX §四](/docs/04-前端/前端UX设计.md)。

## 四、双产物：过程与结论都是一等

辩论结束**交付两样，都做好，不分主次**（用户拍板第①条）：

### 4.1 结论产物 —— 决策简报

- 争议焦点（双方真正分歧在哪）
- 各方去水后的**最强论点**
- 主持人的倾向性判断 + **置信度**（如「基于事实反方更站得住；但若你更看重 X，则正方成立」）
- 给用户的建议
- **交接清单（handoffs）**：辩论没替用户解决的残留项，统一为单列表 `brief.handoffs[{kind, text}]`，按**解决路径**（谁/什么能把它闭合）分三类——`value`（只有用户的价值观/偏好能闭合）、`fact`（证据能闭合，AI 可接手查证）、`question`（当下闭合不了：等外部事件 / 预测验证 / 后续观察）。判别铁律单一来源（简报 prompt 一处定义，判序：证据能闭合→fact；用户拍板能闭合→value；都不能→question）；未答清的用户追问必须收编、不得石沉大海；关键事实的证据状态语内联在条目文本（§4-2.3 grounding）。条目写法：`value` **问句化**（每条 = 用户可直接回答的一个问句 + 一句「你的选择如何影响结论」）；三键均对齐 `strongest_points`「去水压成单句、只留命门」。
  - **前端呈现（「留给你的」）**：外层标题保留；按 kind 三种**异质形态**——`value` = 问句卡置顶（高光 +「回复拍板」→ composer 预填）、`fact` = 可查证任务列表（「派查证」→ composer 预填）、`question` = 脚注级次要文字。分类名词标签（需你定夺 / 事实分歧 / 待解问题）从 UI 退场，靠形态差异而非标签分组。**被替代**：三分组小节同质 bullet 列表 + 抽象分类名词标签（同形态平铺、靠文案区分，拍板/查证行动不可见）。
  - **落地形态（wire）**：LLM 输出接口保守——仍填三键 JSON（键名即分类指令、输出契约零膨胀），解析层规整为统一 `handoffs`；wire `DebateBriefInfo.handoffs` 单列表，坏 kind 容错归 `question`（不丢内容）。**被替代**：三个平行裸字段 `factual_disputes` / `value_disputes` / `open_questions`——桶间定义重叠矛盾（`open_questions` 曾定义为「需用户拍板」与 `value_disputes` 同义，前端却把它归「无需你定夺」组）、条目无结构承载不了元数据、前端「需不需要你」分组维度靠组件硬编码二次映射。

### 4.2 过程产物 —— 交锋叙事线（三层渐进披露）

这是「过程本身有用」的落地，不是旧的「正反两栏平铺」，而是被主持人组织过、带攻防关系的叙事：

| 层 | 内容 | 服务对象 |
|---|---|---|
| **L1 焦点小结流** | 每轮一句焦点 + 小结，串成一条「认知推进线」 | 速读者：30 秒看懂整场怎么演进 |
| **L2 逐轮攻防** | 每轮 = 本轮议题 + 各方发言 + 主持人点评（谁回应了谁、谁让步 / 新增了什么） | 理解者：看思想如何被攻击与捍卫 |
| **L3 论点级全文 + 交锋边** | 各方完整发言（按 `run_id` 取辩手节点）+ 论点级交锋边「谁驳谁」（裁判逐轮抽取的 `from→to` + 驳的要点，载于 `clashes`，前端据本轮 `sides` 解析成名字/身份色） | 深读者：较真细节、看清谁针对性反驳了谁 |

### 4.3 呈现顺序按形态自适应

- **决策类**（正反 / 红队）：决策简报先行，过程叙事线紧随其后可展开。
- **探讨 / 学习类**（多方圆桌、纯思辨）：过程叙事线先行，简报作为「小结」收尾。

前端落点见 [`前端UX设计.md §四`](/docs/04-前端/前端UX设计.md)。

- 路径约定：`AgentCore/文档/debate/{决策简报|交锋叙事线}·{辩题短语}·{场次8位}.md`（见 [`双模式工作区.md`](/docs/02-架构/双模式工作区.md)「阶段产物目录约定」）
- 失败降级、不阻塞主流程收口；成功路径附在 CEO 输出尾部便于定位

## 四之二、质询式交锋：让辩论像真人（质询 · 记分 · 举证 · 结辩）

> **动机**：旧辩论的底层原语是「**并行独白相递**」——每方各写一篇独白、看对方上轮快照、再写一篇，交锋靠主持人**事后**从独白里抽 `clash`。真人辩论的内核是「**当面质询式交锋**」：你问我答、逼对方正面回应、举证责任在主张方、裁判据实际交锋记分。三支柱把「独白相递」换成「质询式交锋」，**相互咬合、缺一留漏**：质询（P1）产出「谁回避命门 / 循环论证当场被戳穿」的交锋事实 → 记分（P2）据此奖惩 → 举证（P3）让「无据」变成结构上可见、可质询、可罚。设计推导（『并行独白相递＝病根』的根因分析）已并入上述动机；原提案文档随本次落地退役删除，**被否方案留档**：① 只改辩手 prompt（加 hedge / 压字数 / 要求引用）——治标，症状是「独白相递」原语的下游、prompt 层按不住；② 给辩论造独立 Arena 引擎 / 独立 SSE——沿用 §八 既有否决（全部复用现有执行地基、只改交互契约）；③ 质询 CX 全形态全开——否，`thorough=False` 快速对碰跳过 CX、守轻量意图与延迟。
>
> **状态**：✅ P1+P2+P3+P4 均已落地并过测试（后端 prompt/记分/结辩契约 + 前端渲染 + conformance 金样 `multi_agent_debate` 双端绿）。复用现有 round 循环 / `continue_run` / SSE / 双产物骨架，未重建引擎。P4（结辩收束·阶段化发言角色）是「让辩论像真人」的收尾支柱：真人辩论以结辩定音，本产品此前却在末轮戛然而止。

### 4-2.1 质询回合（P1，契约①）

- **是什么**：§二循环第 3 步的质询 beat。主持人对各方发 2–3 个**尖锐必答问题**，被质询方以 `continue_run` 在**自己的 transcript** 上先正面回答再展开——不是新辩手、是原辩手带记忆答问。作答允许充分取证；产出契约与立论同为 markdown 标题体，解析按标题切段。
- **门槛**：仅 `thorough=True` 开启；`thorough=False`（快速对碰）跳过，守轻量意图与延迟。
- **回避判定（裁判裁定，非辩手自评）**：是否正面回应由记分裁判读 Q↔A 原文裁定——诚实认输 / 让步 ≠ 回避。前端质询区只渲染中性 Q→A + 客观状态，不贴褒贬徽章。
- → 见代码: `runtime/debate/rounds.py`

### 4-2.2 记分裁判（P2，契约③）

- **是什么**：裁判从「只判交锋 / 收敛」升级为**逐轮记分**——每回合给各方打论点强度 / 回应完整度 / 证据充分度三维分 + 罚分，读「立论 + 质询问答」一起判。收场 `leaning + confidence` **由累计分推导**、`brief.decisive` **点名胜负手**，不再收场一次性拍脑袋。
- **证据分按【来源等级】分级（grounding）**：`evidence` 维对【已核实】出处再分等级——一手 / 权威源可给满；决定性事实只靠单一二手来源时即便标了【已核实】也只算弱证据。防「决定性结论压在一条未经一手核实的二手报道上」。
- **不违反「主持人≠通用质量门」**：记分判的是**论证有效性 / 证据 / 是否回应**——辩论领域内的核心裁判职责，是既有裁判的自然延伸（守 [`多轮编排与同人续派.md §九`](/docs/03-AI核心/多轮编排与同人续派.md)）。
- **记分仅收场消费（设计决策，非缺口）**：live `debate_round` 虽携带 `scores`，但进行中叙事投影**有意不带**——比分条只在收场 `debate_result` 后渲染。理由：轮中亮分会把「进行中的裁判观感」当成定论，且 live 孪生窄投影守恒「进行中只看焦点/小结/交锋」。
- → 见代码: `runtime/debate/moderator.py`

### 4-2.3 举证责任（P3，契约②，方案 A 内联标记）

- **是什么**：每条**关键事实主张**须**紧跟证据状态标记**，二选一——`【已核实·#eN】` / `【待核实·推断】`。未标记的关键事实一律按【待核实】对待。把「无据」从「靠 hedge 自觉」变成**结构上可见、可质询、可罚、可机械溯源**。
- **三处咬合**：辩手**标** → 裁判**据标记记分/罚** → 前端**渲成证据徽章**。
- **证据状态继承到结论、收尾不得抹平（grounding）**：若 `decisive` / `leaning` 依赖的关键事实是【待核实】或仅【单一二手来源】，不得当既定事实定倾向——要么降置信并标【需一手核实】、要么移入交接清单；CEO 收尾同样不得把待核实事实写成板上钉钉。
- **诚实存疑不罚，硬拗才罚**：诚实标注【待核实】**本身不扣分**；只有「把待核实 / 无据当成【已核实】的决定性论据」才扣——否则辩手会为避罚而假装有据。
- **前端**：已核实 = success 绿、待核实 = muted 中性灰（绝不用琥珀）；仅辩论发言 opt-in。徽章可溯源（M1）：`#eN` 经台账 map 解析；旧磁带自由文本降级纯文案徽章。
- **场级证据台账（M1）**：「点任意已核实都能落到真实来源」的机械地基——检索期绑定 `#eN` → 成稿只沿用本方笔记引用 → 闸 / 徽章同源可溯。成稿 id 闸基准 =「id ∈ 本方笔记引用集」；违规回炉一次，二次降级【待核实·推断】。台账不上 `citations_event`（调研主卡=引用集、辩论场级 id 恒稳）。
- **方案 A（内联）而非 B（结构化）**：先让「无据可见 + 可罚」跑通；结构化 `claims` 作为演进，本期未上。
- → 见代码: `runtime/debate/evidence_ledger.py`

### 4-2.4 结辩收束（P4，方案甲：结辩 beat + 阶段化长度预算）

- **是什么**：§二循环收敛后、写决策简报前的**结辩 beat**。主持人给每位仍在场的辩手最后一次 `continue_run`，让其**短而有力地亮胜负手**：回收最强论点 + 直面对方最致命一击 + 给用户一句可带走的判断。
- **阶段化发言角色**：立论（可长）／质询作答（中等）／**结辩（最短最紧）**；结辩**硬禁新论点 / 新证据**。解决旧辩论「末轮说完就戛然而止」的产品缺陷。
- **门槛**：仅正反辩论 + `thorough=True`；红队 `closings` 恒空（复攻拍已含收束）、圆桌 / 快速对碰跳过。
- **协作图 beat 折叠（✅）**：协作图**一列 = 一轮**——质询作答折进同辩手同轮陈词节点；结辩保留独立「终章」列。**被替代**：初版「质询 / 结辩全部独立成列」——thorough 3 轮每方 7 列、同质卡片墙。→ 见 [`前端UX设计.md §五`](/docs/04-前端/前端UX设计.md)。
- **方案甲而非方案乙（完整发言角色状态机）**：先加最缺的收尾 beat + 长度预算；全套角色状态机作为演进，本期未上。
- → 见代码: `runtime/debate/rounds.py`

### 4-2.5 辩手发言两阶段契约（检索笔记 → 干净成稿 · 2026-07）

- **根因**：旧契约把「ReAct 检索循环最后一条无工具 stop 全文」当正式发言——模型处于收工汇报语境，自然混入过程句与案情复述。引擎 `deliverable_only`、prompt 纪律、前端 preamble 剥除均为补丁，治不了收工语境。
- **是什么（两阶段）**：全部辩手 beat 改为——① **检索阶段**（可退化跳过）：交付物 = **证据笔记**（禁正式发言、禁收工句）；笔记与工具过程只进 journal，**不进** outputChunks。② **成稿阶段**：一次**无工具、干净上下文**调用产出发言全文。结辩禁新论据 → **跳过检索、单次成稿**。
- **前端消费不变**：卡片最终呈现只能是发言正文；`parseSpeechArguments` 只按 `### ` 切论点大纲，**已删除** preamble 剥除补丁。
- **检索预算**：辩手检索硬顶与普通 worker 共用 `engine_worker_token_ceiling`（默认 1M；≤0 关闭）。原独立档 `engine_debate_token_ceiling`（120k）已并入——统一顶抬高后独立动机消失。
- → 见代码: `runtime/debate/speech_pipeline.py`

### 4-2.6 对局记忆：对局台账（match ledger · 2026-07）

- **根因**：跨方信息只有主持人按轮喂的窄通道——**质询里的撤回 / 让步不跨方同步**（「幽灵归因」），且两阶段成稿的干净上下文**看不见己方上轮全文**。这是**状态同步**问题，加宽通道贵 token 且只治一症——已否决（见 §八）。
- **是什么**：裁判每轮 JSON **兼产** `ledger_events`（与记分同一遍推理，零额外 LLM 调用）——只收显式发生的状态变化（`withdrawal` / `correction` / `disputed_fact` / `concession`；宁缺勿滥）。主持人跨轮累积后**双向注入**下一轮全部辩手。成稿 brief 另附**己方历轮论点标题一览**，防自漂移。
- **预算硬顶**：每轮 ≤8 条、单条 ≤120 字；注入摘要 ≤1200 字。坏 JSON → 空列表，行为逐字回退。
- **wire 边界（决策）**：**只进 prompt、不上 wire**——先验证 prompt 层收益；对局台账上 UI 另案。
- **与 §五「跨轮论点账本」的分工**：论点账本喂给**裁判**判收敛；对局台账喂给**辩手**作行为约束。前者是「已辩过什么」，后者是「哪些状态已变化、不可再当有效」。
- → 见代码: `runtime/debate/match_ledger.py`

> **测试与金样**：conformance 向量 `multi_agent_debate*` / `multi_agent_debate_multibeat`；单测族 `test_debate_*`（举证 / 台账 / 结辩 / 预算 / 记分编排）。

## 四之三、证人模式：幕间角色连续性 ✅（2026-07-19 定案落地 · 2026-07-20 LV 案真跑验证）

幕1 透镜调研员以「**证人**」身份进入幕2 辩论——不占辩席、不写辩词；主持人质询环节需要事实澄清时点名证人，证人带幕1 调研**现场记忆**（查过什么、试错过程、来源）作答。多幕协作「角色可连续」性质的落地形态（幕序列与宿主图见 §7.3）。

- **v1 形态**：开赛 `probe_witness_sessions` 扫会话 roster 认幕1 透镜 session（无则整场零行为、单独辩论不回归）；质询档 LLM 步 `witness_exam_questions` 点名（system 约束**只问事实性问题**，失败 / 空则跳过不阻塞赛程）；答问 = 辩论幕内**证人席位 session**（fork 自透镜 transcript）的窄 `continue_run`（`WITNESS_TOOLS` 只读工具集、透镜 `recall_count` 不递增、不占 CEO 续派额度）；`register_witness_answers_in_ledger` 把答问登记进场级证据台账（`side_key=witness:{key}`），辩手可引用。
- **边界**：辩方创建路径不动（仍对称冷起 + 共享案卷，立场由命题赋予）；v1 不做辩手主动传证人、不做用户点名（用户掌舵插话已有）。
- **产品理由**（评估 `87e7b72a` 结论）：保留「亲手做过调研的人可被盘问」的同人感与现场记忆价值，同时避开转任辩手的中立性伤害。**否决**全量续派转任辩手：四堵架构硬墙（辩论首轮冷起接线、图接续锚 vs 幕归属、RunSpec 身份/工具/两阶段成稿契约）+ 透镜滤镜污染辩手中立性（「各护各的调研稿」非真对抗），且与「换角色→冷委派」教法冲突。**暂不做**透镜摘要注入辩手起点：与已落地案卷消费 + 检索分工重叠、有「变相写剧本」风险。
- **契约 / 图锚**：additive `witness_exam` / `witnesses` 字段 + channel；席位声明在辩论幕、答问挂**证人节点**（不挂幕1 透镜节点）。双端渲染：桌面 `arena/WitnessExamSection`、手机 fold / `DebateView`；证人 pending 显示「待命」、整场未被点名显示「未传唤」（`debate.witness.unexamined` 可观测日志）。conformance 向量 `multi_agent_mlr_debate_witness` 双端 + parity。
- **验收口径**：证人答问核实检索**单列**、不占辩手检索预算（黄金场环4，见 [`本地开发.md` §黄金场验收](/docs/02-架构/本地开发.md)）。正反+证人路径已有真跑样本；红队形态 e2e 见 §三「待实测」。

→ 见代码：`runtime/debate/witness.py`、`runtime/debate/constants.py`（`WITNESS_TOOLS`）。

## 五、收敛与轮次治理

**收敛完全由主持人逐轮自判**（§二第 4 步裁判的 `converged`）——没有任何「最小轮数」机械门槛强制多轮。**终止条件**（满足其一即停）：

1. **收敛**：裁判判定各方无实质新论点（开始重复）。
2. **焦点澄清**：分歧已归结为价值 / 偏好之争（AI 判不了，交用户）。
3. **红队耗尽**：无新风险可挖（红队形态专用）。
4. **安全上限**：达到 `max_rounds` 硬上限——纯保险丝（防失控的断路器兜底，**非目标值**，收敛永远可早于它发生）。

前三条都是裁判的判定结果；第 4 条是与内容无关的硬上限。

> **跨轮论点账本**：裁判只吃当前轮时会把「换措辞重述」误判为新论点 → 永不收敛。决策：注入 `_prior_ledger` 压缩账本，`new_arguments` 按跨轮真去重判。→ 见代码：`runtime/debate/moderator_judge.py`；校准 `evals/debate_converge.py`。
>
> **边际递减断路器**：连续两轮 `new_arguments=false` 时机械强制收场（LLM 仍给 `converged=false` 也收）——确定性下限，不改裁判语义；用户边界 `CONTINUE` 可覆写。→ 见代码：同上一指针；回归 `test_diminishing_returns_*`。
>
> **`stop_reason` 归一**：未收敛强制留空；收敛时校验词表否则回落 `STOP_CONVERGED`。→ 见代码：同上一指针。

**收敛北极星 = 「在不糊弄的前提下，尽快把用户的决策交付出来」**（呼应用户第①条：要的是产物，不是轮次）。这不再靠「跑满 N 轮才许收」，而是内化进【定议题】与【裁判】两处的逐轮标准——

- **定议题：钻决定性分歧，不巡游维度**：后续轮优先用上轮 assess 兼产的 `next_focus`（从「仍存分歧」派生，真去重）；仅当缺失 / 空串时 `_frame` 兜底，盯住「真正决定用户问题的那个分歧」往深里逼（用更尖锐、更逼胜负的子问题推进），只有当它确已辩尽（被事实分出高下 / 见底成价值选择）才转下一个最影响结论的点。仍注入「已谈焦点清单」禁「换个说法重谈」（防冗余「修订 v2」），但旧的「每轮必须换一个正交新维度」——这条把决策辩论推成维度巡游、几乎必然撞满上限的过度约束——已去除。（多方圆桌例外：本就为铺光谱，可自然转新视角。）
- **裁判：价值之争见底 = 收场信号，不是继续信号**：`thorough=True`（认真辩透）≠ 把每个角度都辩一遍——盯决定性分歧往深里辩，一旦它被事实分出高下、或见底成「只能用户拍板的价值/偏好选择」即判收敛；仅当还能冒出「会改变结论」的实质新论点时才继续。`False`（快速）= 核心交锋一清晰即收。**旧「仍有未决关键交锋就别收」已废**：它与「分歧归结为价值之争即收」（终止条件 2）自相矛盾——价值之争天生就是永远未决的关键交锋，于是价值承重的题（法律 / 决策等本产品主场）每场都撞满上限、`focus_clarified` 永不触发。
- **第 1 轮（开场立论）默认继续**：各方此时通常只是各自亮出立场、尚未真正接火（`real_clash=false` 是常态），默认判「未收敛」以逼出下一轮真交锋；**仅当**命题空泛到开场就无新论点时才许收。
- **快速单轮**（`max_rounds=1`）：一次对碰即收，裁判不强求多轮。

这样绝大多数决策辩论自然收在 2–3 轮，`max_rounds` 回到「罕见兜底的纯保险丝」定位（本节开头的设计原意）。也根治了旧机械楼层病：trivial 命题被强逼跑满 N 轮 → 续写者输入几乎相同 → 冗余「修订 v2」节点。

| 形态 / 模式 | `max_rounds`（安全上限） | `thorough` |
|---|---|---|
| 正反 / 红队（认真辩透） | 5 | `True` |
| 圆桌（探讨型，铺光谱即可、略紧） | 4 | `True` |
| 快速对碰（任意形态，轻量意图） | 1 | `False` |

`thorough=False` 对**所有形态**（含圆桌）一律快速单轮——轻量意图不该被强制多轮。轮数永不暴露给用户设定：用户只选形态（或由 CEO 据意图判 `thorough`），收敛由主持人逐轮自调，`max_rounds` 只兜底。

## 六、老板可掌舵：ambient 非阻塞插手

用户是老板，应能在辩论中途介入（不微操辩手，只对主持人表达，承袭 [`多轮编排与同人续派.md §一`](/docs/03-AI核心/多轮编排与同人续派.md) 的心智）。✅ 已落地：**ambient 掌舵**——辩论默认自动跑、**永不硬停**；有活跃用户时掌舵恒可用，用户随时把「继续辩 / 加角度 / 追问 / 够了收」fire-and-forget 送进 steer 队列，主持人在**下一轮边界非阻塞**捞起应用（§6.1–6.5）。收场后若还不满意，用户自行在对话框对 CEO 说话、CEO 重开一场全新辩论（§6.6）；外加**用户侧**站队（会话内态，§6.7）。

> 心智模型：用户是「**带着倾向旁听、能随时插一脚的第三方**」——干预只作用**议程 + 价值层**，**绝不篡改事实层**（保 AI 裁决的中立可信）。前端呈现见 [`前端UX设计.md §四`](/docs/04-前端/前端UX设计.md)。

### 6.1 触发与门槛（有活跃用户即武装）

- **开赛前另有一道门（开工卡 ✅）**：顶层 `debate` 经 kickoff gate 挂 `team_preview`；嘱咐≠改 motion。**有合规命题卡**走阶段推进卡（`skip_kickoff`），不开工卡。与中途 ambient 正交。→ 见 [`编排器 §五`](/docs/03-AI核心/编排器与CEO主Agent.md)
- 辩论**默认自动跑**（裁判逐轮自判收敛）。CEO **不再**传 `interactive`——该参数已从 `debate` schema 删除。
- 门槛 `ambient_armed`（= 服务端 `checkpoint_enabled`）：有活跃用户即武装 ambient 掌舵；自治 / handoff 不武装 → 纯裁判自判。与其它检查点共用「有活跃用户」总开关。
- **永不硬停**：掌舵不阻塞主持人循环；用户不插手时循环与旧「非交互」路径逐字同辙。

### 6.2 在哪生效、谁说了算

- 主持人**每轮小结后**走轮边界钩子（`Moderator.run` 的 `on_round_boundary`；与 emit `debate_round` 的 `on_round` 正交）——**非阻塞** `take_steers(execution_id)`。
- 空队列 → 回落裁判自动收敛；有 steer → 用户选择**覆盖**裁判：`continue` 即便裁判要收也续；`conclude` 即便裁判要续也在该边界收场（`stop_reason=user_concluded`）。
- **conclude 下一轮边界生效**：用户在某轮生成中途 fire conclude → 当前轮先跑完，到边界才收场（不腰斩正在生成的轮）。

### 6.3 掌舵动作（常驻输入，非挂起卡）

赛事页主列常驻 `SteeringPanel`（辩论进行中可见），fire-and-forget 提交后回显「已发送·下一轮生效」：

| 动作 | 语义 | 落到引擎 |
|---|---|---|
| 继续辩一轮 | 再来一轮（裁判要收也续） | `continue`，无 focus |
| 按此角度继续 | 给下一轮指定议题角度 | `continue` + `focus`（覆写下一轮焦点） |
| 够了，出结论 | 下一轮边界收场出简报 | `conclude`（`stop_reason=user_concluded`） |

**追问（叠加项）**：可选【追问文本 + 定向某方/全场】，与 continue/conclude 一并提交（`ask` + `ask_target`）。注入下一轮辩手 prompt（`round_feedback`）+ 终审交代是否被回应，verbatim 进 `debate_result.rounds[*].user_interjections`（conformance `multi_agent_debate_followup`）。

### 6.4 机制：复用 redirect 模式的 in-process steer 队列

按 `execution_id` fire-and-forget 排队；drain last-wins 折成 `RoundBoundary`。旧阻塞式 `DEBATE_ROUND` 已摘除。**被否**：再造持久化交互；把 ambient 做成阻塞；CEO 猜 `interactive`。→ 见代码: `runtime/debate/steer_queue.py`

### 6.5 前端落点

掌舵**常驻**在赛事页主列 `arena/SteeringPanel`（非「暂停才冒出的挂起卡」）；记分牌有「掌舵」快捷滚到输入区。画布指挥台对辩论仍 `includeDebate=false`。呈现见 [`前端UX设计.md §4.3`](/docs/04-前端/前端UX设计.md)。

### 6.6 收场后再辩（用户对 CEO 说话 · 全新辩论）

用户选「够了，出结论」后若不满意，**不**复活已收场的协程，也**不再**走结构化播种续辩。产品决策（2026-07）：续辩专用链路整体下线——用户在对话框对 CEO 说话，CEO 重开一场**全新辩论**（无 `debate_seed`）。

**曾落地又移除**：结构化补轮（`SendMessageRequest.debate_seed` → …）——与「用户自己对 CEO 说话即可」重叠，维护成本不相称。

**否决（历史仍成立）**：① durable debate resume；② 会话内软撤销窗；③ 服务端自动取最近辩论结果作种子。

### 6.7 站队（用户侧 · 会话内态）

**站队**（倾向某 `side.key` / 未定）是**纯用户侧轻量标注**——仅你可见、**绝不写进 AI 裁决**。前端 store `debateUserTake.ts` + 记分牌 `StanceControl`；终局 `FinaleStage` 附「你 vs AI」软对照。呈现见 [`前端UX设计.md §4.4`](/docs/04-前端/前端UX设计.md)。

**会话内态、不持久化**：重载 / 翻页即重置。

**「用户拍板」(gavel) 已整体移除（2026-06）**：理由见历史——纯客户端标注不回灌 AI、与站队重叠、专用表过建。表由迁移 `f1d8c3a6b9e4` 删除。

→ 见代码：`stores/debateUserTake.ts`、`components/chat/debate/arena/Scoreboard.tsx`。

## 七、技术落点（现状）

### 7.1 主持人 = `debate` 工具内的确定性编排循环（非 LLM 编排角色）

辩论是 CEO 的一个**编排工具** `debate`（`tools/builtin/debate/` 仅 schema + 薄 execute；域逻辑在 `runtime/debate/`，与 `delegate` 同边界原则，`ToolCategory.ORCHESTRATION`，非终结）。CEO 识别对抗性意图 → 调 `debate(motion, form, sides[, thorough, background])` → 工具适配层驱动主持人循环 → 交回双产物供 CEO 用自己的声音收尾。

- **开辩前对齐用户原意（忠于原框）**：CEO 拟 `motion`/`sides` 时须**如实覆盖用户点名的每一极**——用户已给出争议轴 / 具体两极（如「加重【还是】减轻」）时不得悄悄砍掉一极、或把它偷换成更温和 / 不对题的立场（如把「减轻派」换成「审慎派」）；辩论所**依赖**的关键指代模糊（如「最近很火的那个」未点名指哪件事）时，先 `ask_user` 澄清再开辩，仅小返工可平滑纠偏才按合理默认开辩并在正文标注一句。这条行为约束由 `debate_and_review` 系统 Skill（`runtime/skills.py`）承载，回归测试见 `tests/test_skills.py::test_debate_skill_teaches_intent_alignment_before_opening`。
- **`stance` = 一句立场倾向（薄约束，✅ 2026-07；校验口径改语义形状 2026-07-22）**：CEO 开辩时每方 `stance` 只写该方主张什么结论的**单句判断句**（如「支持一审判决正确」/「认为判赔过重」）；**禁**论点清单、论证角度指令、事实细节——客观事实归 `background`，论点与论证路径归辩手自己检索构建。根因：过厚 `stance` 会原文注入辩手「你的立场/视角」，预写大纲让真交锋退化成执行剧本。**校验主拦语义形状**（换行/分号/编号顿号列表/「首先其次」类论证展开/论点清单指令，机械可查、拒后引导重写），字数仅兜底 `STANCE_MAX_CHARS=80`——48 字纯字数闸三次被 LLM 突破致 `debate` 首调失败，实证字符数不是可执行约束。约束由 schema `validate_stance` + `debate_and_review` Skill 承载，回归见 `tests/test_debate_tool.py`、`tests/test_skills.py::test_debate_skill_teaches_thin_stance`。**否决**：拆 `brief` 字段=给病态开合法通道；运行时剥离/摘要=兜底补丁易误伤；只改开工卡展示=治观感不治病；纯字数收紧=LLM 数不了字。
- **赛前底料（`background`，可选）**：具体案件建议 CEO 开辩前检索客观事实随参传入；首轮以主持人名义双方共享注入；底料出处预登记进场级台账改写为 `#eN`。空参零行为变化。→ 见代码: `runtime/debate/prompt.py`

主持人是**确定性 Python 循环**（非自由发挥 LLM agent）：循环骨架由代码控制，每步判断走 `provider.complete` 出结构化 JSON。「怎么派一轮」经 `RoundRunner` 注入。

- **为何确定性循环而非 LLM 编排角色**：循环 / 收敛是确定逻辑，交代码更可控可测；省一层编排 agent token；仍满足「主持人在 CEO 与辩手之间」。
- **委派深度**：辩手 `depth+2` 叶子，卡在 `MAX_DELEGATION_DEPTH=2` 内。

### 7.3 节点结构：CEO → 主持人 → 辩手（主持人为完成态节点）

团队图呈现三层、进度正确收尾：

- **主持人是完成态节点**：emit `run_started`→`run_completed`；`thinking: false` 如实声明。
- **辩手挂主持人下**：身份随 `run_started` 上 wire；发言角色由 `run_context.channel` 表达。
- **辩论进宿主图 · 幕序列 ✅**：辩论作为新幕生长在宿主图（同 `execution_id`）；追加入口 = 机制携带宿主 id；挂点 = 幕1 汇总员后。**否决**「辩论仅作特殊小组」小改方案。→ 见代码: `runtime/kickoff/debate_host.py`
- **逐轮真实任务上 wire ✅**：续写 beat 的 `run_context` 首块为 `channel="task"` 的逐字任务（与喂给 LLM 同一字符串，零双源漂移）。→ 见 [`前端UX设计.md §十`](/docs/04-前端/前端UX设计.md)

> **决策：主持人作为完成态节点**。备选「主持人不进图」会丢掉「谁在主持」层、进度分母不含编排成本。

### 7.4 双产物与 SSE

- **契约决策**：`DebateResult` = brief + rounds + `narrative_first`；给 CEO 只渲染简报 + L1（L2/L3 不进 CEO 上下文）；收场 `debate_result` 为 journal 权威——叙事线 + 质询/记分进事件，**发言/作答全文不进事件**（靠 `run_id` 从图节点取回）；举证内联正文（§四之二）；两端 fold 过 conformance。→ 见代码: `runtime/debate/types.py`
- **辩手消费调研案卷 ✅**：有 `research/` 则注入案卷索引（非全文）；辩手只读工具自取全文。→ 见代码: `runtime/debate/research_dossier.py`
- **逐轮实时 + 重载**：`debate_round_started` / `debate_round` **DURABLE**；重载与收场叙事线互为印证；前端归一单一 `DebateModel`。台账不占 `citations_event`。→ 见代码: `runtime/events/disposition.py`
- ✅ **ambient 掌舵**：§6；旧阻塞式 `DEBATE_ROUND` 已摘除。

### 7.5 真·多模型辩手（各方由不同厂商模型独立驱动）✅ Phase 3 · 2026-07-27 定案

> **状态**：产品定案已收口（含审计补丁 + **2026-07-27 B+C+D 消歧补丁**）；**代码已启用 per-side 注入**；口语→目录消歧 / 默认对阵接通 / 开赛卡改选见下「消歧层」。

**已启用行为**：空身份仍回退 turn 主模型（同模型场）；非空经目录校验后注入路由键；裁判**可点名、不要求中立**（可与辩手同模）。前端徽章以 run **实际执行 model** 为准；kickoff / `debate_result` 带 roster 与裁判字段。

**消歧层（B+C+D · 2026-07-27）**——修「教法要求填三元组、CEO turn 无目录 → ask_user 瞎问」：

| 路径 | 定案 |
|---|---|
| **B · Runtime 消歧（主）** | 辩手 / **裁判**均可只填人类可读提及；开赛前消歧写回正式三元组。点名直开；禁止元问题。裁判**不要求中立**，可与辩手同模。 |
| **C · 默认对阵接通** | 工具旗标 `cross_model=true`（用户只说跨模型未点名）且各方 model 空 → runtime **真调** `resolve_default_matchup` 填入双方；Skill 写清：留空且无旗标 = 同模型场，**不是**跨模型。 |
| **D · 开赛卡兜底** | 消歧零匹配 / 多候选 → 不 silent；开赛卡列出目录候选改选（或结构化失败带候选），**禁止**元问题三选一（「当前主模型 vs 另一个」）。 |

**透传链**：提及或三元组 →（消歧）→ 正式三元组 → 路由键 → debater/取证 payload → `RunSpec.model` → Router。空身份回退 turn 主模型。

#### 定案（入口 · 身份 · 路由 · 默认对阵 · 裁判 · 范围）

| 维度 | 定案 | 理由 |
|---|---|---|
| **入口** | **B 为主**：点名 → CEO 只填 `sides[].model` 口语提及，runtime 消歧直开；**C**：只说跨模型 → `cross_model=true` + 空 model → 套默认对阵；**D**：消歧失败 → 开赛卡/结构化错误列目录候选。禁止 ask_user「是不是当前主模型」 | 消歧是系统责任 |
| **模型身份** | **存储/注入**仍是三元组；**输入允许**不完整提及，由 runtime 消歧后再校验。完整三元组可直填 | 口语层与存储层分离 |
| **允许值** | 消歧结果须落在目录内经 `validate_model_choice` 且凭据齐的条目 | 防 silent 错路由 |
| **空 vs 非法** | 空 model 且无 `cross_model` = 同模型场；`cross_model` + 空 = 套默认对阵（凑不齐则失败）；提及消歧失败 = 硬失败/开赛卡候选，禁 silent | 分清三种意图 |
| **回合 Router** | 开赛前收集辩手 + 裁判所需 provider，扩展 turn extras（辩论专用装配，突破现 `build_turn_router`「最多一个 Worker extra」）——平台↔BYOK 同场必须可路由 | 审计硬阻塞；否则默认对阵②与验收场跑不通 |
| **默认对阵** | ① 平台 allowlist ≥2 → **PLATFORM_MODELS[0] vs [1]**（不是统一目录 models[] 前两项——BYOK 会插在前面）；② 仅 1 个平台模型 + 已配 BYOK DeepSeek → 平台主模型 vs 该 DeepSeek；③ 凑不出两家 → **不开跨模型模式**，提示去配模型 / 加 BYOK。用户点名优先于默认 | 顺序稳定、差异最大 |
| **主持人 / 裁判** | **不要求中立、可与辩手同模**（2026-07-27 纠偏）。用户点名裁判 → `moderator_model` 提及（同辩手消歧）优先；未点名 → 默认可用 DeepSeek 系或 turn 主模型（**不再**因辩手已用而跳过）。CEO/schema 可填裁判提及 | 用户点名优先于旧「中立槽」教条 |
| **取证员** | **跟本方辩手**同一三元组；各方检索预算仍严格同额（§二之二） | 队感一致 |
| **第一刀范围** | 仅 **正反 DEBATE × 2 方**；红队 / 圆桌 per-side **后置** | 降回归面 |
| **呈现** | 记分牌双方 **真实 model 徽章**（run 实际 model，已有）；`team_preview` / 开赛卡 sides 带模型展示 + 裁判 model；决策简报抬头署「正方 X · 反方 Y · 裁判 Z」；计费按各方实际 model 入 `arena` | 「谁更聪明」叙事立得住 |
| **教法** | Skill：点名只填提及、禁元问题；只说跨模型用 `cross_model=true`；正例「平台 5.2」/「DeepSeek」 | 修教法与运行时脱节 |
| **验收** | 端到端至少一场「平台模型 vs DeepSeek（或平台第二模型）」⏳ 待真跑；探针见 [平台LLM接入.md §四](/docs/05-平台与运维/平台LLM接入.md) | 宣传视频仍未启动 → 远期规划 §4.3 |

## 八、被否决 / 决策演进

> 本节为**全局否决 / 演进总表**；另有**就地否决**散在各节上下文，不在此重复：§四之二（质询三支柱的被否方案）、§6.3（追问不另起 `InteractionKind`）、§6.6（可逆叫停 / 结构化补轮的否决与移除）、§6.7（拍板 / 站队的否决与移除史）。

- **独立 Arena 子系统**（独立 SSE + 状态机 + 阶段轮转引擎 + `arena` RunKind）——**仍否决**。主持人不是独立执行引擎，底层复用 DAG 调度；本设计只补回「主持 / 收敛 / 产物」的产品层。
- **旧法：CEO 一次 `delegate` 静态展开 2N 节点 + 手搓跨轮 `depends_on`**——**被替代**。理由：轮数先验固定（无法运行期收敛）、CEO 手搓交错依赖图易错、`round` 与 `depends_on` 无一致性校验。改由主持人逐轮推进。
- **`round` 展示标记**——从「CEO 预先拍、可能与依赖脱节的 display-only 字段」**降级**为「主持人逐轮推进时自然产生、天然与执行一致」的叙事单位。旧的「round/依赖脱节」根因随之消失。
- **机械「最小轮数」楼层**（`min_rounds`，达门槛前不许判收敛）——**被替代**为「主持人逐轮自适应收敛」（§五）。理由：楼层不看内容、把 trivial 命题也逼满 N 轮，续写者每轮输入近乎相同 → 产出冗余的「修订 v2」；「别过早收敛」的意图改由裁判逐轮标准承载（第 1 轮默认继续、`thorough` 调收敛松紧），`max_rounds` 仅留作纯安全上限。`RoundPolicy` 随之去掉 `min_rounds` 字段、新增 `thorough: bool`。
- **二元 pro/con 专属**——**被替代**为「立场标签」泛化模型（§三），支持红队 / 圆桌。
- **主持人 = LLM 编排角色（depth 1 的可委派 agent）**——**落地时改为**「`debate` 工具内的确定性循环 + 每步嵌入式 LLM 判定」（§7.1）。理由：循环 / 收敛逻辑确定化更可控可测、省一层编排 agent 的 token 与不确定性；「主持人在 CEO 与辩手之间」这一层由工具内循环 + 图上完成态节点表达，无需是图上一个 LLM 节点。
- **跨方通道加宽（把质询问答全文塞给对手辩手）**——**否决**（2026-07 对局记忆）。每轮多喂全场质询全文贵 token、且只治「撤回不跨方」一症，不治「成稿看不见己方上轮」；改为裁判兼产结构化 `ledger_events` + 主持人累积注入（§4-2.6），一份摘要同时治两症、预算可控。
- **主持人调研 beat（主持人先自行取证产底料、辩手引用）**——**否决**（2026-07 取证层优化）。辩手的重复检索是**并行**发生的、墙钟被遮蔽；首轮前串行加一个调研 beat（带检索的 ReAct run，约 30–60s）反使首轮墙钟净增，token 减半不抵体验回退。现状 = 幕前调研产物落 `research/`、开赛注入案卷索引（§7.4）+ CEO 对具体案件 / 真实事件类命题仍可备 `background`（工具描述 + Skill 引导，非强制）+ 注入时**归主持人名义**（§7.1）；无案卷时辩手并行独立取证（墙钟最优）。**事实前提修正（2026-07-21，LV 案两场真跑）**：「辩手并行自搜、墙钟被遮蔽」实测不成立——无协调的并行自搜本身就是首轮主要墙钟且质量差（三方重复检索、噪声域名、预算耗尽）。否决仍成立的部分 = 主持人**串行**自查；「无案卷时辩手并行独立取证」随 §二之二 庭前取证阶段**被替代**（受协调的并行分工取证）。
- **辩论独立 SSE 通道 / 散乱事件族**——**仍否决**。收场全量叙事线由单个 `debate_result` 结构化事件承载（§7.4）；逐轮实时只补一对增量（`debate_round_started` / `debate_round`）——走现有 SSE、不另起通道。掌舵不另造决策事件族（§6.4 steer 队列无 SSE）。
- **逐轮阻塞挂起（`DEBATE_ROUND` + `debate_round_decision_*`）**——**被 ambient 掌舵替代**（§六）。旧病：CEO 猜 `interactive` + 每轮硬停 babysit。现状 = 有活跃用户即武装、fire-and-forget steer 队列、轮次边界非阻塞 drain；旧交互 kind / 决策事件 / resolve 路径已摘除。
- **可逆叫停 = durable resume / 软撤销窗 / 服务端自动种子 / 结构化补轮（`debate_seed`）**——**否决 / 已下线**；现状 = 用户对 CEO 说话重开全新辩论（§6.6）。
- **站队/拍板**——**拍板已整体移除、站队降为会话内态**（§6.7）；曾落专用表 `debate_user_takes`（d4e9f2a1c7b6）持久化，因「没人消费的便利贴 + 与站队重叠 + 基建不相称」由迁移 `f1d8c3a6b9e4` 删除。原「存 `messages` metadata / `conversation` JSONB map」备选亦否决（违物理隔离 / 并发易覆）。
- **真·多模型辩手用「人设模拟」（同一模型扮多角）**——**否决**；走真·多模型（各方真由不同厂商模型驱动，§7.5），最有说服力、避免同源模型自导自演。
- **真·多模型一上来 4 方 / 红队·圆桌同期开 per-side**——**否决**；第一刀仅正反 `DEBATE` × 2 方；默认对阵按目录/BYOK 规则解析（§7.5），非写死豆包×DeepSeek。
- **主持人 / 裁判必须中立、不得与辩手同模**——**已撤销**（2026-07-27）；改由用户点名优先，未点名也不再因辩手占用而跳过 DeepSeek（§7.5）。
- **非法模型身份 silent 回退 turn 主模型**——**否决**；非空但校验失败须硬失败进开赛卡；**空身份**回退 turn main 为合法同模型场（§7.5）。
- **仅靠裸 `model` 字符串消歧目录行且无 runtime 消歧层**——**否决**；存储仍须三元组，口语提及须由 `prepare_debate_model_plan` 消歧后再校验（§7.5 B）。
- **沿用 `build_turn_router` 单 Worker extra 撑平台↔BYOK 同场**——**否决**；辩论须装配参与方全集合 extras（§7.5）。
- **把「平台 5.2 / DeepSeek」消歧甩给 CEO `ask_user` 元问题**——**否决**（2026-07-27）；系统消歧或开赛卡列目录候选（§7.5 B+D）。
- **Skill 写默认对阵却不调用 `resolve_default_matchup`**——**否决**；`cross_model=true` 须真接通（§7.5 C）。
