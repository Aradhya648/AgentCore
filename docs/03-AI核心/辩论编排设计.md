## 一、产品目标

**目标**：用对抗性多视角思考，帮用户得到能信、考虑过反面的**结论或决策**，同时看懂**思想如何交锋**。

| 三问 | 答案 |
|---|---|
| 谁用 | 决策者 / 学习者 / 方案作者 |
| 解决什么 | 决策（选 A/B）、压力测试方案、学懂争议话题、思辨 |
| 如何呈现 | 用户只抛问题或选形态；产出**过程 + 结论**双产物 |

**主持人为何存在**：辩论需要有状态编排——发起对抗 → 逐轮判收敛 → 裁决 → 交付双产物。它不是独立执行引擎，而是 **CEO 之下、辩手之上**的编排角色；底层仍复用并行委派 + 上游产物注入。「轮次」对用户隐藏，由收敛自停。

---

## 二、主持人循环

主持人 =「主持 + 裁判 + 书记」三合一。一轮四步：

| 步 | 做什么 |
|---|---|
| 1. 定本轮议题 | 首轮 `_frame` 拆争议焦点；后续优先用上轮 `verdict.next_focus`；`focus_override`（掌舵）最高优先 |
| 2. 派各方发言 | 按形态 profile 分流（正反并行波 / 红队星型三拍 / 圆桌点名串行）；缺席方标 `absent`，跳过对其质询与对抗记分 |
| 3. 质询交锋 | 仅正反 DEBATE + `thorough`；细节 → [质询证据与证人](/docs/03-AI核心/辩论质询证据与证人.md) |
| 4. 裁判 + 决策下一步 | 一次调用兼产：是否真交锋 / 可否收场 / 记分 / 本轮小结 / `next_focus`；收敛 → 简报收场，未收敛 → 下一轮，关键分歧可请老板掌舵 |

**收场前结辩**（仅正反 + thorough）：收敛后各方一次结辩机会（禁新论点），与决策简报并行。细节 → [质询证据与证人](/docs/03-AI核心/辩论质询证据与证人.md)。

**收敛**：由裁判逐轮自判（无实质新论点 / 焦点已成价值之争 / 红队风险挖尽）；`max_rounds` 仅安全保险丝。认真档约 5 轮上限、快速档 `thorough=False` 单轮。主持「裁判」= 辩论域交锋与收敛判定，≠ 通用 worker 质量门。

## 三、三形态

一套循环经 `FormProfile` 参数化；用户只选形态（或由 CEO 判定），永不碰参与方数 / 轮数 / 依赖。

| 形态 | 参与方 | 轮内拓扑 | 质询/结辩 | 产物侧重 |
|---|---|---|---|---|
| **正反辩论** | 正 / 反 | `parallel_wave`（+ thorough 质询） | ✅ / ✅ | 简报先行 |
| **红队挑刺** | 方案方 + 1~N 红队 | finding 星型：攻→合并→应（thorough 复攻） | ❌ / ❌ | finding 台账 + 门决 |
| **多方圆桌** | 3~N 视角 | `nominate_serial`（+ 可选 crux） | ❌ / ❌ | 过程 / 共识地图先行 |

红队之间不互驳；圆桌不作全员并行波（否则各自独白）。

---

## 四、双产物

结束交付两样，不分主次：

1. **结论 · 决策简报**：争议焦点、各方最强论点、倾向判断 + 置信度、建议、**handoffs**（`value` / `fact` / `question`——按谁能闭合分，非旧三分组裸字段）。
2. **过程 · 交锋叙事线**（三层）：L1 焦点小结流 → L2 逐轮攻防 → L3 全文 + 交锋边（`clashes`）。

呈现顺序：决策类（正反/红队）简报先行；探讨类（圆桌）过程先行。前端 → [辩论室 UX](/docs/04-前端/辩论室UX.md)。工作区落盘 → 见代码: `runtime/debate/persist.py`。

---

## 五、庭前取证（决策）

取证是辩论质量的**内在前提、系统责任**，不是用户可选上游关卡（`research_first` 已退役）。开赛后、首轮立论前：

1. 主辩点单（每方 ≤3 条取证任务）→ 2. 主持人代派取证员（同深度叶子、只读检索、无发言；`group=pretrial:investigators:{side}`，禁落 `debate:` 命名空间）→ 3. 并行取证登记场级台账 → 4. 定焦开辩。

**四条边界**：发言权不下放；预算对称；成稿只引台账 `#eN`；`thorough=False` 不带队。案卷桥无条件汇流（CEO 检索 / background / `research/` 一律进 `#eN`）。取证失败降级为辩手自检索，赛程不卡死。

**就地否决**：给辩手 `delegate` 提深度；中立取证员；取证笔记全文注入主辩起点。→ 见代码: `runtime/debate/pretrial.py`。

## 六、老板掌舵

用户是老板：辩论默认自动跑、**永不硬停**；有活跃用户即武装 ambient 掌舵。用户 fire-and-forget 送入 steer 队列，主持人在**下一轮边界非阻塞**捞起：`continue`（可带 focus）/ `conclude`。干预只作用议程 + 价值层，不篡改事实层。收场后再辩 = 对 CEO 说话重开全新辩论（无 durable resume / 结构化补轮）。站队为会话内态、不回灌 AI。前端 → [辩论室 UX](/docs/04-前端/辩论室UX.md)。→ 见代码: `runtime/debate/steer_queue.py`。

---

## 七、技术落点摘要

- **入口**：CEO 调编排工具 `debate`（schema 在 `tools/builtin/debate/`；域逻辑在 `runtime/debate/`）。主持人 = 确定性 Python 循环 + 逐步结构化 LLM 判定，非自由发挥编排 agent。
- **复用**：并行委派 / `continue_run`（辩手跨轮带记忆）/ WaveScheduler / kickoff gate / steer 队列；不重建引擎。
- **图结构**：CEO → 主持人（完成态节点）→ 辩手；辩论进宿主图为新幕。
- **契约**：`DebateResult` = brief + rounds + `narrative_first`；收场 `debate_result` 为 journal 权威；发言全文靠 `run_id` 取回，不进事件。
- **约束**：`stance` 薄单句（禁论点清单）；`background` 可选底料双方共享；辩手 `collaboration=False`。
- **真·多模型辩手**：✅ 已启用——各方可填不同厂商模型（分字段三元组 / 口语消歧含用户「平台的」偏好 / `cross_model` 默认对阵；`model` 禁路由键）；第一刀仅正反 2 方；空身份 = 同模型场。细节 → 见代码: `runtime/debate/`（model plan / router extras）。

## 八、否决项

| 方案 | 结论 |
|---|---|
| **独立 Arena 子系统**（独立 SSE / 状态机 / `arena` RunKind） | **仍否决**——主持人不是独立引擎，只补产品层 |
| CEO 一次 `delegate` 静态展开 2N 节点 | 被主持人逐轮推进替代 |
| 机械 `min_rounds` 楼层 | 被裁判自适应收敛替代；`max_rounds` 仅保险丝 |
| 二元 pro/con 专属 | 被立场标签 + 三形态替代 |
| 主持人 = depth-1 LLM 编排 agent | 改为工具内确定性循环 |
| 辩论独立 SSE 通道 / 散乱事件族 | 仍否决；收场靠 `debate_result` |
| 逐轮阻塞挂起（`DEBATE_ROUND`） | 被 ambient 掌舵替代 |
| 人设模拟当「多模型」 | 否决；走真·多模型 |
| 非法模型身份 silent 回退 | 否决；空身份回退合法，非法硬失败 |
