## 认知同构 · 执行异构

对模型而言 Tool / Skill / 记忆等皆为 token；执行侧异构（Skill 只读、Tool 有副作用、Agent 有循环与状态）。原则：**默认不放，按需才拉**。

五杠杆（选择 / 时机 / 压缩 / 外置 / 分治）实现归属见记忆·工具·执行引擎·协作模式各篇——本文不复制。「谁来拉」已决：**模型自选**（否决 embedding / LLM 预筛）。

## 决策：现在不建统一 ContextProvider

1. 真「目录 + 按需取」consult 源仍少且不同构（Skill / `consult_memory` 成形；Tools 不同源；`consult_rule` 未建）。
2. 第 3 次真实重复才抽——registry 层重复 = 2（Tool / Skill 刻意照抄不共享基类）。
3. 复杂度在写侧 / 执行侧 / 预算侧，不在注入侧统一接口。
4. 收敛长在 `assemble_system_prompt` / `ContextAssembler`，不必新立门派。

守恒律：统一只罩注入侧；输出侧（副作用 / 循环 / 状态）复杂度搬家不消灭。

## 扳机（均未触发 → no-op）

- **A 抽接口**：第 3 个真 consult 源落地 → 小 `Consultable` 协议（非大一统 Provider）。`consult_rule` 等规则量真实增长才建；第一期用户规则只走 `always`。
- **B 建预算**：prompt 真溢出 / 裁错 / 打穿缓存 → 才长裁剪降级。装配主干 + `PromptContributor` 插件化已落地；`budget` 仅预留读取点。COST-004 只观测不闸。
