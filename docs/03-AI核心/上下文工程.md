# 上下文工程

> **定位**：AgentCore「上下文注入」（system prompt 装配）的**工程总览 + 架构决策档**。三件事：① 从第一性原理（"一切 Tool / Skill / Agent / 记忆 ≈ 模型 + 注入的上下文"）给出**认知模型**；② 五个可调度杠杆的 **map**（各指向子系统权威）；③ 『注入侧是否收敛统一抽象（`ContextProvider` / `Assembler`）』的**已定架构决策**（现在不建）与两个**重启扳机**。
>
> **边界**：装配实现的单一真相源在 [记忆 §5.5](/docs/03-AI核心/Agent记忆与知识系统.md)；本文只做 map + 决策理由，不复制各机制实现细节（细节在 `01`–`05`，本文只留指针）。
>
> **来源**：2026-06 一次"从技术实现看 Tool/Skill/Agent 本质"的讨论 + 基于代码现状（`runtime/resolve/prompt.py`、`runtime/context/assembler.py`、`runtime/skills.py`、`tools/registry.py`）的核验。

---

## 一、视角：认知层同构，执行层异构

起点：从技术实现看，Tool / Skill / Agent / 记忆等概念，对模型而言**都是"模型 + 注入的上下文（token）"**。这个判断在**认知层成立**——模型只有一条感知通道（上下文 token），Skill / 工具描述 / persona / 记忆 / A2A 消息都是变成 token 进窗口。[`Agent记忆与知识系统.md` §5.2](/docs/03-AI核心/Agent记忆与知识系统.md) 已逐字写明"注入进 prompt 后一切都是文本"。

但它在**执行层异构**：

| 概念 | 边界另一侧发生什么 |
|---|---|
| **Skill** | 纯只读上下文，零副作用 |
| **Tool** | 上下文（schema）+ 真实副作用执行（走 function-calling 通道） |
| **Agent** | 上下文（persona）+ 自治循环 + 持久状态 |

一句话：**提示词决定"想做什么"，运行时决定"真能做什么"。**

## 二、抽象命名：Provider / Assembler

若只看认知层（注入侧），它可塌缩成两个原语：

- **Provider**：一切上下文片段源的统一形状——`目录()` + `按需取(name)`，或 `预算装配()`。
- **Assembler**：收集片段 → 选择 / 排序 / 裁剪 → 在预算内拼出最终 prompt。

注入侧的核心工程问题只有一个：**避免提示词爆炸**——真正的目标函数不是"塞得下"，而是"对的时间、最少 token、最相关上下文"（成本 / 延迟 / 质量三者受害，质量最致命）。原则：**默认不放，按需才拉（渐进式披露）。**

### 可调度的五个杠杆（均已有实现归属，本节只做指针汇总）

| 杠杆 | 做法 | 实现归属 |
|---|---|---|
| 选择 | 检索 / 路由，只注入相关片段 | [`记忆 §5.6`](/docs/03-AI核心/Agent记忆与知识系统.md) 实时概览 + agentic 检索（向量 RAG 已取消、降扳机后手）；[`执行引擎 Phase1`](/docs/03-AI核心/执行引擎架构设计.md) CEO 只读 / 检索子集 |
| 时机 | 渐进式披露：菜单常驻、正文按需读 | [`工具与能力 §二`](/docs/03-AI核心/工具与能力系统.md) Skill 目录模式 + `consult_skill`；编排工具 schema 短触发；闲聊态省略 `replan`/协调四件套，`delegate`/`ask_user`/`debate` 常驻（`ceo_surface`） |
| 压缩 | 历史 compaction、工具输出截断 | [`执行引擎 §三`](/docs/03-AI核心/执行引擎架构设计.md) 长对话压缩 |
| 外置 | 文件系统当溢出区、递指针 | ⏳ `recall(id)` / Agentic Recall 未落地（[`记忆 §四`](/docs/03-AI核心/Agent记忆与知识系统.md) 远期）；**已落地外置手段** = 工作区落盘 + `file_read` / `consult_memory` 按需取回 |
| 分治 | 子 Agent 各持任务上下文、回传蒸馏结果 | worker 隔离上下文（Anthropic 实测 +90.2%），见 [`Agent协作模式`](/docs/03-AI核心/Agent协作模式.md) |

## 三、守恒律：复杂度不会因统一而消失

统一只发生在注入侧；它对**输出侧**（执行副作用、控制循环、状态生命周期、失败 / 重放）一字未说。复杂度搬家、不消灭：

- → Assembler 的"选什么 / 何时 / 排序 / 淘汰"策略（注入侧唯一难点）
- → 工具 / 记忆写入运行时、[`执行引擎 §8.5`](/docs/03-AI核心/执行引擎架构设计.md) 引擎纯化、`§八` ports

**接口很简单，策略很难；输入统一了，输出没有。**

## 四、决策：现在不建统一 ContextProvider

核验代码现状（2026-06 快照，权威以代码为准）：5 套机制虽多已落地，但**真正的"目录 + 按需取"consult 源仍少**——

| 机制 | 代码现状 |
|---|---|
| Skills | ✅ `SkillRegistry` + `consult_skill`，最完整的"目录 + 按需取" |
| 记忆主题 | ✅ `consult_memory` 按需取主题（`主题/*.md`），第 2 个接线 consult 源（见 [记忆 §5.4](/docs/03-AI核心/Agent记忆与知识系统.md)） |
| Tools | ✅ `ToolRegistry`，但走 function-calling 通道 + 带执行（不同源） |
| Memory→`<rules>` | ✅ 常驻注入 = 用户规则 + AI 记忆两档合成（`memory/rules_injection.py`，用户规则前置权威措辞、跨文件预算）套标签，复杂度在写侧 |
| Rules on_demand / `consult_rule` | ⏳ 面向用户手写规则的通用 `consult_rule` 全仓无实现 |
| Workspace `<workspace_file_index>` | ✅ 实时概览（`runtime/context/workspace_overview.py`）+ agentic 文件工具；**向量 RAG 已取消**、语义检索降为扳机后手（详见 [记忆 §5.6](/docs/03-AI核心/Agent记忆与知识系统.md)） |

四条理由（现在不建）：

1. **真"目录 + 按需取"的 consult 源仍少且不同构**：Skills（`consult_skill`）最完整、记忆主题（`consult_memory`）第 2 个；Tools 不同源、Workspace 概览是实时套标签、面向用户规则的 `consult_rule` 还没建。给尚未成形的 consultable 源设计统一接口，落地必漏必改。
2. **唯一真同构已消化**：`skills.py` 明写"mirrors ToolRegistry"——刻意选"照抄、不共享基类"。按"第 3 次真实重复才抽"的纪律，现在 registry 层真实重复 = 2（Tool / Skill）。
3. **复杂度不在注入侧**（守恒律）：注入侧最便宜；难点在记忆写侧 / 工具执行侧 / 还没建的预算侧。统一接口只罩最便宜那块。
4. **家已点名**：`assemble_system_prompt` docstring 自述"Full version will support skills, rules, workspace context"——真要收敛就长它（装配主干已照此长成 `runtime/context/assembler.py`（`ContextAssembler`），见扳机 B），不必新立门派。

## 五、两个触发扳机（满足才动，均未触发 → no-op）

- **扳机 A（抽接口）⏳**：第 3 个**真**"目录 + 按需取"源落地（市场 Skill / rules on_demand / pgvector 知识库）→ 从 `SkillRegistry` 抽一个小 `Consultable` 协议（3 个真实例撑）。**不是**大一统 Provider。
- **扳机 B（建预算）⏳**：拼出的 prompt **真的**溢出 / 裁错 / 打穿缓存 → 把装配长成带预算 + 优先级的真 Assembler。**装配主干 + 常驻源插件化已落地**：`runtime/context/assembler.py`（`ContextAssembler`） 统一收集 / 排序片段，每个常驻源（base / runtime context / 记忆 / CEO core / 技能目录 / citation / 工作区概览 / 附件）皆为 `PromptContributor` 插件、渲染序由 `SectionOrder` 声明（稳定前缀逐字节一致护缓存）；`budget` 字段已预留**唯一读取点**，但**预算 / 裁剪 / 降级逻辑仍未建**——按需才长。方案见 [`执行引擎 §七`](/docs/03-AI核心/执行引擎架构设计.md)"降级模式"（DeepSeek 1M 未逼到，见 [`记忆 §六`](/docs/03-AI核心/Agent记忆与知识系统.md)）。**COST-004 仅观测**：`cost.prompt_assembled`（系统提示）+ `cost.tools_offered`（tools JSON chars / 约算 token）——零行为改动，攒据后再开软闸。

## 六、文档结论：各子系统维持 split

代码不统一 → 各子系统文档**维持按机制 split**，不建统一权威实现文档（合并文档应是合并代码的结果、非前提：代码维持多套则文档维持 split；若日后建统一模块，再让 move + delete 跟代码一起走）。本文只承载**跨子系统的 map + 架构决策**，不吸收各机制实现细节——那些的单一真相源在 `01`–`05`。
