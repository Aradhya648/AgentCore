## 一、新增一个内置工具

注册面已声明式收敛：三 registry（builtin / worker / CEO）、能力图鉴、白板接线均从声明名册收集，**新增 = 三触点**，不再逐处挂注册。

| 落点 | 职责 |
|---|---|
| `tools/builtin/<your_tool>.py`（或子包如 `web/`） | 工具实现：`ToolSchema` + `execute`（协议 `tools/protocol.py`），并加类属性 `registration = ToolRegistration(surface / audience / 可选 execution_class·browser_class·local_only·ceo_wire·needs_location)` |
| `tools/registration.py` · `_load_declared_tools()` | 名册按序追加该类——registry / catalog / OpenAI defs 的顺序即此序 |
| `tests/test_tool_registry_catalog_snapshot.py`（+ 工具自身单测） | 快照钉住三 registry 成员序、受众、审批档与授权名集 |

**声明字段即分流**：`surface=builtin` 进内置全集（`audience` 含 `ceo` 且 `NEVER` 自动进 CEO 直持集）；`surface=worker_only` 只挂 worker 集（`local_only` 仅本地 backend）；`execution_class` 整类随 `code_execution_enabled_for` 闸、自动进委派授权白名单；**`browser_class`** 叠在 execution 闸之上，另需 `browser_execution_enabled_for`（云端 gVisor 真隔离；subprocess / 本地不挂浏览器，见 `tools/builtin/__init__.py`）；`surface=ceo_orchestration` 进能力图鉴静态 schema、**不**进 worker registry——其运行时构造仍是手工装配（重依赖）：`ceo_wire=always/memory/checkpoint` 在 `runtime/resolve/prepare.py` `_assemble_ceo_toolset`，`coordination` 在 `runtime/resolve/ceo_surface.py`，`board` 走 `register_board_ceo_tools`（assemble / resume 共用）。

**仍要手动碰的例外**：新 CEO 编排原语除声明外还需在 `_assemble_ceo_toolset` 写构造；子命令升格审批（如 `git` 写入、`terminal start`）在 `runtime/approvals.py` · `tool_call_requires_approval`。工具本身无专用 codegen；改 REST schema 走 `pnpm gen:types`（`scripts/dump_openapi.py`）。

行为权威 → [工具与能力系统](/docs/03-AI核心/工具与能力系统.md)、[执行引擎 §五](/docs/03-AI核心/执行引擎架构设计.md)。

## 二、新增一种辩论形态

成员集（enum / 工具 schema enum / wire `form` / `FORM_LABELS` 键）已声明式收敛：权威源 = `DebateForm`；派生面见下「成员集」行。**新增形态的行为面**仍要手写。

| 落点 | 职责 |
|---|---|
| `runtime/debate/types.py` · `DebateForm` + `RoundPolicy.for_form` / `DebateConfig` | **成员集权威源** + 轮次策略；扩 enum 即扩 wire/schema 成员 |
| `runtime/debate/constants.py` · `FORM_LABELS` / `DEBATE_FORM_VALUES` | 展示名（import-time 穷尽断言）；schema enum 序 |
| `runtime/debate/form_profile.py` · `form_profile` | 形态 → 交互单元 + 轮内 phase 拓扑 + 质询/结辩门槛 |
| `runtime/debate/prompt.py`（+ moderator 族） | 辩手/主持人 prompt 与循环差异（`moderator.py` / `moderator_phases.py` / `moderator_agenda.py` / `moderator_judge.py` / `moderator_brief.py`） |
| `tools/builtin/debate/schema.py` · `parse_form`（+ `tool.py`） | 解析；**`form` enum 已由 `DEBATE_FORM_VALUES` 派生**，勿手抄 |
| 根 `pnpm gen:types`（payloads 已用 `DebateForm`；`dump_sse_payload_types.py`） | 再生 `packages/contract-types`（含 `DebateForm` 别名） |
| 桌面 `apps/desktop/.../chat/debate/model/{types,labels,projection}.ts` + `arena/`（入口 `DebateArena.tsx`） | 投影 / 文案 / 形态英雄区（如 `FindingThreads` / `ConsensusMap`）；类型已跟 payload `form` |

| `tests/test_debate_form_member_snapshot.py` | 成员集棘轮（漏扩必红） |
| `conformance/vectors/debate/`（builder + `__init__.py` 登记）→ `packages/protocol-conformance/fixtures/` | 金样；跑 `pnpm conformance` |

|---|---|
| `config/platform.py` · `PlatformSettings` | 厂商 `*_api_key` / `*_base_url` 字段 |

| `llm/provider/router.py` · `ProviderRouter` | 按 `厂商/model` 前缀路由 |
| `llm/provider/openai_compatible.py` | 现厂商均走 OpenAI 兼容客户端 |

| `llm/pricing.py` · `_VENDOR_PREFIXES`（+ `community_prices.py` / `pricing_data/` 可选） | 前缀计价分支 / 价卡 |
| `llm/model_metadata.py` | 目录行展示增强（显示名/能力标签/上下文），未知 id 有 best-effort 派生；**发现源是 catalog，metadata 只 enrichment** |
| `runtime/spans.py`；`api/routes/inference/proxy.py` | 可观测厂商名归一；sidecar 推理代理 |
| 文档 [平台 LLM 接入](/docs/05-平台与运维/平台LLM接入.md)（计费口径 → [成本配额与计费](/docs/05-平台与运维/成本配额与计费.md)） | 运维配方，改完同步 |

**边界**：BYOK 主路 = 用户自配多服务商列表、任意 OpenAI 兼容端点（`llm/provider_service.py` + `api/routes/llm_providers.py`），**不必**动 `_VENDOR_PROVIDERS`——厂商表服务于部署级前缀路由（多模型辩论等）。非 OpenAI 兼容协议需新 `LLMProvider` 实现并改 factory，不能只加前缀（当前仓库无第二套协议实现）。
