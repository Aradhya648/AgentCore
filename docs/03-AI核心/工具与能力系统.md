### 工作区文件与 Git 工具（内置）✅

**注册面为声明式单源**（对齐 LLM 厂商链「表驱动 + 配置即接入」的收敛风格）：每个工具类自带 `registration = ToolRegistration(surface / audience / execution_class / local_only / ceo_wire …)` 声明，`tools/registration.py` 的名册按序收集出三 registry、能力图鉴与白板接线——**新增一个工具 = 实现（含声明）+ 入册 + 测试**三触点，registry / catalog / 装配线不再各自维护平行清单。

平台内置 `build_builtin_registry()`（web / 文件 / grep / `code_search` / git / `test_run` / `code_execute` 等；成员序以声明名册与快照测试为准，**勿写死个数**）；worker 另挂 worker-only 面（`escalate`、便签三件套、`handoff`、`desktop_notify`，以及条件装配的 `terminal` / `browser_*`——见下）；CEO 直持子集 = 内置中声明 `audience` 含 `ceo` 的只读工具（`build_ceo_tool_registry`，与 `approval=NEVER` 只读口径对齐、快照测试锁一致）。编排原语（`delegate`〔含带现场续派 `continue_from_run_id`〕 / `replan` / `debate` 等）声明 `surface=ceo_orchestration`——进能力图鉴、不进 worker registry，重依赖构造仍在 pipeline 装配线（`_assemble_ceo_toolset`）。工作区相关能力要点（契约细节 → 见代码 `tools/builtin/file_ops.py`、`tools/builtin/git_ops.py`）：

| 工具 | 要点 |
|---|---|
| `file_read` | 可选 `offset`（1-based）/ `limit`（≤500 行）；有任一参数走 `WorkspaceBackend.read_lines()`，输出带 `{n:>6}\|` 行号前缀与范围注记；都不传时全文读取（默认 500 行上限，向后兼容）。宜在 `grep`/`code_search` 命中后精读，禁整目录通读。**本 run 已落盘路径** → 硬拒 body 回读（附现盘标题树/行数廉价结构，不计同路径读上限）；探索读仍受同路径成功读上限（默认 2 次）约束 |
| `file_append` | 在文件末尾追加内容（不存在则创建）；`GRANTABLE` + `FILESYSTEM`，与 `file_write` 同属文件改动类审批。**Artifact-first**：仅允许「短骨架 / SECTION·OUTLINE 锚点」后的按节填空，或新建缺失文件；本 run 已 `file_write` 成篇正文的同 path → **硬拒绝**。成功回执 = artifact manifest。超长路径见系统 Skill `long_form_writing` |
| `file_write` | 新建或整体覆盖；对已存在**成篇**成品（≥约 400 字）整文件覆盖 → **硬拒绝**并引导 `str_replace` /（骨架上的）`file_append`。不足阈值的短文件仍可覆盖；覆盖时若正文含省略标记或新字数 < 旧字数 60%，回执另附完整性软警示。成功回执 = **artifact manifest**（path / kind / bytes / lines / hash / 标题树 / 末段预览）——以此验真，禁止再对本文件 `file_read`。中等单篇默认一次写完；超长先骨架再填空 |
| `file_list` | 可选 `recursive` / `max_depth`（默认 3、上限 8）；`recursive=true` 走 `list_tree()`，ASCII 树形（`├──` / `└──` / `│`）；跳过 `IGNORED_DIRS`、总条目上限 200 |
| `grep` ✅ | 精确正则搜文件内容（**内嵌 ripgrep** / Rust regex；云端 Docker、sidecar、桌面 `extraResources` 均带二进制，不依赖 PATH；缺二进制显式失败）。返回 `path:line: text`；`glob` 仅文件名；ignore 为产品名集（不默启 gitignore）。与 `code_search` 并存。→ 见代码 `tools/builtin/grep.py`、`workspace/rg_grep.py` |
| `file_delete` | 默认可逆删除：`LocalWorkspace` 通道走桌面 `shell.trashItem`（系统回收站）；云端 / sidecar（`ServerWorkspace`）移入工作区 `.agentcore/trash/<id>/` 并写 `meta.json`（保留 `original_path` 等还原信息）。`permanent=true` 才硬删。`GRANTABLE` + worker-only |
| `file_copy` | 复制文件或目录树（含二进制）；不覆盖已存在目标；拒绝复制到自身/子树。`GRANTABLE` + worker-only |
| `mkdir` | 创建空目录（含上级）；已存在则失败。`GRANTABLE` + worker-only |
| `file_batch` | 一次提交多条 `move`/`copy`/`delete`/`mkdir`（上限 50）；目标同名冲突 = 跳过入报告；`organize_plan_id` 绑定已确认整理方案时跳过二次审批并校验仅方案内条目；`organize_undo=true` 逆回放当次会话 move/mkdir（删除项引导回收站）。`GRANTABLE` + worker-only |
| `git` | 单工具 + `subcommand` 分派 7 个子命令：`status` / `diff` / `log`（只读，`NEVER`）与 `add` / `commit` / `branch` / `checkout`（写入，审批层单独 gate）。**被否决**：拆 `git_read`+`git_write` 两工具（减模型工具表膨胀）；开放 Bash 跑 git（结构化子命令便于审批分层与前端富渲染）。硬禁 `push`/`reset`/`rebase`/`merge`/`clean`/`stash`；`add` 禁 `.`/`-A`/`--all`/通配符；`commit` 禁 main/master 直提；`GIT_TERMINAL_PROMPT=0` 防挂起 |
| `code_execute` | 长任务经 `ToolContext.on_progress` 发射 `tool_use_progress`（`phase="output"` + `{stream, chunk}`），**复用现有事件、不新增 journaled 类型**；重载后权威态仍为 `tool_use_end` 完整 stdout/stderr。→ 见 [`执行引擎架构设计.md` §二](/docs/03-AI核心/执行引擎架构设计.md) |
| `code_search` ✅ | 意图/概念搜代码（tree-sitter 分块 + BM25；查询保留标识符、中英分词，符号列加权）。与 `grep` **并存**：概念→`code_search`，精确符号/字符串→`grep`；空命中仍 `success` 并附可执行下一步（含建议 grep 关键词），不静默二次调用。索引旁路在 `.agentcore/index/`，**刻意不做** prompt 自动 RAG。云端 / sidecar `ServerWorkspace` 直连盘；`LocalWorkspace`（云遥控桌面）经通道读文件、索引缓存在 `data_dir/code_index/`。设计约束见 [`记忆 §5.6`](/docs/03-AI核心/Agent记忆与知识系统.md)。→ 见代码 `tools/builtin/code_search.py`、`workspace/indexing/` |
| `terminal` ✅ | 后台长时进程（dev server / watch / 长脚本）：单工具 + `subcommand` 分派 `start` / `read` / `stop` / `list`。**worker-only 且仅 `backend.location=="local"` 装配**（`local_only`）；`start` 经审批特判升格。进程由**桌面主进程**代持。一次性短命令仍走 `code_execute`。呈现：右坞「终端」tab。→ 见代码 `tools/builtin/terminal.py` |
| `browser_*` ✅（六工具） | `browser_navigate` / `click` / `type` / `scroll` / `snapshot` / `screenshot`——L3 团队浏览器。**一律 worker-only**（`surface=worker_only` + `browser_class=True` + `execution_class`）；**仅云端 gVisor** 条件装配（`browser_execution_enabled_for`：`backend.location=="server"` 且 `GVISOR_ENABLED` + 沙箱健康；subprocess「伪沙箱」与本地/sidecar **不**挂浏览器）。**架构**：会话级长驻沙箱（跨多次工具同 page）+ 沙箱内 driver ↔ 宿主 **stdio JSON-RPC**（**否决**宿主 Playwright 直连沙箱 browser server——需打 netstack 洞）；egress = Chromium `--proxy-server` 走宿主过滤代理 + `core/net.py` SSRF（公网全开、禁 RFC1918/元数据；**否决**域名白名单起步 / 宿主 nftables）。**画面**：关键帧挂 `tool_use_end.display`（journal 可回放；**否决**挂 transport-only 的 `tool_use_progress`）；直播 = CDP screencast → **SSE 旁路**（附着才开播；**否决**全站首个 WebSocket / 宿主轮询截图）。**接管**：默认仅无 turn 运行时可接管（**否决**运行中任意抢占；接管期零帧落盘 + `browser_takeovers` 表留档）；**登录闭环**：`browser_type` 对 password 硬拒（`metadata.code=password_blocked`）→ `escalate(browser_login=true)`（强制 `awaiting=user`）→ 用户可在 turn 仍 running 时接管登录 → 归还后发「继续」（不自动 resume；会话内 cookie）；**AI 永不经手用户密码**；持久凭据库 / 手机富卡 → M3 后置。审批 `GRANTABLE`。桌面呈现 → [前端技术 §9.12](/docs/04-前端/前端技术与架构.md)。→ 见代码：`tools/builtin/browser.py`、`tools/registration.py`（`browser_class`）、`tools/builtin/__init__.py`（装配闸） |

### 联网检索与引用质量闸 ✅

`web_search` / `read_url` 产出同时进两条通道——**来源卡**（`citations_event` = 成稿实际引用集）与**回合共享证据台账**（stable id / 检索痕迹）。域名可信度由平台层单源 `citation_tier_for_url`（`runtime/citations.py`）判定，**禁止另造第二套分级器**——辩论台账登记、来源卡徽标、台账 `tier` 共用同一规则表。

| 档位 | 来源卡（`citations_event`） | 台账登记 | 典型域（**假设、待校准**） |
|---|---|---|---|
| `blocked`（硬拦） | 检索出口剔除；永不挂卡 | **永不进台账** | UGC 问答（如 `zhidao.baidu.com`）、搜索引擎首页/壳（`baidu.com` / `bing.com` 等精确 host）、浏览器聚合页、中日文词典站（如 `weblio.jp` / `kotobank.jp` / `jitenon.jp`） |
| `weak`（低质） | **仅当成稿显式 `#rN` 引用时挂卡**，强制弱源徽标 | 登记且 `citable=true` | 文库 / 百家号 / 题库聚合 / 知乎·CSDN 等常见 UGC |
| `official` / `media` / `unknown` | 同上：仅成稿引用集挂卡并戳 `tier` | 登记且 `citable=true` | 政府域、权威媒体名单（含中文补齐如 `bjnews.com.cn`）、其余待评 |

**登记谓词（已写死）**：工具成功路径上，**除 `blocked` 外全量登记**进回合共享台账（`runtime/evidence_ledger.py`，id 前缀 `#r`，与 `turn_citations` 同级 ContextVar；并行 worker 分配路径串行化，禁止各从 `#r1` 起编）。注入可见面「`[已登记来源] #rN=url`」；`read_url` 可升级既有条目的 `deep_read`。条目记 `query` / `tier` / `registrant`（`ceo` / `worker:<id>`）等——辩论场级 `#e` 仍走辩论薄封装，**不经**本回合调研路径。

**两通道分工（P2 现状）**：`citations_event` = **成稿实际引用过的台账条目**（按 `cited_ids` 投影，**无硬帽**；旧池帽 24 随池语义退役）；未引用命中只留在独立 SSE `evidence_ledger`（delta / entries / `cited_ids`；DERIVED → `Message.evidence_ledger`）。**被否**：把「除 blocked 外全量」痕迹塞进 `citations_event`（毁主卡信噪，对称辩论 O1）；「先放 weak 进旧池再翻转」中间态（迁移铁律）。主张须证：prompt 软约束已落地（编排侧见 [编排器 · 调研引用](/docs/03-AI核心/编排器与CEO主Agent.md)）；机械闸待观测数据 → 远期规划 §三·主张须证机械闸（详细提案不在公开仓 / 维护者本地）。

**检索姿态（`search_policy`，✅ 2026-07-22）**：per-run 结构化信号（`RunSpec.search_policy` → `ToolContext` → 检索出口 `filter_results_for_injection`，**禁** prompt 文本触发）。`debate_evidence`（辩论庭前取证员 + 辩手 speech research）在注入出口额外硬剔 `weak` 档与商城/词典/医院百科域及产品/词条 path——把任务书「商城/词典不算证据」从教法落成代码；普通调研姿态不受影响（防伤「只有百科有词条」的题）。同批定案：`uniformly_weak`（整页无一命中过线）由「诚实保留 min_keep 残渣」改为**空成功** + 促重拟查询 note，且文案改准「字面重合不足/疑似离题 SERP」——不再自称「搜索引擎降级」（真跑实证模型会复述误导文案）。动因（2026-07-22 场 `f7b4…` 实证）：来源教法在出口不执行，百科/知乎/品牌商城靠字面重合合法过闸、official 注入占比仅 ~9%。→ 见代码 `tools/builtin/web/relevance.py`

## 一、能力域架构 ✅ 已确定（领域模块 ⏳ 未实现 · 只读能力图鉴已落地）

> **实现现状**：目标架构，后端尚无 `capability` **领域模块**（`AgentEntityBinding` / Skill / Rule 能力实体与绑定），MVP 在 pipeline 固定注册内置工具。**但只读「能力图鉴」`GET /v1/capabilities`（`api/routes/capabilities.py` + `tools/catalog.py`）已落地**——与运行时 pipeline 共用同一函数对外暴露工具/技能目录（详见 §二）。

**四关注点**：能力域 `capability`（能力定义与绑定）/ 市场侧（发现与发布）/ 本地侧（已装+自建）/ 获取通道（安装动作）。

**两铁律**：① 运行时永远只读「本地侧」，不直接碰市场侧；② 本地侧不反向依赖市场侧（市场可整体下线而运行时照跑）。

**单源原则**：Tool / Skill / Rule 经统一 `AgentEntityBinding` 绑定到 Agent；能力曾是 marketplace 子模块——根因是「能力地基盖在了市场楼里」，须拆回能力域。

**逻辑本地先行**：当前本地侧 = 云后端 user 维度私有空间；物理本地（设备侧、离线）留演进，不为后者预建 provider 抽象——两条铁律担保将来只换「本地侧从哪儿读」。

## 三、表达形态 vs 创作产物 vs 受控能力 ✅ 已确定

### 3.1 区分原则

| 类别 | 通道 | 判据 | 示例 |
|---|---|---|---|
| **表达形态** | LLM 直写代码块 + 前端渲染 | 只影响呈现、无副作用、不留可编辑产物 | mermaid / markmap / vega-lite |
| **创作产物** | 用户编辑器 + Agent 工具共编 | 可持久化、可反复编辑 | 导图文档、画布、多维表格 |
| **受控能力** | 工具（Tool） | 读写数据、触发副作用、需审计/计费 | 文件读写、HTTP、代码执行 |

**铁律**：纯可视化表达 = 直写代码块 + 前端渲染，绝不包装成工具；需持久化可跨轮编辑则升级为「创作产物」。

**同名异物（判据看通道，不看形态名）**：同一可视化形态名可能横跨上表两栏——最典型是**导图 / mind map**：既是**表达形态**（`markmap`：LLM 直写代码块 + 只读渲染、不留可编辑产物），又是**创作产物**（可持久、可反复编辑的导图文档）。归类**只认「通道 + 是否留可编辑产物」这条判据、不认形态名**：直写代码块 → 前端渲染 = 表达形态；用户编辑器 + Agent 工具共编 + 可持久 = 创作产物。二者是同一形态的两种落地，不矛盾。

> **表达形态层 ✅ 已落地**：聊天内 mermaid / markmap / vega-lite 三引擎渲染，流式先显源码、回合结束再渲染，失败回退源码。→ 见代码 `apps/desktop/src/renderer/components/chat/Diagram.tsx`

### 3.2 为什么直写优于工具（表达形态场景）

工具通路用于表达时有 4 个累积失败点：参数 JSON 构造 → 工具执行 → 模型原样复读结果 → 目标格式语法正确。直写代码块消除前三个失败点，且天然支持流式（半截大纲仍是合法大纲，半截 mermaid 是语法错误）。

### 3.3 文本为典范模型

当内容同时被人和多 Agent 协作创作时，**典范模型应为 Markdown 文本**（非富文本 JSON/AST）——LLM 输出文本、本地 `.md` 落盘是文本、AI diff 也是文本。由此推导：文本即真相、AI 协作一等公民、聊天与编辑器共享渲染核、绝不损坏字节。

### 3.4 创作工具：产物的两副面孔 ✅ 已确定

「创作工具」每个对应一种**产物类型**，与「动作工具」并列：动作工具执行确定性动作不留可编辑产物；创作工具产出可持久 artifact，同时有用户面（UI 编辑器）与 Agent 面（类型注册工具集）。产物统一进文件/产物体系，可被对话 `@` 引用。前端工具箱见 [前端UX设计 §十二](/docs/04-前端/前端UX设计.md)。
