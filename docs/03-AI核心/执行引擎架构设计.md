## 核心定位

执行引擎是 CEO 与 worker 之间的调度中枢：接收 `delegate` 子任务（`build_run_plan` 据 `depends_on` 建 DAG），连续依赖调度、在决策边界让出、处理失败/取消，经 SSE 推状态。

## 一、DAG 调度与受监督波循环

### 连续依赖调度

计划是 DAG：每 step 声明 `depends_on`。`WaveScheduler` **连续依赖调度**——节点自身依赖就绪且并发有空位（`max_parallel`）即发射，**不等同一拓扑波的其余节点**。步骤 `queued → running → completed`，异常 `failed` / `skipped` / `cancelled`。多 Agent = 多 asyncio Task。

**扇入默认宽松（取消≠失败）**：默认 `require_upstream=false`——≥1 上游成功即跑，缺席上游以「前置缺席」块注入（禁编造）；零成功且存在硬缺席才跳过；`FAILED`+`degrade` 属软缺席仍放行。`require_upstream=true` 恢复严格级联；`force_continue=true` 零成功仍放行。CEO 经 `replaces_run_id` 补派可改写下游 `depends_on` 并复活被级联跳过的节点。

**否决**：把「上游须 SUCCESS」写进 ready 谓词——失败节点永不变 COMPLETED，下游会死等，且与 merge 重派冲突。正确路径：级联跳过 + `replaces_run_id` 改边复活。

级联跳过 / 中途取消均 DURABLE（`run_skipped` / `run_cancelled`），重载图上呈「未执行 / 已停止」而非假排队。

### 检查点（与审批正交）

- **CEO `ask_user`**：唯一发问原语；挂起即收口 → `POST …/resume` 冷路。语义见 [检查点与开工卡](/docs/03-AI核心/检查点与开工卡.md)。
- **DAG `checkpoint_after`**：波间 `plan_review`；仅顶层 `depth==0`；挂起即收口。**协调态例外**：只发 `BOUNDARY_YIELD`，用户拍板改走 `ask_user`。
- **勿与工具审批混淆**：`approval_required` 是 GRANTABLE 闸门，非检查点。

**不引入 `RunPhase.PAUSED`**：暂停的是整回合，用 `paused_turns` 落盘；细节 → [运行时三模型与挂起](/docs/03-AI核心/运行时三模型与挂起.md)。

### 受监督波循环（晚绑定 + 边界让出）

把「CEO 下完计划即缺席」改为「CEO 是波边界的监督者」：一次建全 DAG，节点可晚绑定，调度器只在**决策边界**让出，续跑同一张图。

| 概念 | 取值 / 语义 |
|---|---|
| 晚绑定 | `bind_after_deps`：依赖就绪后 CEO 定稿；未定稿绝不调度 |
| 边界判据 | `CHECKPOINT` / `BIND` / `SCOPE`（checkpoint_after · 待定稿 · 未消费 escalate scope） |
| 边界结果 | `PROCEED` / `YIELD`（软暂停、排空 in-flight、尾部不 skip）/ `ABORT` |
| 双臂 | BIND/SCOPE → CEO（无感 `plan_revised`）；CHECKPOINT → 用户 `plan_review` |

**成本纪律**：无晚绑定 / 无 escalation / 无 checkpoint 时一路跑到 terminal——**CEO 回合数 = 真实决策点数，不是波数**。

**偏离信号**：复用非阻塞 `escalate` + `kind=scope|dep`，同走 SCOPE 边界；**否决**为 scope/dep 单立 `InteractionKind`。

**被否决**：worker 实体化（暂压）；默认阻塞路径的波内抢占 / CEO 波内重入（协调模式除外）；运行期软护栏（边界结构性决策后基本不需）。

协调模式 as-built → [编排器 · 协调模式](/docs/03-AI核心/编排器与CEO主Agent.md)。→ 见代码: `runtime/runs/`

### 失败策略与性能约束

| `on_failure` | 行为 |
|---|---|
| `retry`（默认） | 调度器内退避；用尽 FAILED 后按扇入规则处置下游 |
| `skip` / `degrade` / `abort` | 同款扇入 / 下游照跑 / 排空后停整波 |

| 约束 | 值 |
|---|---|
| 最大并行 | 12（`engine_max_parallel_delegations`） |
| 单次 delegate 最大步骤 | 20（`MAX_DELEGATION_TASKS`，产品口径） |
| 事件传播延迟 | < 50ms（目标） |

产物经 `WaveScheduler.completed` 按 `depends_on` 注入下游（无 worker↔worker 直连）。

## 三、执行管线

`conversation/service` → `runtime/pipeline` ReAct → SSE。

**关键决策 / 否决**：

- **历史重建**：最近 N 条 user/assistant 文本进上下文；工具 I/O 不回放；空正文失败轮折叠为系统注记。
- **Finalize**：开局必插 running 占位；Finalize 只结算已有行。**否决**失败再补写/对账自愈。`messages.content` = 最终交付 only。
- **压缩 / 工具清理**：跨回合折叠旧轮（治 context rot + 缓存失效）；回合内 `tool_clear` / `write_args_clear` 只投影发给模型的视图，不动 journal。二者正交。

## 四、ReAct、收敛与执行解耦

### 不变量

轮次上限 `ModelProfile.max_rounds`；治理统一进 `LoopController`（滑窗循环 → NUDGE/FINALIZE、工具失败熔断、无产出早停、反思注入）；交付前 `finish_guard`；结构化 `RoundOutcome` → `LoopDirective`，主循环穷尽 `match`。

### 收敛治理（决策摘要）

| 机制 | 决策要点 |
|------|----------|
| 重复/交替/同参失败 | 滑窗 3 轮 → NUDGE；再触发 → FINALIZE |
| LLM 重试 | 未提交前透明重试；已提交后不重试（否决「按已吐行数」判可重试） |
| 硬失败 / 已提交掉线 | ERROR 或 DEGRADED 收口，保留半成品；**否决** profile 级 Flash→Pro fallback |
| 工具熔断 | 按工具累计；`policy_failure` / `contract_failure` 不进累计 |
| Worker token 硬顶 | 统一单值 backstop（否决四档启发式）；到顶 `force_finalize`；瘦身主力是 `tool_clear` |
| Turn token 硬顶 | 触顶禁新派、在飞跑完不 cancel（策略 A）；交付预留软闸；否决杀在飞 / USD 顶 / 按 playbook 分档 |
| 协作取消 ✅ | **断连 ≠ 取消**。显式 Stop = **取消**（`user_stop` 全清：停协调、关回合）。**否决** Stop→pause 可续（价值薄、同 turn 暂停状态机过重、行业无此惯例）。Interaction 挂起（ask_user 等）仍用 `FinishReason.PAUSED` + 冷 Resume，与 Stop 正交。否决：仅在 cancel 分支塞 harvest 特例 |

**上游 LLM 限流（429）失败可见**（定案）：工程侧短退避（最多 6 次，`Retry-After`>30s 不睡满），**不做** pause 代等。产品态 `LLM_RATE_LIMIT` 中文终态 + 可重试；CEO 回合 `failed` 时若仍 `execution_detached`，失败与「团队后台运行中」**并陈**。与平台 API `RATE_LIMITED` 正交。→ 见代码: `core/errors.LLMRateLimitError` · 桌面 `StatusStrip` / `errors.ts`

**到顶收口**：`is_thrashing()` → DEGRADED + 上浮信号（不自动重分解）；正轨 → `force_finalize`。**顺序分裂已退役**——真并行只在规划层 `delegate`。触顶禁换马甲（须 `continue_from_run_id` 或 `force`）。

### finish_guard

模型自报 done 是唯一终止信号；放行前过纯代码轻层守卫（造引用 / 台账 id / 结构完整性 / 交付验收对照），未过回炉。`LoopController` 强制收口**不过此守卫**。回炉发 `content_reset` / `run_output_reset`（transport-only）。→ 见代码: `runtime/verify.py`

**可用性诚实性（定案：甲 + 丙；乙窄闸 ✅；交付完成窄闸 ✅；完成态互斥 ✅；全面禁吹二期不做）**：

- **真相（丙）**：验证形工具失败（`browser_navigate` / 有界验证 `test_run` / verify 形 `code_execute`·`terminal` 等）必须压低 `delivery_status` verdict，不得仍为 `delivered`；缺口 `reason=verify_failed`。`test_run` 超预算为验证未完成（`contract_failure`），不进工具熔断。
- **路径验收**：`delivery_status.artifacts` = path + `accepted`|`rejected`（主清单数据源）；`delivered_files` / CEO「已交付」**仅** accepted；draft 不进 artifacts。→ 见代码: `runtime/runs/file_acceptance.py`
- **呈现（甲）**：用户面**否决**「交付验收」大卡与卡上动作。主呈现 = 产物清单（`artifacts`）+ 船长散文；`delivered` / `notes` **静默**（不弹验收）；仅 `partial` / `blocked` 一句轻提示（无缺口明细、无按钮）。可用性短问仍可复用最近一次对账事件（供清单与 finish_guard），不另造第二套。
- **与对账矛盾的可用宣称**：`blocked`/`partial` 时 finish_guard 拦「已完整可用」等与 verdict 冲突的窄句式（绑定 verdict，非全面禁吹）。
- **与对账矛盾的修好/验绿宣称（乙·窄闸已落地）**：`blocked`/`partial` 时 finish_guard 另拦「已修好 / 验证通过 / 已跑通」等冲突话术（沿用否定前缀防误伤）；**不等于**全面禁可用类话术二期。
- **与对账矛盾的交付完成宣称（窄闸已纳入）**：`blocked`/`partial` 时另拦闭集「已完成交付 / 交付完成 / 已全部收卷…」与「站点/网站/页面…做好了」（否定前缀豁免；裸「已交付」不升有文件闸）。
- **完成态互斥（收口诚实性）**：同一条用户可见收口只能是 (A) 已交付完整结果 / (B) 部分完成并标明未完成项 / (C) 阻塞需确认——禁止 A∪C（如「请确认」+「已全部收卷」）。真源：`closing_posture`（`finish_guard` 拦单段；resume `reconcile_resume_closing` 拦 pre_pause∪续写硬拼；确认姿势不 G6 重灌）。
- **不做（全面禁吹二期）**：终稿堆正则全面禁「可用」类话术。完成态条**不**再标「交付未过关」（失败细节交轻提示/正文）。

→ 见代码: `delegate/delivery_status.py` · `runtime/verify.py` · 桌面 `DeliveryStatusMount` / `FileArtifactsCard` · 手机 `TeamView` DeliverySection

### 执行与请求解耦

回合执行从 SSE 生命周期解耦：`send` / `regenerate` / `resume` 把 pipeline 作 **detached task** 交 `TurnRunRegistry`；SSE 仅 **attach**；`turn_leases` 持久 RUNNING，崩溃后 sweeper 续跑。

**契约**：

- 客户端断连 ≠ 取消；显式 Stop = **取消**；graceful 关停 = 抢救收口；仅真硬杀标 orphaned。**否决** Stop→pause 同 turn 可续。
- 持久化独立于连接；重连 = journal 回放 + live tail。
- 进程内 registry 非真相；真相在 `turn_leases`。

**Resume 身份不变量**：不新开 turn；`message_id` / `execution_id` / journal 游标不变。**否决** resume 伪装新回合、client UUID 当执行槽键。挂起即收口；窄兜底（帧失败退限时挂起）已删。

`regenerate` = 推翻重来。**否决** `retry-failed`（只补失败节点）：产品入口与 API 已退场；部分失败走对 CEO 续聊 / 同人续派，不另开机械补跑旁路。

## 五、工具装配原则

- **声明式单源**：工具类自带 `registration`；三 registry / 能力图鉴从名册收集，禁平行清单。
- **全部 opt-in**：无「对所有 Agent 默认发放」的 core 档（MVP 装配现状以代码为准）。
- **审批与来源无关**：只认 `ToolSchema.approval`；`GRANTABLE` 仅 worker、本地经 `ApprovalGate`。
- **时间即上下文**：当前时间进 system prompt `<runtime_context>`，不走工具。

## 六、任务分级与模型选择

无 `classify_task`、无 worker 模型档位。一回合解析一个上游模型（`turn_model`），CEO / worker / 辩手共用。力度差异走协作结构，不走 profile 档。**否决**编排者强档/叶子便宜档与请求级 `"auto"` 分级树。

## 七、提示词架构

World A（Agent 主提示词，`PromptAssembler`）与 World B（内部窄任务）互不相交——关注点不同，禁强行共用。装配顺序权威 → [记忆系统 §5.5](/docs/03-AI核心/Agent记忆与知识系统.md)。World B 统一 registry **暂不收敛**（同形样板拖累或第 4 处窄任务再抽薄助手）。
