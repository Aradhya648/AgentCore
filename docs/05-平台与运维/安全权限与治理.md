### 对话导出与公开分享（导出对话 / 分享对话）✅ 已落地

> 把对话「带出产品」的两条路径，安全要点全在「代码看不出来的取舍」上。→ 见代码 `api/routes/conversations/crud.py`（export）、`api/routes/sharing.py`、`conversation/export.py`、`conversation/sharing.py`、`db/models/conversations.py:ConversationShare`。

**导出（私有下载）**：所有者把整段对话存成 Markdown（仅问答正文，给人读/粘贴）或 JSON（全保真，可再导入）下载。读**整段**转录（非滚动窗口，避免漏）、owner-scoped（非属主 404，IDOR）；花费等台账字段不进导出（在成本台账，不在消息体）。下载文件名由服务端净化并带 RFC 5987 `filename*`（承载中文标题），经 CORS `expose_headers` 放行供前端读取。整段导出仍以交付正文为准；单条消息在客户端复制另有「仅交付 / 含过程」两档（过程来自该回合 journal / `process[]`，不改导出契约）——见 [前端 UX §一B](/docs/04-前端/前端UX设计.md)。

**分享（公开只读链接）**——决策与约束：

| 决策 | 取舍 |
|---|---|
| **冻结快照**而非实时只读 | 链接 = 创建那刻的内容拷贝（`conversation_shares.snapshot`）；之后编辑 / 新回合都不影响已有链接（所见即所享），杜绝「未来内容意外泄露」，也免去公开面实时鉴权 |
| **仅问答正文**（user/assistant 文本） | 快照只取对话正文，**剔除** reasoning / 成本 / 工具内部数据 / 引用等敏感或冗余面——公开面最小化暴露 |
| **服务端渲染 HTML**（非前端构建） | 公开页 `GET /shared/{token}` 直出自包含 HTML，无需装应用即可看；Markdown 经 `markdown-it-py`（`html=False` + 拒危险链接 scheme）渲染——未受信正文当数据、绝不当可执行 HTML / 活链接，杜绝 XSS。页面带 `noindex` |
| **不泄露存在性** | 未知 / 已撤销 / 格式非法 token 一律返回极简 404 页（不 500，也不区分「不存在」与「已撤销」） |
| **可随时撤销** | 软撤销（`revoked_at`）：撤销后公开页立即 404；创建 / 列出 / 撤销管理端点均 owner-scoped |
| **级联撤销** | 删除对话、或注销账户（匿名化）时连带撤销其全部分享链接——数据卫生与隐私一致性（→ `ConversationShareRepository.revoke_all_for_*`，调用点见 `conversations/crud.py` 删除、`auth.py` 注销） |
| 过期策略 | ✅ 新建默认 **30 天** TTL（`expires_in_days` 可选 7/30/`null` 永不过期）；到期公开页 404。仍可显式撤销 + 级联 |

> 这是统一 `share` 插件（[`后端架构.md` §二·平台业务](/docs/02-架构/后端架构.md)：文件 + 对话 + `share_token` + 过期）的**首个落地切片**，现以对话专用实现内建于 conversation 模块；统一插件仍 ⏳。

### 多人共享空间的安全面（✅ 2026-07-16）

产品形态与机制 → [双模式工作区 §十一](/docs/02-架构/双模式工作区.md)；此处只记安全要点：

- **成员鉴权独立成模块，不在 owner-scope 上开洞**：全库「owner 独占、非属主 404」不变量（§十「多租隔离」）保持零改动；`shared:` 是 workspace 解析的**加法式**成员分支（`shared_spaces/service.py`），非成员 / 未知 id 一律 404（不泄露存在性，与分享同姿态）。这是否决「Folder+成员表」的首要理由。
- **角色即授权，审批门在成员会话侧**：viewer/editor/owner 三档映射真实读写面；成员 Agent 写空间走**该成员自己会话**的 `permission_preset` 审批，空间侧不加第二道门——owner 授「可编辑」即等于信任对方会话的 Agent 写面。**工具调用粒度实时校验角色**：降权/移除后下一次文件操作即拒绝，不吃缓存旧权限。
- **邀请防遍历 + 拉黑联动**：仅 IM 精确搜人定向邀请（接受制）；拉黑挡新邀请并自动拒双方 pending，不自动移除已有成员（避免隐式数据剥夺，移除恒为 owner 显式动作）。
- **注销级联**：`cleanup_account_resources` 扩展——owner 注销删空间与盘并通知成员，成员注销删成员行废挂载，双方 pending 清理（与分享链接级联撤销同一数据卫生纪律）。
- **防滥用底线（非计费配额维）**：10 空间/人 · 20 成员/空间 · 1 GiB/空间 · 邀请 20 次/小时。

## 三、工具审批与开工授权（Human-in-the-Loop） ✅ 已确定

### 核心问题

旧模型（布尔开关 `approval_required`）只有「每次都问 / 从不问」两档。批量场景崩坏：一次团队委派产出 76 个本地文件 = 76 次审批弹窗。审批疲劳的终点是用户无脑点允许——门还在，防护已经没了。

### 两态策略（工具固有属性）

审批级别是**工具的固有属性**（声明在工具定义处），判据 = 可逆性 × 副作用范围：

| 级别 | 语义 | 判据 | 代表工具 |
|------|------|------|---------|
| `never` | 静默执行 | 只读 / 纯计算 / 可信沙箱 | 检索（`web_search` / `read_url`）、计算器、数据库查询 |
| `grantable` | 经能力授权后可放行 | 有副作用但局部可控，典型为批量发生 | 写本地文件（含 `file_copy` / `mkdir` / `file_batch`）、**可逆删除**（`file_delete` 默认进回收站/软删区；`permanent=true` 仍走本档）、**Git 写入**（`add`/`commit`/`branch`/`checkout`）、执行代码（`code_execute` / `test_run`） |

> 原三态中的 `always`（每次都审批、不提供放行）已确认无消费者后删除；不可逆外部副作用工具不在 MVP 集合内。

→ 见代码 `runtime/approvals.py`、`api/routes/conversations/`、`tools/builtin.approval_class_tool_names()` / `delegation_grantable_tool_names()`（统一白名单：文件改动类 + `git` + 执行类）

**`git` 写入子命令**：`git` 工具 `schema.approval=NEVER`（使 CEO 注册表自动收录只读子集），但 `tool_call_requires_approval()` 对 `add`/`commit`/`branch`/`checkout` 升格为与 `file_write` 相同的 `ApprovalGate`。「本轮内允许所有文件改动」与开工卡授权白名单**同时覆盖** `git` 写入与 `test_run`。

**`terminal` 子命令（同款机制第二例）✅**：`terminal`（后台进程，worker-only / 仅本地模式装配）schema 亦 `NEVER`，仅 `start`（spawn 长进程）经 `tool_call_requires_approval()` 特判升格；`read` / `stop` / `list` 免审批（只读 / 自家进程低危）。已纳入 `delegation_grantable_tool_names()` 执行类白名单（开工卡一次授权可覆盖 start）。用户在终端 tab 手动停止进程 = 用户主权、不走审批。

**用户交互 shell 与 AI 的边界（M3 决策，2026-07-12）✅**：右坞「你的终端」（node-pty）**不设边界**——不拦 cd / 不拦命令 / 不走 AI 审批门（用户自己的手，同系统终端心智；限制既反直觉也防不住）。AI 侧三条铁律：① **可读**——用户 pty 会话纳入 `process_list` / `process_read`（name=`用户终端 #N`、read 前 strip ANSI），终端输出走工具结果通道、被既有 `<untrusted_content>` 基座框定为数据非指令（与 `code_execute` 输出同级注入面，不需新机制），UI 在该区常驻「AI 可读取此终端输出」透明提示；② **不可停**——`process_stop` 对用户终端 typed 拒绝（仅用户可关，反向主权保护）；③ **不可写**——AI 向用户终端注入输入（`send_to_terminal` 类）仍为高危未开放项（终端提案 §6 边界）。→ 见代码 `desktop/main/pty-service.ts`、`desktop/main/fs/workspace/process.ts`

### 会话级权限模式 PermissionPreset ✅ P1

运行时权限判定的**单一真相源** = `conversations.permission_preset`（不做双层取更严）。用户级 `AutonomyPolicy` 仅作新建会话种子。

| 会话档 | 语义 | ← 用户默认映射 |
|---|---|---|
| `observe` | 不注册执行类工具；写类逐次审批；开工卡不预授权写类；只读检索照常 | `always_ask` |
| `workspace`（默认） | **会话信任文件改动类**（`mkdir` / 写 / 改 / 可逆删 / git 写入免逐次卡；永久删仍问）；开工卡确认组队并授权**执行类**（code / terminal / browser）；云 gVisor 执行自动放行 | `first_grant` |
| `full_trust` | ≈ 原 full_auto：跳过开工卡；全自动放行，含本地 sidecar 执行免审批（UI 明示「AI 将与你同权执行命令」） | `full_auto` |

git 硬禁清单等既有熔断不随任何模式放开。团队统一用会话模式，不做按 Agent 角色分权。存量会话回填 `workspace`。

**全链路取值**：云端新回合 / durable resume 在回合入口读会话列；sidecar 由桌面每回合传 `permissionPreset`。中途切换：`PUT /v1/conversations/{id}/permission-preset`（下一回合生效；**P2** 写入 `agent_audit_events` `permission.preset_changed`）。

→ 见代码 `core.types.PermissionPreset`、`conversations.permission_preset`、`conversation/common.resolve_permission_preset`、sidecar handlers、桌面 `services/permissionPreset.ts`；用户默认仍 `GET/PUT /v1/users/me/autonomy`（设置页文案为「新会话默认权限模式」）。无单独「本地目录信任」层——绑本地根即用户主动选择，权限只靠会话 `permission_preset`。
### 沙箱 → 审批策略表 ✅

| 环境 | 执行类工具（`code_execute` / `test_run`） |
|---|---|
| 本地 subprocess | 需授权（走 ApprovalGate / 开工卡） |
| 云端 gVisor 真隔离 | 自动放行（不弹审批） |
| 云端无沙箱 | 不可用（工具不注册，现状保持） |

例外：dev 逃生口 `CODE_EXECUTE_CLOUD_ENABLED`（§5.4）开启时云端照常注册执行类并**免审批**执行——姿态表只喂 auto-pass、云端 worker 本就不挂 per-call 闸（`worker_gate_applies=False`）；生产默认关 + 非 debug 无 ack 拒启动不变。

→ 见代码 `runtime/sandbox_approval.py`

### 统一熔断层（circuit breaker）✅ P3

对齐 Claude Code「bypass 模式下熔断仍在」：无论会话模式（含 `full_trust`）、开工卡授权、「本轮内都允许」，熔断规则恒生效——**毁灭性动作**（`rm -rf` 根/家目录、格式化/写设备、强推 main/master、关机类）强制人工审批，且熔断卡上的「本轮都允许」降级为一次性；**敏感文件读**（`.env*` / 私钥 / 凭据类路径）直接拒绝并按 `policy_failure` 回填令模型改道。git 硬禁子命令清单收口至同一模块（行为不变）。触发写 `agent_audit_events` `permission.circuit_breaker`（force 落盘）。**定位如实**：启发式黑名单是兜底最后防线、不是安全边界（可被绕过），审批卡文案与代码注释均不宣称完整拦截。→ 见代码 `runtime/safety_breaker.py`

### 「本轮内都允许」的四条边界

| # | 边界 | 理由 |
|---|------|------|
| 1 | **turn 级**，非会话级/永久 | 每条用户消息是一个新的意图边界 |
| 2 | **按「类操作」放行**，非全部工具 | 默认粒度【同名工具】；文件改动另给【文件改动类】（含 `git` 写入）；执行类可对本工具名本轮放行，但不被文件档覆盖 |
| 3 | **整棵 DAG/委派树共享** | 子 Agent 也执行相同操作，只对主 Agent 生效则形同虚设 |
| 4 | **新轮清场 + TTL 兜底** | 下一条消息永远从干净状态开始 |

### 开工卡（编排层统一 · 两卡合一）✅

原 `team_preview`（计划确认）与 `delegation_authorization`（能力授权）合并为一张**开工卡**（事件类型仍为 `team_preview_*`，冷路 durable 挂起），并由编排层公共 gate（`runtime/kickoff`）供 `delegate` 与 `debate` 共用：

- payload 带 ``primitive``（`delegate` / `debate`）判别卡片布局
- delegate：展示即将上场的队员（角色 / 任务 / 依赖 / 辩论）**同时**列出将授权的**执行能力**（`execution_class`：code / terminal / browser；文件改动类已由会话档 `workspace`/`full_trust` 信任，不再列在卡上）
- debate：展示辩题 / 各方立场 / 轮次预算（辩手只读 → 能力半边恒空）
- 一次交互：delegate **授权并开工（可带嘱咐）** / **停止**；debate **授权开赛（可带开赛嘱咐）** / **停止**（原条件第三键 `research_first` 已于 2026-07-21 随庭前取证内化退役，历史卡渲染保留；见 [`编排器 §五`](/docs/03-AI核心/编排器与CEO主Agent.md)）。delegate 嘱咐非空时授权开工 ≡ 原 adjust（steer 注入全体未跑队员）；debate 嘱咐 = 首轮全场用户插话（不覆写辩题，换辩题走停止后对 CEO 重说）；`per_call` / `adjust` 入口均已撤，枚举保留供历史时间线渲染
- 会话 `permission_preset=full_trust` 时两原语都不弹卡；能力静默授权（P1 前判据为 `AutonomyPolicy.full_auto`）
- 跨对话感知与审批同等：Toast / 侧栏待审批点 / 原生通知

→ 见代码 `runtime/kickoff/`、`runtime/approvals.py::grant_delegation` / `_session_file_trust_covers`、桌面 `ResumePrompt` / `TeamPreviewCard` / `teamActivityNotifications`

### 交互设计

- 逐次审批卡按钮：**允许一次 · 本轮内都允许 · 拒绝**；文件改动类多一档 **本轮内允许所有文件改动**
- `file_batch` 审批卡：标题「本次共 N 项」+ 最简操作清单（move/copy/delete/mkdir）；整理方案卡（`card=organize_plan`）确认后批次经 `organize_plan_id` 绑定放行，不再二次弹卡。**云端裸聊整理**同此面（方案卡 + 桌面 op 白名单），**不**挂 `worker_gate`（`ServerWorkspace.location` 仍为 `server`，仅 `external/` 走 per-op `root_id` 通道）→ [双模式工作区 §八.10](/docs/02-架构/双模式工作区.md)、§十不变量表
- **执行确认面（对标 Cursor · 单一聊天内确认）**：
  - **`workspaceOp('execute')` / AI `code_execute`**：仅聊天审批卡——`workspace_op_required` 只在后端 `ApprovalGate` 放行后触发；主进程**不再**叠 OS「即将运行 python」框。
  - **用户直触 bash**（代码块「在终端运行」，唯一入口）：聊天内 `RunConfirmPrompt` DecisionCard（取消 | 运行 | **本会话都允许**）；经 `rendererConfirmed` + `fs:grantSessionRun` 跳过 native。未带确认的旧 IPC 入参仍走 native 兜底。
  - **`openPath`**：仍白名单 + 单次 native 确认；不引入永久跨天 allowlist。
- `code_execute` 审批卡信息面 ✅：可本轮放行后，优化方向仍是**提高单次审批的信号质量 + 削减不必要弹窗**。① 卡片标题用模型自述的可选 `purpose` 参数（意图声明），并列展示由代码文本启发式派生的风险标签；② 参数预览默认 600 字符截断，唯 `code_execute.code` 放宽至 20K；③ 工具描述引导「抓网页/调公开 API 优先 `read_url`/`web_search`」，削减纯网络读取走 `code_execute` 的弹窗。根因解 → 见 §五 演进方向
- 并行审批自动批量放行：权威实现在后端门 `ApprovalGate._sweep_pending_tools`；sibling 清扫有 conformance 向量钉住。
- 工具审批拒绝回填 ✅：被拒调用向模型回注中文「未获用户授权」令其改道，并标 `policy_failure`（不进熔断）；同回合同工具 `_denied` 不重复弹卡。默认无限期等待（无自动 deny）；运维可配 `approval_timeout_seconds` 上限。

### 被否决的方案

- **永久 allowlist**：消费级跨天对话里永久放行 = 失去感知
- **按 Agent 放行**：用户难以理解「放行的是谁」，DAG 对用户半透明
- **审批队列批量勾选**：UI 复杂，不解决后续调用还会弹的根本问题
- **两卡串联**（先团队预审再委派授权）：交互冗余，已合并为开工卡

### 演进路线

根答案是**可回滚性决定是否需要审批**。路线：本地写入前自动备份 → 一键还原 → 写文件从 `grantable` 降为 `never`（零审批、可撤销），审批只剩不可逆动作。两态模型为此预留平滑通道——只改工具声明级别，交互不动。

## 五、代码执行沙箱 ✅ 已确定

> AI 的「跑代码」工具（`code_execute`）的隔离边界设计。

> **MVP**：受限 subprocess + `SandboxProvider` 抽象。gVisor 第二实现**已落地并完成生产化**（开关默认关、按部署灰度开；产物写回 / 护栏见下）；Firecracker / NATS → 见 远期规划 §2.1（详细提案不在公开仓 / 维护者本地）。

### 5.1 为何需要独立沙箱

API 容器内子进程不构成安全边界——资源爆炸拖垮全站、子进程可达内部 DB、黑名单模型不可靠。

**威胁模型前提（产品决策）**：云端 server **将面向公众多租**（现内测、公测后开放注册）→ 不可信多租成立。故 `test_run` / 沙箱硬化（真隔离、越权拦截、资源/网络限额、工作区写模型兑现）列为**公测上线前必做**，不是「仅自用则可选项」。

### 5.4 默认关闭治理

> **实现现状 ✅**：云端 `location=server` 工作区默认**不注册**代码执行类工具（`code_execute` / `test_run`——`test_run` 跑测试即执行任意工程代码，执行力等价，同经 `code_execution_enabled_for` 一个闸；`CODE_EXECUTE_CLOUD_ENABLED=false`）；本地 / sidecar（`location=local`）保留 + 审批门。独立沙箱 worker ⏳ 远期。

**「关闭时工具不进入工具列表」✅ 已按现有开关兑现**：闸门谓词 `code_execution_enabled_for`（`GVISOR_ENABLED` / `CODE_EXECUTE_CLOUD_ENABLED`）统一治理执行类注册，关闭即整类不注册——原设想的独立 `code_sandbox_backend` 枚举由此取代。配置开启时另叠一层**启动期健康探测**（`tools/sandbox/cloud_health.py`，lifespan 一次性）：探测失败折入同一谓词 → 整类不装配 + `workspace_context` 如实显示未装配（fail-safe，不拒启；宣告与真实可用性一致）。`http_request_enabled` ⏳ 保留原义（通用 HTTP 请求工具至今未建，建时默认 `false`）。

### 5.x SandboxProvider Seam

→ 见 [`核心接口定义.md` §三](/docs/02-架构/核心接口定义.md)（`SandboxProvider` 协议、`code_execute` 只依赖协议、失败语义映射为 `ExecutionResult` 不抛异常打断 ReAct 循环）。

**第二实现 ✅（生产化已落地，开关默认关、按部署灰度开）**：`GVisorSandbox`（`tools/sandbox/gvisor.py`，`GVISOR_ENABLED`）已落地；工厂选择 `local`/`sidecar` → `SubprocessSandbox`（可信本机，**不**强制 gVisor），`server` + gVisor 门控 → `GVisorSandbox`；Firecracker + NATS worker 再后（见 远期规划 §2.1（详细提案不在公开仓 / 维护者本地））。云端模型：**按会话 `permission_preset` 分级出站（P2）**——`observe` / `workspace` 仍 `--network=none`；`full_trust` 走 `network_mode=restricted`（去掉硬编码断网 + OCI network namespace，受控出站；产品 HTTP 工具仍过 `core/net.py` SSRF）。**被否决**：Phase 2 主路径走 E2B/Modal 托管沙箱（与自建/BYOK 方向冲突，可作远期企业选项）。

**产物写回（copy-in / copy-out）✅**：沙箱**永远拿不到权威工作区的可写句柄**——每次执行把工作区**拷贝**进一次性 staging 目录、以 **rw** 绑到 `/workspace`（cwd，相对路径写行为与本地 Subprocess 一致）；进程跑完（任意退出码）后把新增 / 变更的普通文件在限额内拷回真实工作区，写回清单上 `ExecutionResult.written_files`（工具结果向模型如实列出、日志 `sandbox.write_back` 可审计）。超时 / 取消**不写回**（被杀进程不落半成品）；删除**不回传**（产物语义：只增改、不静默删权威文件）；symlink 双向剔除 + `.agentcore/` 内部区双向排除 + 写回目标 realpath 圈定工作区内。**被替代**：原「/workspace 只读 + overlay（ro 下层 + tmpfs 上层）」方案——runsc overlay 上层是内部 filestore、产物取不出来，且 tmpfs 上层本就不落盘，满足不了「云端生成 pptx 可下载」的产品要求，由 staging 写回取代。→ 见代码 `tools/sandbox/staging.py`、`tools/sandbox/gvisor.py`

**灰度护栏 ✅（配置见 `production.env.example`「云端代码执行」段）**：进程级执行位信号量 `GVISOR_MAX_CONCURRENT_EXECUTIONS`（2C8G 起步值 2）+ **有界等待**（`GVISOR_SLOT_WAIT_SECONDS`，默认 15s，等不到 → 快速失败、stderr 向模型解释「执行位已满，稍后重试」——纯快失败在轻度争抢下太脆，无界排队会顶穿引擎工具 90s 兜底，故取有界等待）；单次执行 `GVISOR_MEMORY_LIMIT_MB`（OCI cgroup，默认 512）+ `GVISOR_TIMEOUT_MAX_SECONDS`（默认 60，超时杀进程不写回）；staging / 写回限额 `GVISOR_STAGE_MAX_BYTES` / `GVISOR_WRITE_BACK_MAX_BYTES` / `GVISOR_WRITE_BACK_MAX_FILES`（超限跳过并向模型披露件数）。**不为云执行新增配额维**（既有决策，[双模式工作区 §八.7](/docs/02-架构/双模式工作区.md)）。运行前置（镜像 runsc、compose 权限叠加、部署后人工验证清单）→ [部署与运维 §云端执行灰度](/docs/05-平台与运维/部署与运维.md)。

### 管理后台模块定位

→ 详见 [`管理员后台.md`](/docs/05-平台与运维/管理员后台.md)（独立 `apps/admin`、P0 契约、鉴权姿态）。

例外规则：域 service 无对应写方法的治理专用字段（如 `role`/`status`），由管理模块端到端拥有；一旦域将该写操作正式暴露为 service 方法，立即改为委托。

### 审计日志

管理操作写入 **append-only 审计表**，确保所有治理行为（下架、角色变更、停用）可追溯。

### Agent 行为审计（✅ Phase 1–2 已落地）

**为什么单独一层**：多 Agent 协作引入四类单 Agent 不存在、现有基础设施未直接覆盖的追溯难题——**决策归因**（文件谁写 / 谁触发，跨 CEO delegate / 上游 pass_through / 便签 decision）、**并行因果**（同波 worker 的输入依赖谁的产出）、**跨 Agent 数据流**（pass_through 注入 / 便签广播 / 文件指针的敏感流转）、**权限传播**（嵌套委派深度 / `tools` 收窄 / 审批 DAG 的**生效**权限）。**不重复建设边界**：Turn Journal 仍是回放 / UI 单一事实源，审计表是从 journal + 运行时钩子**投影**的查询视图（不替代，见 [执行引擎 §8.3](/docs/03-AI核心/执行引擎架构设计.md)）；`cost_events` 仍是钱的单一源（审计只引 `run_id`/`message_id`、不复制 token）；`admin_audit_logs` 只管人工治理操作（与 Agent 自动行为审计分表、分受众）。

**采集与 schema**：append-only `agent_audit_events` 专表，`AuditRecorder` **先 journal 后审计**偏序采集，写库走 **telemetry 独立池**（与正文写 primary 池分离，重度并行下永不抢正文连接，见 [成本配额 §三](/docs/05-平台与运维/成本配额与计费.md)）+ **回合内 `create_task` 异步投递 + 回合末 `flush`**（不阻塞热路径、失败不阻断回合、降级计数入 `turn_metrics.audit_drops`）；**默认仅 delegate 回合写审计**；**P2：`full_trust` 会话全回合采集工具副作用**（不依赖是否委派）；审批决策（`approval.*`）**force 落盘**（含非委派回合）；模式切换 `PUT …/permission-preset` 写 `permission.preset_changed`（category=permission）。记录编排决策 + 副作用工具 + 审批 + Agent 间通信（流向元数据；便签 ≤200 字全文为唯一例外）+ 状态 / 失败 + 每 run 权限生效快照 + checkpoint 挂起 / 恢复 + 重试 `attempt` 序号 + 权限明细（`permission.tool_disabled` / `permission.write_conflict` / `approval.swept` / `permission.preset_snapshot`）；不记只读工具与流式 delta。schema 取舍：去 `actor_run_id`（由 `actor_kind`+`run_id` 推导）、`seq` per-recorder 独立编号 + `(turn_id, seq)` **唯一约束**（幂等去重，容 at-least-once 重投不生重复行）、`target_ref` 存工作区相对路径。审批「谁批了什么」落在 `detail.decided_by=user`（`actor_kind` 仍为 captain/member/system，不加 DB 枚举迁移）。

**因果 · 查询 · 留存**：审计 API 可选返回 `causal_graph`——后端按 `depends_on`/`parent_run_id` **运行时重建** parent / depends_on / inject 三类边（`include_causal` 开关，`build_causal_graph` + 单测已就绪）。inject 上游取自 `run_context` wire 的 `blocks[].source_run_id`（`projector._context_inject_source_run_ids`）；修复前写入的历史行不回填，须新跑多 Agent 回合才有 inject 边。**C 端不设通用审计时间线**（否决 GraphView 节点「活动 N」角标 → drill-in run 详情「活动记录」）；场景化消费面为：① 桌面 run 详情「关系 › 数据从哪来」inject 入边（`useTurnAudit` + `include_causal`，默认折叠、可下钻上游）；② 协作图审计数据流高亮（`litRunId` inject 邻域 + 工具栏「始终显示审计数据流」）；③ 文件预览写入链反查（`GET …/audit/file?path=` / `FileAuditTrail`）；④ **P2 权限档位就近展示**（回合级 `useTurnAudit` 的 `permission.preset_snapshot` → run 详情头部「回合档位」chip，历史回合当时的档位仍可见；会话级 `GET …/audit?category=permission` 的 `permission.preset_changed` → 聊天主流「权限模式 A → B」系统提示行。原侧栏「安全台账」的写入 / 执行 / 审批清单已下线——文件写入链仍经 ③ 反查，审批为回合内即时交互不再留侧栏清单）；⑤ 运营 `GET /admin/audit/summary` 聚合。**⏳ 手机因果层未落地** → 远期规划 §2.8（详细提案不在公开仓 / 维护者本地）。留存 90 天 TTL sweep（`audit_retention_days` + 日级 sweeper）+ 删对话级联删审计行；审计走 REST 拉取面、不进 SSE conformance fold（`#/preview` 空态兜底）。→ 见代码：`runtime/audit/`（recorder 采集链 / projector 投影 / causal 重建），桌面 `hooks/useTurnAudit.ts` · `stores/permissionChanges.ts` · `components/chat/PermissionChangeLine.tsx` · `sections/RunCausalInject.tsx` · `GraphView.tsx`。

**关键取舍（被否决方案存档）**：① 专表 append-only 而非扩 `turn_journal`（否则污染 fold 回放契约、含 delta 破坏「投影非第二事实源」）；② 独立钩子先 journal 后审计偏序，而非塞 `EventSink.emit` 热路径（阻塞 SSE）；写库改 telemetry 独立池 + 回合内异步投递 + 回合末 flush（不抢正文连接、不阻塞热路径），仍 **best-effort**（未落盘持久化解耦队列——那会「崩溃丢未 flush 事件」，但审计定位不需合规级不丢；对比计费 `proxy_spend` 因涉钱才用 at-least-once 落盘队列，见 [成本配额 §三](/docs/05-平台与运维/成本配额与计费.md)）；③ 数据流只记流向元数据而非全文（避免第三副本、违反最小化）；④ 权限记每 run 生效快照而非仅审批（合规需证明「授权了什么」而非仅「出了什么错」）；⑤ 桌面因果 UI 仅画 inject、否决全量虚线叠加 / 迷你 DAG / ELK 为 inject 重布局 / audit 替换 handoff（→ [前端 UX §五](/docs/04-前端/前端UX设计.md)）。其余议题（受众 / 粒度 / 因果模型 / 查询面 / 留存分级）逐项论证见 git 历史。
