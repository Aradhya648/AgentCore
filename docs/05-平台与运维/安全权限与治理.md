用户间隔离 → [认证与会话 §八](/docs/05-平台与运维/认证与会话.md)。Agent/项目隔离、传输加密、驻留 → ⏳ §九。

## 三、工具审批与开工授权 ✅

**问题**：布尔 `approval_required` → 批量写文件审批疲劳。

**两态**（工具固有属性）：`never`（只读/纯计算）/ `grantable`（局部可控副作用）。原 `always` 已删。`git`/`terminal` schema 可 `NEVER`，写入/start 子命令运行时升格。用户 pty **不设边界**；AI 可读不可停不可写。

**PermissionAxes**（会话单一真相源；用户 AutonomyPolicy 仅种子配方）：

| 轴 | 取值 | 语义 |
|---|---|---|
| `file_write` | `ask` / `session` | 可逆写逐次审 / 会话信任 |
| `command` | `ask` / `kickoff` / `auto` | 不预授执行 / 开工卡授 / 免审执行 |
| `team_kickoff` | `always` / `rules` / `skip` | 总挂组团卡 / 现行跳过规则 / 跳卡 |
| `host` | `off` / `ask` / `session` | 本机 Host 整面关 / GRANTABLE Host（L2+L3+`host_shell`）逐次审 / 会话信任（熔断除外） |

非法：`command=auto` ∧ `file_write=ask`。`host` 与 `command` **正交**：Host 工具**不**挂 `execution_class`，**不**吃开工卡/`command=auto` 静默授。CEO **唯一**可持的 GRANTABLE schema 为 `host_shell`（L2/L3 仍仅 worker）；本地 `terminal` 亦 CEO 可持，但 schema 为 `NEVER`（`start` 运行时升审批）。配方默认 `host`：谨慎=`off`；少打断=`ask`；托管=`session`。`host=off` 只关 Host 面，**不**等价于禁工作区 `terminal`。账户默认入口：桌面对话权限徽章「设为新会话默认」（仅三配方）；自定义轴不可存为用户默认。`ask_user` / `plan_review` / 熔断与敏感读不可被轴覆盖。

**沙箱→审批**：本地 subprocess 需授权；云 gVisor 自动放行；无沙箱不注册。

**熔断（P3）**：毁灭性动作强制审 / `host_shell` 启发式硬拒（格式化磁盘、`rm -rf /`、shutdown 等）及长驻启服命令硬拒（导向 `terminal`）；敏感文件读硬拒——任何模式不可覆盖。启发式黑名单是兜底、非完整边界。

**「本轮内都允许」**：turn 级 · 按类操作 · 整棵 DAG 共享 · 新轮清场。

**开工卡**：`team_preview`∪授权合一；delegate/debate 共用；`team_kickoff=skip` 不弹。被否：永久 allowlist、按 Agent 放行、两卡串联。演进：可回滚写入 → 降为 `never`。

## 五、代码执行沙箱 ✅

云端多租 → 真隔离公测前必做。默认云端**不注册**执行类（`CODE_EXECUTE_CLOUD_ENABLED=false`）；`GVISOR_ENABLED` 灰度。健康探测失败 → 整类不装配（fail-safe 不拒启）。

**产物写回**：staging copy-in/out；超时不写回；删不回传。被替代：ro overlay（产物取不出）。护栏：并发位 + 有界等待 + 内存/时长/写回限额。**不为云执行新增配额维**。部署前置 → [部署拓扑与环境 · 云端执行灰度](/docs/05-平台与运维/部署拓扑与环境.md)。

## 七、凭据加密 ✅

AES-256-GCM；明文永不落库/不回前端。`billing_mode=byok` → 缺密钥生产 fail-closed；`platform` → fail-safe。交叉 → [成本 §〇·五](/docs/05-平台与运维/成本配额与计费.md)。

### 七·a 密钥轮换与 production.env 灾备

> **密钥值不入仓、不入 chat、不入 PR/Issue**。机上真相源 = `deploy/config/production.env`（由 `production.env.example` 复制填值；compose `env_file` 同路径）。根 `$AGENTCORE_HOME/.env` 仅镜像仓库凭据等，**不含** JWT/加密主密钥。模板字段名 → `deploy/config/production.env.example`（`JWT_SECRET_KEY` / `ENCRYPTION_KEY`）。

#### A. `JWT_SECRET_KEY` 轮换

| # | 检查项 |
|---|---|
| 1 | 维护窗口公告：轮换后**全部** access/refresh 失效，用户须重新登录 |
| 2 | 备份当前 `production.env` 到机外安全位置（见 C；**勿**提交 git） |
| 3 | 生成新密钥（长度足够的随机串；勿用示例占位符） |
| 4 | 仅在机上改 `JWT_SECRET_KEY=…`；保存文件权限仅运维可读 |
| 5 | 重启 api（`finish-server.sh <当前 sha>` 或 compose recreate api——**不要**顺手升到未验证 SHA） |
| 6 | 验收：旧 cookie/Bearer → 401；新登录成功；Admin MFA 会话须重新过 MFA（若启用） |

#### B. `ENCRYPTION_KEY` 轮换（高风险）

| # | 检查项 |
|---|---|
| 1 | **先读清**：该键加密用户 BYOK API Key 等落库密文。换键且未先重加密 → 已存凭据**无法解密**（设置页表现为绑 key 失败 / MFA 相关能力异常）。`production.env.example` 亦注明「一经启用切勿随意更换」 |
| 2 | 确认是否有用户 BYOK / 依赖该键的密文；无存量密文时等同首次配置，直接写入新键并重启即可 |
| 3 | **有存量时**（当前无可照抄的一键 migrate 脚本）：维护窗口 → 导出/记录需重绑的用户范围 → 写入新 `ENCRYPTION_KEY` → 重启 → 通知用户重新绑定 API Key（或按维护者私有流程做离线重加密——**过程中密钥仍不入仓**） |
| 4 | `billing_mode=byok` 生产缺键会 fail-closed；`platform` 可启动但 BYOK 功能死——验收模型配置页与 MFA（若用加密存 TOTP） |

#### C. `production.env` 灾备 checklist

| # | 检查项 |
|---|---|
| 1 | 首次上线：自 `production.env.example` 生成机上文件；真实值**只**留在服务器与批准的密钥保管处 |
| 2 | 每次改密钥/LLM Key/CORS 前：拷贝 `production.env` → 加密介质或密钥保管柜（文件名含日期；**禁止**进仓库、Slack、邮件明文） |
| 3 | 机损恢复：新机摆好 compose 布局 → 从保管处回写 `deploy/config/production.env` + 根 `.env`（ACR 凭据）→ `finish-server.sh <已知好 sha>` → `/readyz` + 登录烟测 |
| 4 | 与 DB 备份正交：[发布与门禁 §7.7](/docs/05-平台与运维/发布与门禁.md#77-备份与恢复策略) `backup.sh` 只管 PostgreSQL；**不**替代 env 备份。丢 env ≠ 丢库，但服务起不来 |
| 5 | 泄露应急：视为 A/B 都需轮换 + 轮换上游 LLM Key；审计谁曾接触备份副本 |

镜像/桌面回滚步骤 → [发布与门禁 §7.7a](/docs/05-平台与运维/发布与门禁.md#77a-回滚-runbook可照做)。

## 八、治理边界 ✅

一受众一应用（admin 独立）。管理操作 → append-only `admin_audit_logs`。

**Agent 行为审计**：专表 `agent_audit_events`（投影非第二事实源）；默认仅 delegate 回合；`command=auto`（少打断/托管配方）全回合副作用；审批 force 落盘。telemetry 独立池 + 异步 flush。C 端不设通用时间线——场景化：inject 入边 / 协作图高亮 / 文件反查 / 权限配方 chip。被否：扩 `turn_journal`、热路径 emit、全文副本。未落地尾巴 → 远期（详细提案不在公开仓）。

内容审核首选 **事后治理**；前置过审保留作压力上升时启用。

## 十、已坐实不变量

| 面 | 不变量 |
|---|---|
| 凭据 | AES-GCM；响应仅掩码；prod 拒占位密钥 |
| IDOR | 路由 scoped + 仓储 `user_id` 必填（SEC-002） |
| 注入 | SQL 参数化；`resolve_safe_path`；命令 argv 无 shell |
| SSRF | `core/net.py` + `PinnedIPTransport`；**不**为 dev fake-ip 放宽 |
| CSRF | 仅「有 Bearer 且无 access cookie」豁免 |
| 提示注入 | `<untrusted_content>` 框定工具/网页/文件为数据 |
| XSS / Electron | CSP `script-src 'self'`；`connect-src` 收窄；sandbox + openExternal 白名单 |
| 预览 / 浏览器 | ✅ 统一 BrowserSession：产物完整预览并入右坞壳（桌面 workspace://；Web 下载）。旧 preview 分区非持久、无 preload、Bearer 仅主进程代理（协议参考保留，产品不挂 embed）。Local **外网与 workspace partition 默认按 `conversation_id` 切开**（同对话多 tab 共享；项目共享登录 ⏳）；密码不进模型；用户随时接管；Bridge 仅本机鉴权；缺 `conversationId` fail-closed |
| 沙箱 | cloud 默认关；无 ack 拒启动 |

逐轮 PoC / 回归见 git 历史。整体：零未决 P0/P1。
