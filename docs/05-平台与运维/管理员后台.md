# 管理员后台

> **状态**：P0–P2 后端 `/v1/admin/*` + 独立 web 控制台 `apps/admin` ✅ 已落地。→ 见 §三 模块范围。

面向平台运营者（创始团队）的管理界面。管控**跨用户**的账号与平台（独立于桌面消费端）。

## 一、形态决策：独立 web 控制台（apps/admin）

**决策**：管理后台是**独立 web 应用**（`apps/admin`），**不**塞进桌面端（Electron）。

**为什么（按分量）**：

1. **架构契合**——admin 本质是「`/v1/admin/*` 之上的薄 CRUD 客户端」，不需要桌面端的 sidecar / 本地文件系统 / MCP / inference-token 机制；独立 web 是它最干净的形态。
2. **安全 / 运维**——admin 代码不下发到消费端桌面包；独立访问路径 + 身份门（见 §二）；独立部署不受 Electron 自动更新滞后拖累；爆炸半径隔离。
3. **零浪费**——后端 `/v1/admin/*` 与前端形态无关，是真边界也是稳定面；独立形态不浪费后端工作，也省掉「从桌面端抽离」的迁移。
4. 与 `cross-platform-frontend` 一致——「各端全新建 + 只共享 contract-types / design-tokens」的又一「端」。

**被否**：A 扩「设置 → 成员」页（设置区窄列放表格挤、admin 代码混入消费端）；B 桌面内 `/admin` 路由（同样混入消费端、背桌面壳）。两者安全增益都只是「换个端口」——真安全取决于访问路径，而非源码放哪个目录。

## 二、鉴权 / 访问姿态（决策）

| 维度 | 决策 |
|---|---|
| 真边界 | 后端 cookie 会话 + `AdminUser`（`role==admin`）→ 403；前端只是客户端 |
| 登录 | **独立登录页**，cookie 限定在 admin origin（不复用桌面会话）|
| 网络 | **独立 origin**：管理后台与消费端分离；建议反代/Tunnel 到本机静态端口，并叠加外层身份门（可选）+ 应用内 `AdminUser`（两道互补，外层不替代登录）——见 [`部署与运维.md`](/docs/05-平台与运维/部署与运维.md) §管理后台 |

| CORS | 后端按 admin origin allowlist + credentials |

## 四、后端契约（✅）

`AdminUser` 门控（401 未认证 / 403 非 admin）。

| 端点 | 行为 |
|---|---|
| `GET /v1/admin/overview` | 总览 Dashboard：今日脉搏 + 账号计数 + 近 7 日趋势 + 部署健康 + 近期错误 feed（`trace_id`/`conversation_id` 供下钻）。**纯读侧聚合** |
| `GET /v1/admin/users` | 全量名册，分页 + 子串过滤（`q`）+ 维度筛选（`role` / `status`，AND 组合）+ 排序（`sort` ∈ {`created_at`, `cost`}、`order` ∈ {`asc`, `desc`}，默认注册时间倒序）。**累计成本** `cost` = 账本（`cost_events`）按用户 LEFT JOIN 求和（未花销账号 = 0）；每行带 `cost_total`（nano-USD），响应带 `cny_per_usd` 供前端折 ¥。**注销账号（自助注销、已匿名为 `deleted_<id>`）默认隐藏**，`include_deleted=true` 才纳入（审计用，行带 `deleted_at` 标记）。`total` 随同口径；非法枚举值 → 422 |
| `PATCH /v1/admin/users/{id}` | 部分改 `role` / `status` / 配额。配额**三态**：字段缺省 = 不变 / `null` = 清覆盖回继承全局 / 值 = 设（0 = 该维度不限）|
| `POST /v1/admin/users/{id}/reset-password` | 生成一次性临时密码、改哈希并清锁定，同时**吊销该用户全部 refresh（强制登出所有设备）**；临时密码**仅在响应体返回一次**。复用 `AuthService`，未知用户 → 404 |
| `POST /v1/admin/users/{id}/set-password` | 管理员指定新密码（`new_password` ≥8 位、`force_change` 默认 true）；**不返回明文**（操作者已知）；吊销全部 refresh、清锁定。审计 `user.set_password`（detail 仅记 `force_change`，不落密码）。未知用户 → 404 |
| `DELETE /v1/admin/users/{id}` | 注销账号（用户管理强操作）：软删除 + 匿名化、吊销会话、停用，并**跨域级联**（对话软删 / 分享撤销 / BYOK 删除 / 头像清理）——与自助注销**同一路径**（复用 `cleanup_account_resources`），唯**不验证密码**（admin 门控 + 前端二次确认即意图证明）。**拒绝注销自己**（防自锁）→ 422；未知用户 → 404。账本保留；返回墓碑记录（带 `deleted_at`）|
| `GET /v1/admin/users/{id}/detail` | 用户详情下钻：单账号 + 已配服务商数（`provider_count`）+ 账号默认模型名（`default_model` / `background_model` = 账号默认指针取值，仅名、永不下发 key）+ 本人用量（含 **近 30 日 by-model**，扫 `cost_calls`）+ 最近会话 + 最近回合活动（`turn_metrics`）|
| `GET /v1/admin/usage/summary` | 全站用量看板：跨用户聚合（含 **by-model**）；byok 下为各用户**自带 key** 花费之和 |
| `GET /v1/admin/observability/summary` | 运营观测：回合健康 + 趋势 + 近期错误 feed |
| `GET /v1/admin/observability/conversations/{id}` | 会话复盘：消息 + `turn_metrics` + `cost_events` + `turn_journal` spans/**轻量 runs** **跨源合并时间线**；admin **跨用户**。无正文回合以「裸回合标记」入线；多 Agent 的 `ReplayMessage.runs` 复用 `runs_from_entries`→`project_turn` + `message_final` 全文（非完整 events）；前端按 `run_id` 分组 spans |
| `GET /v1/admin/conversations` | **对话名册 · 会话段**：跨用户分页会话索引。行含 owner、消息/回合/错误/**委派** rollup（`delegated_turns` / `workers`）、累计成本；默认**含软删会话**。筛选：`q`、`user_id`、`has_errors`、`has_delegated`、`since`/`until`；排序：`updated_at` / `created_at` / `cost` / **`delegated`** |

| `PATCH /v1/admin/feedback/{id}/status` | 更新反馈状态（`open` / `acknowledged` / `resolved` / `closed`）并可选写入 `admin_reply` |
| `GET/POST /v1/admin/notices` · `PATCH …/{id}` · `POST …/{id}/publish|archive` | **产品公告**：草稿 CRUD → 发布/归档；字段含 severity / surface(banner\|inbox\|both) / dismiss_policy / 时间窗 / CTA。用户面见下方「产品公告」 |

路由与参数 → 见 OpenAPI / `api/routes/admin/`。

**护栏（service 层）**：admin 不能改**自己**的 `role` / `status`，也**不能注销自己**（防自锁——账号不硬删，唯一通往「零 admin」的路径是最后一个 admin 对自己动手，故此一条即保证恒有 ≥1 active admin）。停用即时生效：被停用账号下次请求 `get_current_user` 复检 `status` → 401（无需吊销令牌）。

**注销账号 = 两入口、同一落点**（防销户路径漂移）：注销 = 软删除 + 匿名化（`deleted_at` 盖戳、`username`→`deleted_<id>`、清邮箱/头像、`status=disabled`；账本不动，不变量①）。

- **两入口**：自助 `DELETE /v1/auth/me`（密码确认）与管理员 `DELETE /v1/admin/users/{id}`（防自锁 + 前端二次确认、无密码）。
- **同一落点**：跨域级联收口在 `api/account_cleanup.py::cleanup_account_resources`（对话软删 / 分享撤销 / BYOK 删除 / 头像清理）；auth 域变更（软删用户行 + 吊销会话）各自在 `AuthService`（`delete_account` 带密码 / `admin_delete_account` 不带）。
- **墓碑账号**：从名册与系统/概览计数（`total`/`active`/`admins`）**默认剔除**，仅 `include_deleted` 审计视图可见、按只读墓碑渲染。

**P1/P2 复用既有聚合与基建，不另起炉灶**：跨用户口径复用 `CostEventRepository` 的窗口聚合（去 user 过滤 + 新增 by-user 聚合，join `users` 取展示名）；账本→cost/usage schema 的映射抽到 `api/cost_view.py`，与 `/v1/usage/summary` **共用一份**（账本已定价，只读不重算）；DB 探活、版本各下沉**单一源**（`/readyz`、`/version` 均与 `system` 同源）。

**运营观测的数据源 = `turn_metrics` 表（DB），不是日志文件**：

- **为何不用日志**：AI 运行时日志（`logs/dev.jsonl`）是给 dev/cursor 排查的 firehose，生产默认仅 stdout（`settings.log_file` 缺省空）、只追加无索引、不含正文——不适合在线给 admin 查。
- **落点**：回合持久化尾（`conversation/turn_persistence.py::persist_turn_result`，即 `chat.turn_complete` / `chat.resume_complete` 完成路径的收口，与 `cost_events` 落账同一处）**best-effort 落一行 `turn_metrics`**（同成本落账铁律：遥测写失败绝不炸用户回合），写入回合已算好的结果/质量（status / finish_reason / rounds / duration / delegated / workers / tokens），看板用带索引 SQL 聚合。
- **三源可拼**：钱在 `cost_events`、正文在 `messages`，均以 `trace_id` 与 `turn_metrics` join（遥测行不重复存钱/正文）。

**协作质量 · MAST 看板（多 Agent「学·度量」的在线半）✅ 已落地**：把「协作好不好」变成能数的几样，按 **MAST**（Multi-Agent System Failure Taxonomy，14 类 / 三组：规格不达 / 互相错位 / 验证缺位）打标——别自创词表。

- **在线四列**：`turn_metrics` 加 `boundary_yields` / `scope_signals` / `revises`（＝带现场续派次数，CEO `continue_from_run_id` + redirect 热修，不计辩论）/ `escalations`（经 delegate 工具上卷、`chat.turn_complete` 日志），健康窗口算 **`first_plan_survival_rate`**（首版计划多少撑到底——直接量「太依赖第一次编排」这个痛点，也是 lead B 铺开值不值得的主证据）；前端落「分析·健康」的「协作质量 · MAST」卡片。
- **离线对照**：`scripts/log_stats.py` 按 `trace_id` 纯读现成日志算同样四样（返工率 / 首计划存活 / 漂移率 / 空转·早收），与在线同义（prod 是 stdout-only 日志姿态、可能不写 `logs/dev.jsonl`，故双面）。「空转·早收」读现成 `finish_reason`、不新增列。
- **评测半（共线）**：MAST 标签化离线评测集（`agentcore/evals/mast.py` 14 类 + `cases/mast/` 多 Agent 用例 + report `mast_breakdown`，已接入 `evals-nightly.yml`）需真模型回合才出 pass_rate——与 远期规划 §2.4（详细提案不在公开仓 / 维护者本地）「提示词优化」共用「真跑评测」主线，前置 `EVAL_DEEPSEEK_API_KEY` + 裁判 gold-set 同见该节。

→ 见代码：`apps/server/scripts/log_stats.py`、`agentcore/evals/`（`mast.py` / `report.py`）、`turn_metrics` 仓储 + `admin/service.py`（健康窗口）。

**tool/LLM span 级明细复用 `turn_journal` 投影，不另起 `span_metrics` 表**：

- **复用 journal**：span 事实（`llm_call` / `tool_call` …）**早已落 Postgres**（`turn_journal`，回放/续写唯一事实源，按 `turn_id`=assistant msg id），故会话复盘的「执行明细」是对它的**读侧投影**（`load_map` 批量 + 压缩成 triage 用的 `ReplaySpan`，丢掉系统提示/完整结果等重负载），零新表零迁移。
- **多 Agent runs**：同 journal 经既有显示投影（`runs_from_entries` → `project_turn`）折出轻量 `ReplayRun`（run_id / agent / task / 树边 / status / debrief / `message_final` 全文），**不**下发完整 `RunsPayload.events`；admin 用轻量树/泳道列表排障，禁止搬入桌面协作图画布。
- **系统提示各取所需**：admin 投影丢掉的系统提示由**用户向**「收到的上下文」补上——captain 的 `system` 块（`run_context` 投影、与喂 LLM 同源）随 CEO 气泡**按需弹窗**对**本人**展示（详见 [`../03-AI核心/上下文传递可视化.md`](/docs/03-AI核心/上下文传递可视化.md)）；作用域区别：admin 跨用户只读、用户向限 owner+会话。per-agent 花销/耗时已在 `cost_events` 可聚合。
- **为何暂不立表（YAGNI）**：唯一会让 `span_metrics` 扁平表成立的是「跨回合 span 聚合」（工具/模型健康看板：工具 X 的 p95、按模型错误率——对 `turn_journal` 的 JSONB 全扫不可扩展，同 turn_metrics vs 日志的理由），该需求尚未提出。per-span 延迟当前未可靠落账（执行事实多无 ts），需要时给 `ToolCallFact`/`LlmCallFact` 补 ts/duration 即可，非新表。

→ 见代码 `api/routes/admin/`、`admin/service.py`、`api/cost_view.py`。配额维度语义见 [`成本配额与计费.md`](/docs/05-平台与运维/成本配额与计费.md)。

### 产品公告（全局 Notice）✅

面向**已登录用户**的可配置运营提示（维护、故障、额度/政策、小功能上线），**不是** IM 群内管理员公告，也**不是**协作 Toast / 站立任务收件箱。

| 决策 | 选择 | 理由 |
|---|---|---|
| 内容模型 | 一条 Notice → 多 surface（`banner` / `inbox` / `both`） | 运营配一次，客户端按面渲染 |
| 消费表面 | 顶栏 Banner（≤1，紧急/维护）+ IM「AgentCore 官方」会话（inbox） | 对标服务号/工作通知；More「公告」已撤 |
| IM 接线 | 首次 `publish` 且 `surface∈{inbox,both}` → 官方会话 1 条共享 `system_card`（`kind=product_notice`） | Notice 仍是运营真相源；全员共享一条；归档不删 IM；历史不回填 |
| 谁发 | 仅平台 `AdminUser` | 全站广播；租户级公告未做 |
| dismiss | Banner：`product_notice_dismissals`（`once` / `never`）；官方号：IM 已读 | 维护类 Banner 可用 `never` |
| 投放 | Banner：桌面软轮询 `GET /v1/notices/active`；inbox：publish 写官方号 + `chat_message` firehose | IM 走现有实时通道 |

用户 API：`GET /v1/notices/active`、`POST /v1/notices/{id}/dismiss`（`never`→409）。桌面：`ProductNoticeBanner` + 消息页官方号；`#/more/notices` 重定向官方会话。Admin：`/notices`。

→ 见代码 `api/routes/notices.py`、`api/routes/admin/notices.py`、`db/models/notices.py`、`messaging/service.py`（`publish_product_notice`）；会话形态 → [消息 IM §七](/docs/05-平台与运维/消息IM.md)

## 五、前端（apps/admin, ✅）

独立 web 应用：**独立登录页**，cookie 限定在 admin origin（**不复用桌面会话**）。侧栏页（概览 / 用户 / **对话** / 分析 / 审计 / **公告** / 系统）由 `AdminShell` + **URL 路由**（`react-router`）切换；用户详情（`/users/:id`）、会话复盘（`/replay/:id`）为可书签深链，默认落「概览」。邀请码页已下线（注册开放后不再需要运营发码）。

**信息架构（去重为纲：每个明细事实只在一个页存在一次）**：

- **概览** = 枢纽：今日脉搏 4 个 KPI tile（点即深链：活跃用户→用户 / 回合·错误率→分析·健康 / 成本→分析·成本 / P95→分析·健康）+ 部署健康灯带（数据库 / 计费模式，点→系统）+ 近期错误 preview（5 行，点行下钻会话复盘，「查看全部」→分析·健康）。**不重渲染明细**——`/overview` 仍含 7 日数组，但趋势图只在「分析」渲染。
- **对话** = 全站 AI 对话记录的**唯一索引归属**：顶部分段 `会话 | 回合` + **conversation_id / trace_id 直达复盘**框。**会话段** = 分页名册（用户 / 标题 / 消息·回合·错误 / **多 Agent 徽章** / **委派列可排序** / 成本 / 更新时间；标题搜索、`user_id`、仅有错误、**仅多 Agent**、`since`/`until`、按更新/创建/成本/**委派**排序；默认含软删会话与用户注销标记）。**回合段** = `turn_metrics` 流水（含 `trace_id` 列可点复制，对照 `logs/dev.jsonl`；**多 Agent 徽章** + **仅多 Agent** 筛选）；按状态与时间筛选。两段行点击均下钻 **会话复盘**（`/replay/:id`，回合行带 `?trace=` 锚点）。复盘宽屏 ≈ 左回合目录 | 中时间线（含队员交付全文块）| 右协作树 + 按 run 分组执行明细；**中栏交付块 ↔ 右侧树/执行组双向高亮联动**；窄屏 Tab；支持 `?trace=` / `?turn=` 高亮。页头 `conversation_id` 与消息旁 `trace_id` 均可点复制。用户详情「最近会话」「最近活动」各保留 15/20 条 preview +「查看全部」深链到此页（带 `user_id`）。观测总览「近期错误」的 `trace_id` 亦可点复制。
- **分析** = 用量 + 观测合并（两者同构：窗口卡 + 7 日趋势 + 表 + 会话复盘下钻，仅指标不同），顶部 `成本 | 健康` 分段切换，右侧常驻「会话 ID 复盘」框；**仅当前段拉取**对应接口（`/usage/summary` / `/observability/summary`），不一次拉两份。成本段含 **by-model**（`cost_calls`）。
- **用户 / 审计 / 系统**：
  - **用户**：名册（顶部按 角色 / 状态 下拉筛选 + 用户名/昵称搜索，「注册时间」「累计成本」列头可点排序；行展示账号 + 配额 + 累计成本（¥））；详情下钻（配置对话/后台模型名、近 30 日 by-model），详情页「设置密码」→ 输入新密码 + 可选「要求用户首次登录后修改密码」→ 确认（登出所有设备）；「重置密码」→ 确认 → 一次性临时密码弹窗（仅展示一次 + 复制）；行内「注销」→ 二次确认（说明匿名化 / 登出 / 级联清理、不可恢复）→ 默认视图移除该行、审计视图回填墓碑；「显示已注销」开关切审计视图（注销行以「已注销」徽标 + 只读墓碑呈现）。详情「最近会话 / 最近活动」→ **对话**页深链。
  - **审计**：管理员特权操作记录（改用户 / 重置密码 / **设置密码** / 注销；历史邀请码操作仍可能出现在旧记录），分页 + 按操作类型筛选。
  - **系统**：部署只读快照；账号计数的唯一家在此。紧急关闸注册见环境变量 `REGISTRATION_OPEN`（[`认证与会话.md`](/docs/05-平台与运维/认证与会话.md)），不在此页做产品开关。
  - **公告**：产品全局 Notice 的唯一运营入口（列表 / 草稿编辑 / 发布 / 归档）；消费端在桌面壳，不在此渲染。

→ 见代码 `apps/admin/src/pages/`（`OverviewPage` / `UsersPage` / `ConversationsPage` / `AnalyticsPage` / `AuditPage` / `NoticesPage` / `SystemPage` / `ReplayPage`）、`apps/admin/README.md`

**按模型聚合口径**：admin by-model（用户详情 `recent_by_model`、全站 `month_by_model`）**必须**扫 `cost_calls`（`GROUP BY model`）。禁止用 `cost_events.model`——该列只记 run 首次 call 的模型，多模型 run 会错分。
