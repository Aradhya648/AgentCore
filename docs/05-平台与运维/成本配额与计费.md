## 〇、为什么成本是产品而非基建

AgentCore 是 multi-agent，一条用户消息 = CEO + N 个委派 worker，**花销天然能按 Agent/角色拆开**——这是单 Agent 竞品（Cursor/Codex/Claude）做不到的「团队工资单」。别人只能说「这次花了 ¥X」；AgentCore 能说「CEO ¥0.03 / 调研员 ¥0.05 / 写作 ¥0.04」。所以用量可观测是**产品差异点**，台账的 per-run 聚合视图（由 per-call 明细推导）正是为这个差异点服务。（✅ run 级 ¥ 可拆（`agent_id`）；✅ 人设级拆账：明细/聚合行携带 `persona`/`role`，**单回合**工资单与 `cost.recorded` 的 `by_role` 按角色呈现；账户仪表盘只给窗口总额 / 额度 / 趋势，**不再**做月维度按角色看板。）

## 〇·五、计费模式：BYOK 默认 + 每月免费额度 fallback（✅ 已落地）

内测期默认 **BYOK（bring-your-own-key）**：每个用户在「设置·模型配置」自备 **OpenAI 兼容服务商列表**（✅ 2026-07-20 多服务商：`user_llm_providers` 每行 label + `api_key` + `base_url` + 该服务商默认模型，可同时配多家；账号级 chat/后台默认各一对 `(provider_id, model)` 指针），每条对话跑在用户自己的上游额度上。计费路由是 **per-turn 按所选模型的 origin**（✅ 2026-07-20 统一模型目录）：本回合解析出的 `(model, origin)`（会话覆盖或账号默认）决定走用户 key 还是平台 key——原 per-user `users.billing_preference` 列、`PUT /users/me/llm-key/billing-preference` 端点、设置页「模型来源」二分**均已退役**（用户不再预选来源，聊天框 `ModelPicker` 里选平台行 = 平台计费、选 BYOK 行 = 自担费用；行业对齐见 [`平台LLM接入.md` §二](/docs/05-平台与运维/平台LLM接入.md)）。部署级 `config.billing_mode` 保留：作限额组选择（D7）与部署形态开关，不再作注册默认。

**为什么禁用而非删除平台付费**：平台付费整套（全局 key fallback + 配额防线 + 成本账本）是带 DB 列、带防线逻辑的资产；删了再加要跑破坏性迁移 + 反向重建 + 重测一整套计费。故**全部保留**——免费额度（下）正是靠这套资产直接开启。

**一道闸门收口（不撒补丁）**：所有用户向 LLM 调用（云回合 / file assist / sidecar 推理代理）共用 `billing/gate.py::preflight_llm_credentials(model_origin=…)`，按**本回合所选模型的 origin** 分支：

- `origin=byok`：按本回合解析出的 `provider_id` 解密**该服务商**凭据（`resolve_user_llm_credentials(provider_id=…)`，fail-safe 永不抛；pinned 服务商已删/不可解密 → 回落账号默认服务商）→ 有凭据直接返回（**不查配额**）；一个服务商都没有 → `BYOKKeyMissingError` → **402 `LLM_KEY_REQUIRED`**（正常到不了：resolve 对服务商已删的 byok 覆盖会先静默回落账号默认）。
- `origin=platform`（显式选平台行，或无 key 用户的账号默认/免费档 fallback）：平台凭据缺失 → 503 `PLATFORM_BILLING_UNAVAILABLE`；否则过 §一 `enforce_quota`（byok 部署下用 `free_tier_*` 限额组，D7）后用平台 key。

**计费语义（call 级凭据来源，✅ 取代部署级开关算价）**：`calculate_cost` 按**本次 call 实际用的凭据来源**算价、不读全局 `settings.billing_mode`（`llm/pricing.py::resolve_credential_source`，来源标记在凭据/Provider 构造处打上并贯穿 `log_llm_call` / call meter / `_record_proxy_spend`）：

- **用户 BYOK key** → **记账恒 0**（用户自担上游账单，`cost_total_nano=0`），token 照常记入；✅ 另按两层价卡出一笔**估算金额**落 `cost_estimated_nano`（展示用，见下「BYOK 估算可见性」），估算永不进配额 SUM 与平台记账；
- **平台主 key**（偏好 platform / 免费档 fallback / 后台档平台优先路径）→ 真实算价入账；
- **厂商 extras key**（`doubao/` 等 `.env` 多厂商 key，恒平台的钱）→ 真实算价入账。

**BYOK 估算可见性（✅ 2026-07-15 落地；自填单价层已移除）**：BYOK 用户此前 ¥ 恒显「—」（平台无权威单价，硬算误导）——现为**诚实估算**：两层价卡 `resolve_price_card`（`llm/pricing.py`）按 `estimated`（仓库内社区价目快照 `llm/pricing_data/community_prices.json`，`scripts/sync_community_prices.py` 手动同步自 LiteLLM，运行时零网络请求、模型名仅精确匹配不模糊猜）→ `unpriced`（没有 = 不出数，**绝不回落 Flash 价**——user 路径乱猜比不猜危险）。`Cost.pricing_source` 全链路贯穿（台账 JSONB / SSE / REST），前端以「≈¥ + 估算」标注展示，与记账 ¥ 视觉隔离。platform/vendor 路径不变：curated 价卡 → 社区表 → Flash 回落 + `cost.pricing_fallback` warning（配额防线宁偏勿空）。

**后台场景降档（✅ 2026-07-15，多服务商升级 2026-07-20；平台优先 ✅ 2026-07-25；auth 回落 ✅ 2026-07-31）**：`title` / `memory` / `compaction` / `followups` **平台凭据优先**。模型：`platform_background_model` → `platform_model`；仅平台不可用时回落账号后台指针 / chat 服务商。「平台不可用」含：配置缺失 **或** 上游 auth 拒绝后经 `run_background_llm` **一次**回落用户 BYOK（禁止各调用点自拼 try/except，禁止进程内 auth 熔断缓存）。

> 为什么不是 turn 级标记：同一 turn 可混用用户 key / 平台主 key / 厂商 extras key（多模型辩手），turn 级盖不住；维持全局开关算价则月成本帽形同虚设（平台代付 call 记 0）。

**后台调用平台优先 + 过配额（✅ 2026-07-25；auth 回落 ✅ 2026-07-31）**：`resolve_model_config` 后台 purpose 先平台；`resolve_and_gate_background` 对 `source=platform` **一律 `enforce_quota`**（有 BYOK key 也不跳闸，防白嫖）。配额耗尽 → `None`，铸题截断降级 / 记忆·压缩跳过，不 429 主回合。调用统一走 `billing/gate.py::run_background_llm`（platform-first → 遇 `LLMAuthError` 且当前 source=platform 则一次 user BYOK 再跑）。→ 见 [`平台LLM接入.md` §二](/docs/05-平台与运维/平台LLM接入.md)。

**服务商管理面（✅ 2026-07-20 多服务商，硬切换取代单 key 面）**：`/users/me/llm-providers`——GET 列表（含账号默认指针 + 部署级字段）/ POST 新增（首个自动成 chat 默认）/ PATCH `/{id}`（省略 `api_key` 保留密文）/ DELETE `/{id}` / `POST /{id}/test`（连通性与 `supports_tools` 各测各的）/ `PUT /defaults`（设账号 chat/后台指针）。原 `/users/me/llm-key` 单例接口已删（内测期强更拍板，无兼容层）。AES-256-GCM 加密落库，明文永不落盘，算法与 fail-closed/fail-safe 决策见 [`安全权限与治理.md` §七](/docs/05-平台与运维/安全权限与治理.md)。`free_tier_active`（该用户无任何服务商 ∧ 免费档开启 ∧ 平台凭据可用）随列表响应顶层下发——前端免费档信号**挂既有端点**，不造第二个状态源。

→ 见代码 `billing/gate.py`、`billing/preference.py`、`llm/resolve.py`、`llm/provider_service.py`、`llm/pricing.py`、`api/routes/llm_providers.py`

### 每月免费额度（平台代付免费档）

> 注册即可用「**每月 ¥1**」的平台代付额度跑真实回合（上游 DeepSeek Flash），额度耗尽引导接入自己的 key；配了 key 的用户一切照旧。动机：激活漏斗的头号摩擦是 BYOK 下发首条消息前必须先去厂商申请 key——免费档让「注册 → 亲眼看到团队分工协作」缩短到 30 秒；额度耗尽的 429 是天然的 BYOK 转化点；UTC 月初重置是回访钩子。对外文案诚实表述为「每月 ¥1 免费额度」，不说「送你 1 元」。

关键决策（2026-07-13 拍板，含被否方案）：

| # | 决策 | 被否方案 + 理由 |
|---|---|---|
| D1 | 额度语义 = **每月 ¥1 免费档**：复用月成本配额维，UTC 自然月重置 | 一次性赠送金（credit 账本）——商业模式未定，不为其预建新表/新 enforce 分支 |
| D2 | 覆盖**所有无 key 用户**；fallback 挂既有机制 | 「新用户」判定 / 「废除选择只按有无 key」——分叉或丢选择。后记：`billing_preference` 已退役，选择下沉 per-turn origin，免费档 fallback 语义保留 |
| D5 | 耗尽 429 → **`FREE_TIER_EXHAUSTED`** + CTA 直达模型配置；信号挂 `GET /users/me/llm-providers` 顶层 | 独立「免费档状态」端点——双源必漂移 |
| D7 | 免费档专用 `free_tier_*`（见 §一）；全局 `quota_*` 留给 `billing_mode=platform` | 直接改小全局默认——波及存量与全员代付 |

**开关**：`PLATFORM_FREE_TIER_ENABLED`（默认 false）；回滚 = 关开关（「逐字节旧行为」前提是未配平台/厂商 key——配了则 call 级算价从记 0 变真入账，属修 bug）。**sidecar**：代理 **per-call** enforce（可中途拒）；云回合仍「回合前一次」；超额一律 **429**。

**敞口（推算，无真实数据）**：典型多 Agent 回合 ≈ ¥0.03，¥1 ≈ 30 回合；单日靠 `free_tier_daily_tokens=200k` 压敞口；月最坏 ≈ ¥2.5–4/用户（已拍板接受）。防滥用复用既有限流 / 关闸 / admin 停用，不新开面。明确不做 credit 账本与首版手机免费档 parity。

→ 单测 `tests/test_free_tier.py`；探针 `scripts/probe_free_tier.py`

## 〇·六、内测计费翻转：平台额度默认 + BYOK 高级选项（✅ 2026-07-20 拍板落地 · 2026-07-21 生产全量上线）

> 内测主姿势从「BYOK 默认 + 每月 ¥1 免费档钩子」翻转为「**平台额度默认（每月 ¥1000）+ BYOK 高级选项**」。动机：BYOK 默认是开发者向姿势，与「面向大众」定位错位（申请 key 是激活头号摩擦）；行业常规（Cursor / Devin / Manus / Qoder）一律平台代付 + 统一额度制；平台代付路径现金敞口由运营配置约束，风险主项从「用户自备 key」转为「平台配额与上游限速」。

| # | 决策 | 内容与被否方案 |
|---|---|---|
| F1 | 部署形态 = `billing_mode=platform` | 全员代付、`quota_*` 限额组、耗尽走 `QUOTA_EXCEEDED` 等重置语义（与目标文案天然一致）。被否：维持 byok + 把 `free_tier_*` 扩到 ¥1000——免费档整套转化语义（文案 / CTA / `FREE_TIER_EXHAUSTED`）与「主用量」拧巴，翻文案不如翻形态。free_tier 资产**原样休眠保留**（byok 部署形态仍用，回滚 = 改回 .env） |
| F2 | 额度数值（内测起步值） | 月成本 **¥1000**（内部 ≈$139，UTC 自然月、不结转）+ **新增「日成本」配额维 ≈¥100/日**（防单日打爆 / 脚本失控）+ 日请求 500；日 token 维置 0 退出值守——多模型目录下单价差 ~30×，token 帽映射不了钱。admin 每用户覆盖 / `is_unlimited` 提额机制不变 |

| F6 | 耗尽行为 | 主文案：本月额度用完、下月 1 日（UTC）重置、测试需要可联系管理员提额；**次级弱化出口**「或接入自己的 key 继续」（挂设置·模型配置）。免费档转化语境文案随翻转退役 |
| F7 | BYOK 降级为高级选项 | 目录默认只列平台行；配 key 用户目录才出现「自己的端点」分组（标注自担费用）；无 key 用户不再显示置灰引导行（guide rows 在平台目录可用时退役）。BYOK 机制（key 管理 / 发现 / 估算价卡 / byok 回合不查配额）全部保留；已配 key 用户账号默认仍 byok（resolve 语义不变，可手选平台行）——「有 key 用户零变化」承诺延续 |

**as-built（2026-07-20 落地）**：`PLATFORM_MODELS` allowlist（`config/platform.py` + `billing/preference.py::platform_model_allowlist`，空 = 回退单 `platform_model`，byok / 免费档部署零变化）+ **每模型凭据覆盖** `PLATFORM_MODEL_CREDENTIALS`（`config/platform.py::parse_platform_model_credentials` → 单点 `llm/resolve.py::platform_llm_credentials(model)`，云管线 / sidecar / 后台档三调用点按本回合模型解析，`is_platform_available` 视覆盖 key 亦为可用；名义价卡已补 `5.2`（gpt-4o 档）/`grok-4.5`（community grok-3 档），运营可调）→ 目录 `llm/catalog.py`（平台目录可用时 keyless 只见平台行、guide rows 退役；缺 curated 价卡打 `platform_catalog.pricing_missing` warning）；「日成本」第四配额维（`quota_daily_cost_usd` / `free_tier_daily_cost_usd=0` 不回归 + 每用户覆盖列 `users.quota_daily_cost_usd`，enforce 复用当日聚合零额外查询）；F6 文案在 `conversation/quota.py`（单一来源），前端 `QUOTA_EXCEEDED` 补「接入自己的 Key」次级 CTA；契约 `QuotaStatus.daily_cost_nano` 贯穿 usage / admin。→ 单测 `tests/test_quota.py`、`tests/test_model_catalog.py`、`tests/test_platform_model_credentials.py`（per-model 凭据解析）；验收：后端 pytest 全绿 + `pnpm conformance` 双端 100/100 + 渲染冒烟。

## 一、三层防线

三层正交：限流挡「刷得太快」，配额挡「用得太多」，计费只忠实记录、不拦截。

| 层 | 位置 | 管什么 | 失败行为 | 现状 |
|---|---|---|---|---|
| **限流** | 路由层（按用户）+ 中间件（按 IP） | **速率**——单位时间内的请求次数 | 超额拒绝（429 + `Retry-After`） | ✅ 已落地（默认内存单进程；`RATE_LIMIT_BACKEND=redis` 切多 worker 安全的 Redis ZSET 滑窗，含请求级 fail-open） |
| **配额** | 业务层（回合开始前） | **总量**——日 token / 月成本 / **日成本** / 日请求数 | 超额拒绝下一回合（429） | ✅ 强制已落地（含每用户覆盖 + admin `is_unlimited`） |
| **计费** | Finalize（append-only） | **记账**——每个 Run 的真实成本 | 失败 warning + 入落盘队列后台重试，不中断回合 | ✅ 已落地（详见 §三、§四） |

### 限流（速率防线，✅ 已落地）

两个互补的限流器（默认内存、单进程；配 `RATE_LIMIT_BACKEND=redis` 即切 Redis ZSET 滑窗，多 worker 安全）：

- **按用户限流**（✅ 路由层滑窗）：在消息发送 / 重新生成端点按已认证用户限频，挡单账号刷回合。因按用户需已认证主体，落在**路由层**（紧邻 `enforce_quota`）而非中间件；用**滑窗**（非固定窗口）避免边界 2x 突发；被拦的请求不记账。超额抛 `RateLimitedError` → 429 `RATE_LIMITED` + `Retry-After`。→ 见代码 `conversation/rate_limit.py`、`middleware/rate_limit.py`
- **按 IP 限认证端点**（✅ 中间件固定窗口）：限登录/注册/刷新端点（默认 10 次/60s），挡撞库；非 auth 路径与未登录请求放行。→ 见代码 `middleware/rate_limit.py::AuthRateLimitMiddleware`

回合开始前三道闸顺序：**限流（按用户）→ 所有权 → 配额**——限流最外，未过则不做资源级 DB 查询。

前端如何呈现「被拒回合」见 [`../04-前端/前端成本呈现.md` §7.6](/docs/04-前端/前端成本呈现.md)。

✅ 多 worker：`RATE_LIMIT_BACKEND=redis` 经 `RateLimiter` protocol 缝切到 Redis ZSET 滑窗（`RedisSlidingWindowRateLimiter`）/ auth 固定窗（`RedisFixedWindowRateLimiter`），调用点零改动。✅ **请求级 fail-open**：Redis 请求期报错→放行（fail-open）并记 `rate_limit.redis_fail_open`（warning，可告警）；只放松「速率」防线，DB 支撑的「总量」配额防线不经 Redis、不受影响；工厂构造期不可达仍回落内存。→ 见代码 `middleware/redis_rate_limit.py`

### 配额（总量防线，✅ 强制已落地）

> 此防线管**平台代付路径**：`billing_mode=platform` 全员代付，以及 byok 部署下的免费档 fallback / 显式偏好 platform（§〇·五）。**BYOK 有 key 用户不查配额**（用户自担上游账单）——这是**既定姿态而非缺口**（拍板 2026-07-20）：配额的产品目的是保护平台出资，平台替用户限制「花自己的钱」无正当性；BYOK 记账恒 0（估算走展示列，§〇·五）使金额口径配额天然不覆盖它属**设计使然**，勿当 bug 修。「Agent 失控烧用户上游账单」的保护由另一道闸承担：per-worker token 硬顶 / 墙钟超时（[执行引擎 · 收敛治理表](/docs/03-AI核心/执行引擎架构设计.md)）+ 用户显式停止。若未来要给 BYOK 加兜底，正确形态是 **token 口径**日上限（新需求，另案），不是把估算金额混进金额配额。

| 决策 | 内容 |
|---|---|
| 检查时机 | 回合开始前（`enforce_quota`），超额 → 429，不腰斩进行中回合（sidecar 推理代理例外：per-call enforce，可中途拒，见 §〇·五）；免费档路径超额抛 `FREE_TIER_EXHAUSTED`（转化 CTA），其余维持 `QUOTA_EXCEEDED`（等窗口重置） |
| 四维度 | 日 token / 月成本（USD）/ **日成本（USD）** / 日请求数；**0 = 该维度不限**。两组默认（D7 / F2，`config/quota.py`）：全局 `quota_*`（platform 全员代付）= **日 token 0（退出值守）· 月成本 ≈$138.89（¥1000）· 日成本 ≈$13.89（¥100）· 日请求 500**；免费档 `free_tier_*`（byok 部署的平台代付路径）= **200k token/日 · $0.14/月（≈¥1）· 日成本 0（不限）· 50 请求/日**。**为何用日成本兜底**（F2）：多模型目录单价差 ~30×，日 token 帽映射不了钱，故 platform 部署把日 token 置 0、改由日成本维防单日打爆 / 脚本失控；免费档仍靠日 token 压单日敞口（日成本维 0 保持 byok 行为字节一致） |
| 每用户覆盖 | `users` 表 `is_unlimited` + 四维度覆盖（NULL=继承所选默认组；含 `quota_daily_cost_usd`）；`scripts/set_quota.py` 或 admin API（`PATCH /v1/admin/users/{id}`，见 [`管理员后台.md`](/docs/05-平台与运维/管理员后台.md)）设置——覆盖列最优先，admin 特批机制不变 |

→ 见代码 `conversation/quota.py`（`QuotaLimits.for_user`）、`billing/gate.py`

### 计费记账（✅ 已落地）

每个 **LLM call** 落一行 `cost_calls`（权威明细）；每个 **Run** 在 `cost_events` 有一行物化聚合（产品面工资单 / 仪表盘 / 配额 SUM 读这里）。云回合 finalize 双写聚合；sidecar 经云代理按 call 记明细并物化聚合。详见 §三/§四。

## 二、用量/成本不变量

token 与成本在系统中有多种形态（SSE wire、持久化、API 响应、计费台账），下列不变量保证不会算出两套数、也不会跨用户串账：

1. **唯一原始来源**：单次 LLM 调用的原始 `TokenUsage` **5 字段**（`input / output / reasoning / cache_hit / cache_miss`；`total` 为派生属性），所有用量从它累加。→ 见代码 `llm/provider/protocol.py::TokenUsage`
2. **唯一定价转换**：全系统唯一的 `calculate_cost(model, usage)` 把 token 折成钱（`input / cached / output` 三价分离，缓存命中按 ~50× 更低价计），任何地方要成本一律调它，绝不另算单价。钱一律**整数 nano-USD**（1 USD = 10⁹），杜绝浮点。**按 call 级凭据来源定价**（`resolve_credential_source`，不读部署级 `billing_mode`）+ **两层价卡**（`resolve_price_card`）：来源 `user` → 社区估算表 → unpriced（记账恒 0，估算走 `cost_estimated_nano` 展示列，见 §〇·五）；`platform` / `vendor`（厂商 extras）→ curated 价目表 → 社区表 → Flash 回落。`Cost.pricing_source`（curated / estimated / unpriced）随钱贯穿到台账与 wire。→ 见代码 `llm/pricing.py`
   - **记账与估算永分离**：`enforce_quota` 月成本、admin 全站统计只 SUM `cost_total_nano`；`cost_estimated_nano` 是纯展示列（BYOK 工资单/仪表盘），两列互斥非零（`_split_cost`，`runtime/costing.py`）。
   - **缓存拆分对账**：输入费按 `cache_hit/cache_miss` 拆价。解析层（`TokenUsage.from_openai_wire`，网关 / 推理代理 / 视觉读图共用）兼容两种线上方言：DeepSeek 显式拆分（`prompt_cache_{hit,miss}_tokens`，优先）与 OpenAI 风格 `prompt_tokens_details.cached_tokens`（hit=cached、miss=prompt−cached 推导）——否则 OpenAI 方言上游的缓存命中恒报 0，平台价卡（如 gpt-4o）把命中全额按 miss 计价、账单虚高。两种方言都缺时，计价层仍按 `cache_miss = max(input_tokens − cache_hit, cache_miss)` 对账——原生路径（`hit+miss==prompt`）恒等无副作用，缺拆分时整段 prompt 按 miss 计，保证「被计价的输入 == prompt」永不落空。
   - **回落可观测**：未知/未配置 `model` 回落最便宜的 Flash 价（缺价绝不腰斩回合），但可能把 Pro 回合低估约 3×，故回落时打 `cost.pricing_fallback`（warning）而非静默，便于从日志发现漏价。

**真正的钱以 `cost_events` 台账为准**（不变量 #1）；`Message.usage` / `runs` 里的成本只是展示快照。新增任何成本展示点 → 复用统一定价函数，勿手算单价。

3. **会话归属不在写路径校验**：`cost_events.conversation_id` **无**指向 `conversations` 的 FK；推理代理写入不查「该会话是否属当前用户」。读侧一律按 `(user_id, conversation_id)` 收敛（`user_id` 来自鉴权令牌）→ **无跨用户泄漏**；伪造/错挂 id 至多把本人花销记到本人账本里无权的会话上。热路径不加归属 DB 查是有意取舍。→ 见代码 `api/routes/inference/proxy.py`（写头注释）、`db/models/billing.py`

## 三、台账：per-call 明细 + per-run 聚合（✅ 已落地）

| 决策 | 内容 |
|---|---|
| 粒度（②） | **per-call 明细（`cost_calls`，权威）+ per-run 物化聚合（`cost_events`）**。云回合与 sidecar（经云推理代理）同构：代理侧按 call 记明细并按 `run_id` 物化聚合；云 in-process 经 `log_llm_call` → call meter 入明细并 **同步物化**（`materialize_runs=True`），turn finalize 再按 `message_id` 从 `cost_calls` 对账 upsert（补齐 pause/resume / 协调波次下内存 `cost_runs` 漏折的 worker），vision 等仅在 `cost_runs` 的孤儿行再 `record_runs`。明细携带 `role`（结构桶）+ `persona`（人设标签，如「调研员」）+ `run_id`/`agent_id`/`parent_run_id` |
| 货币（①） | 整数 nano-USD；冗余 `cost_total_nano`（记账）与 `cost_estimated_nano`（BYOK 估算，展示专用）双标量列供窗口 SUM，两列互斥非零 |
| 幂等 | 明细 `call_id` unique；聚合 `run_id` unique（finalize DO NOTHING；代理物化 DO UPDATE） |
| 写入时机 | 每成功 LLM call → 明细；turn finalize / handoff / **incomplete 收口**（`/stop` · sweeper · process_kill → `close_turn_interrupted`）/ 代理物化 → 聚合；与 assistant message 共享 `message_id`（背景调用 NULL）。interrupt 路径 `cost_runs=[]` 只物化已有 call，不伪造 orphan；成功后 emit `cost.recorded`（含 `by_role`）并盖 `messages.cost`（已盖则跳过 emit，防双记日志） |
| 写入失败语义 | 同步写失败：warning + **落盘出队后台 drain 重试**（at-least-once）；回合正文已先提交，不因账本失败回滚 |
| 失败 run 计费 | 硬失败（worker `raise_on_error` 抛错、CEO/续跑循环崩溃）仍按**已完成轮**入账——`usage_sink` 把已计量 usage 从抛点带出，经 `calculate_cost` 折钱落 `FAILED` 行（token 已真花在用户 key 上，漏记 = 平台/用户白付）；用户主动取消（`CancelledError`）**不为取消本身造 FAILED 折算行**（`except Exception` 不捕 `BaseException`）——但**已成功 call 仍在 incomplete 收口时对账**（见上「写入时机」）。vision 等仅挂内存 `cost_runs` 的孤儿在 cancel 时可能仍漏物化（本案不抢救） |
| 真相源 | `cost_calls`（明细权威）；`cost_events` 为产品读侧聚合视图；`Message.usage` 仅展示快照。开发期无历史回填——老行可缺明细/`persona`；单回合工资单与 `cost.recorded` 读侧可用 `COALESCE(persona, role)` |

→ 见代码 `runtime/costing.py`、`db/repositories/billing.py::CostEventRepository`、`billing/attribution.py`、失败计费 `runtime/runs/executor.py::_priced_failure`

> **旁路解耦（重度并行止血 · ✅）**：共用落盘账本队列 `billing/cost_ledger_queue.py`——推理代理 `_record_proxy_spend`（`proxy.py`）与云 in-process call meter、主回合 finalize / handoff 同步写失败时一律入队。后台 drain 写 `cost_calls` / `cost_events`（at-least-once，`call_id` / `run_id` UNIQUE 去重），写库走 **telemetry 独立池**——与正文写 `primary` 池按 `DatabaseSettings` 分预算（`config/database.py` 双引擎）。故重度并行 debate 打爆连接池时，计费 / 审计 / journal / roster 等**遥测写永不饿死正文落库**（journal write-behind、audit / roster 回合内异步投递 + 回合末 flush，均走此池）。落盘队列**单进程**本地盘即可；**多 worker 化前须迁 Redis / DB outbox**（本地盘多实例会丢 / 双消费，代码注释已标）。→ 见代码 `billing/cost_ledger_queue.py`、`billing/proxy_spend_queue.py`、`config/database.py`。

## 六、成本预估 ≠ 实际记账

团队组建时提供启发式预估，与真实记账是两套东西，刻意如此：

- 预估用途是**比较不同团队组合的贵贱**（「三个 premium 模型会很贵」），不是预测真实账单
- 算法基于固定假设（Captain 跑 3 轮、队员各 2 轮，每轮约 3000 输入 + 700 输出 token）
- 假设串始终展示给用户，确保该数字永远不被误当成事实
