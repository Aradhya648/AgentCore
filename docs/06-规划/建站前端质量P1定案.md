## 谁用 / 解决什么 / 产品如何呈现

| 问 | 答 |
|---|---|
| 谁用 | 无设计提示词、让产品 AI「搜 X + 做官网」的终端用户 |
| 真实问题 | P0 只拦确定性坏味道；仍可「合规但平庸」（无品牌锁定、无壳可抄、无渲染反馈） |
| 产品呈现 | 质量管线藏在 `build_website` 内；用户可见：开工提案卡选风格 → 更好的站；无 browser/vision 时诚实标未目验，不装已过视觉 QA |

## 目标与边界

**目标**：从「不触发 anti-slop 黑名单」推进到「有可检查的设计契约 + 素材约束 +（后期）视觉反馈」。

**边界（做）**

- 仅建站 / 落地页 / 营销官网路径（`build_website`）。
- 设计源文件与静态对账、内置精选 section 壳、截图→VLM critic（分期）。
- 风格人确认：`ask_user` 开工提案卡硬闸（相对 P0 的 prompt 软约束升级）。

**边界（不做 / 暂缓）**

- 用户上传完整设计系统（Lovable 级）——太重。
- Design Arena 分榜模型路由、anti-slop 全面升 hard——等 P1a/b 有样本再定。
- 把 AgentCore 桌面 `@agentcore/design-tokens` 当作用户站点色板（那是产品 UI，不是生成站）。
- CEO 自拟视觉施工图（P0 已禁，P1 不重开后门）。

### 修订 1 · 风格双闸（2026-07-23 拍板；同日收紧 wire）

1. **Kickoff 闸**：建站意图的 `ask_user`（`intent=kickoff`）**强制非空** `style_options`，option **value/id 必须**为 `s0/s1…`（`normalize_style_options` 铸造），否则**拒调**。
2. **Resume 记账（A ✅）**：`POST .../resume` 显式 `style_id`（优先）→ 否则 `selected` 中合法 `sN` ∈ 当次 options → **禁止**纯 note/散文模糊匹配独过闸。非法 `style_id`（∉ options）拒收（不记账）。确认后写入 turn journal fact `website_style_confirmed`，并快照进 `turn_paused.website_style`；resume / 后续 `build_website` 从该源再水化（进程内 memory 仅热缓存）。
3. **DESIGN 闸**：`site/DESIGN.md` 缺「用户选定风格 id」→ **skeleton / section** 走 `web_quality` **hard** contract fail。
4. **挂点**：`ask_user`；**不是** `team_preview`，**不**强制改走 `proposal_pick`。
5. **`full_auto`**：仅建站风格确认的**窄豁免**——须落**默认风格**进 DESIGN 并写入同一记账；闸 **keyed on `build_website`**，勿误伤非建站委派。
6. **客户端**：桌面 + 手机同 resume 面 — compose 直传 `style_id`，并在 `selected` 附带 `sN`（A 路径兜底）。

### 修订 2 · 散色 / 缺 DESIGN 一律 hard

- 实现层硬编码色值 ⊈ DESIGN tokens、或缺 `site/DESIGN.md` → `web_quality` **hard** fail（与语法损坏 / 编造联系方式同族）。
- **禁止**「先 soft 再硬」的两段式；anti-slop 视觉指纹仍走既有 soft_accept（最多一回炉）——语义不变。

### 修订 3 · 默认独立 `design` 节点（五波）

- 波次：`copy → design → skeleton → sections → qa`（**五波不可减**；含 design）。
- `split_copy` 时：`design.depends_on` = 全部文案节点；`skeleton.depends_on = ["design"]`。
- `design` artifacts 含 `site/DESIGN.md`（色板 / 字体 / 间距 / 对比度策略 / 禁止项 / **用户选定风格 id**）。
- 骨架与分区任务书：只引用 DESIGN tokens；禁止散写色值。

### 修订 4 · 质检预算结构（2026-07-23 拍板 · 反「加大留油」补丁）

**谁用 / 问题 / 呈现**：建官网五波同对话共用一个油箱时，整页 QA 常排在最后被顶掉；用户要的是「别假装验过」+「还能怎么验」，不是再调一个预留数字。

**决定（3 底 + 2 主）**

1. **同对话底线** = 各**分区落盘时**的自动检查（`web_quality` / `{{}}` / 接缝等）——不靠最后再养一个大质检员吃剩油。
2. **整页总检 / 视觉验收** = 可与建站同波；油不够则 **诚实 defer**（`qa_deferred_budget`），提示 **下一回合续派验收**，不抬 `delivery_reserve` / 全局 ceiling 当主修复。
3. 交付预留（旧方案 C）降为**次要辅助**，禁止再加大预留数字冒充结构修复。

**否决**：只把预留从 20 万调到 50 万；只加 prompt「省着点给质检」。

**验收**：跳过页面 QA → partial +「续派验收」缺口文案；**不得**谎称「从未跑过 web_quality」（分区可能已跑）。回归锚：`f6104698…`。

**第二段落地（修订 4 续 · 可点 CTA）**：`playbook=build_website_verify`（slot `site` 必填，只展开 QA 波、`deferred_ok=False`，要求已有 `site/`）；`delivery_status.actions[]` 在 gap reason=`qa_deferred_budget` 时发 `kind=website_verify` + `prompt`；桌面完成条件卡「续派页面验收」一键 `sendTurn` 该 prompt。风格/none 硬闸仍只认绿场 `build_website` / `build_toolshed`（verify 走具名 playbook + follow-up 豁免口径）。

### 修订 6 · 工具台 vs 营销分流 ✅

**决定（已锁定并落地）**
