# 通用多 AI 模拟平台：愿景与后续路线

> **定位**：AgentCore 从任务型多 Agent 协作平台向通用多 AI 模拟平台扩展的战略规划。
>
> **状态**：🗂️ 方向已确认，后续阶段尚未承诺排期。
>
> **边界**：本文只保留战略理由、后续路线与未决问题。AI 小镇已经落地的后端和客户端现状分别见 [运行时总览](/docs/03-AI核心/运行时总览.md#ai-小镇模拟) 与 [AgentTown 客户端](/docs/04-前端/AgentTown客户端.md)；开发运行方式见 `apps/town/README.md`。

## 一、愿景与定位

### 1.1 一句话

不只是让多 Agent 帮人完成任务，而是把 LLM Agent 作为可编程的“模拟人”：赋予不同角色、知识、目标和约束，放进共享环境持续交互，并观察由此产生的群体行为。

### 1.2 任务型与模拟型的差异

| 维度 | 任务型多 Agent | 通用多 AI 模拟 |
|---|---|---|
| 驱动力 | 用户给出外部任务 | 角色目标、关系与环境变化驱动 |
| Agent 关系 | 围绕交付协作 | 合作、竞争、欺骗、结盟等都是场景要素 |
| 时间模型 | Turn / Wave，交付后终止 | Tick / Epoch，可持续运行 |
| 人的角色 | 委托、拍板、验收 | 设计实验、观察、调参、比较分叉 |
| 成功标准 | 交付质量、成本、时延 | 可观察、可解释、可复现、可比较 |
| 涌现行为 | 通常需要抑制 | 核心研究与观看价值 |

模拟平台不是替换现有协作产品，而是同一产品内核上的第二条增长曲线：

- 复用 LLM 网关、事件流、审计、回放和实验基础设施；
- 新增世界状态、内生动机、结构化交互、实验分叉与群体指标；
- 产品心智从“我带领 AI 团队完成任务”扩展到“我观察一群 AI 如何演化”。

## 二、目标用户与场景

### 2.1 用户优先级

长期优先级保持为：

1. 研究机构与政策智库；
2. 企业战略与组织研究；
3. 大众教育与内容消费。

传播与深度产品采用双入口：AgentTown / AI 恋综负责降低观看门槛和形成传播；经济、博弈、社会实验负责验证平台的研究价值。

### 2.2 场景版图

| 场景 | 典型问题 | 需要验证的通用能力 |
|---|---|---|
| AI 小镇 | 角色关系、交易、投票和事件如何共同演化 | 世界状态、记忆、自由交互、观测回放 |
| 博弈实验 | 合作、背叛、拍卖与联盟在不同机制下如何变化 | 规则协议、重复实验、结果比较 |
| 经济沙盘 | 政策或供需冲击如何沿主体网络传播 | 资源与市场、宏观指标、反事实分叉 |
| 社会传播 | 舆论极化、谣言与信任网络如何形成 | 社交图、信息扩散、群体指标 |
| 组织行为 | 激励与信息不对称如何影响组织决策 | 层级关系、私有信息、制度规则 |

AI 小镇仍是通用引擎的首个锚定场景；[AI 恋综场景提案](AI恋综场景提案.md)（2026-07-13 纠偏定案）已并入小镇主线——恋综作为 AgentTown 内的节目功能、`simulation/` 的**第二个场景**推进，实质先于博弈/经济沙盘承担通用层验证。

## 三、已落地基线

Phase 1 已完成足以继续验证的工程基线：

- 后端 `simulation/` 具备世界时钟、居民决策、对话/交易/投票、事件、指标、持久化与回放；
- AgentTown 具备 Unity 3D 小镇、Offline/scripted 演示、Live/Replay、观测 HUD 与 WebGL 连通能力；
- Desktop 仅作为可选启动器，不承载 3D 世界；
- 世界快照是权威状态，客户端只消费 REST/SSE 契约。

本段只说明后续规划的起点，不承担现状细节。权威现状见 [运行时总览](/docs/03-AI核心/运行时总览.md#ai-小镇模拟) 与 [AgentTown 客户端](/docs/04-前端/AgentTown客户端.md)。

## 四、演进原则

| 原则 | 约束 |
|---|---|
| 场景驱动抽象 | 只抽取当前场景真正需要的能力 |
| 两场景验证 | 第二场景无需重写核心层，抽象才算成立 |
| 世界状态权威 | Agent 记忆与客户端表现都可由 tick 快照对账 |
| 实验可复现 | 固定并记录场景配置、种子、模型、温度与版本 |
| 观看与研究分开验收 | “好不好看”不能用宏观指标替代，机制发现也不能只靠观感 |
| 不以复用裁剪需求 | 模拟编排不强行套用 CEO/DAG；出现真实依赖后再抽象调度能力 |

## 五、后续路线

> 项目目前没有真实用户数据、真实质量分或稳定的真 LLM 长跑样本。以下顺序是产品与技术假设，须逐门验证。

### Gate 0：验证真 LLM 涌现

**目标**：先证明居民不是只会复读、同质化和机械执行脚本。

最小验证：

- 3–5 个真 LLM 居民连续运行约 10 tick；
- transcript 中能识别角色目标对行动的因果影响；
- 不出现明显复读、快速同质化或持续人设漂移；
- 由人评估是否存在值得继续观看的关系或事件变化。

若失败，先收敛为“强场景节拍 + 有限自由度”，回炉人设、动机与记忆，不直接扩大居民数或交互种类。

### Gate 1：产品化与 Web 传播

**目标**：把“仓库内可演示”推进到“用户可稳定打开和分享”。

候选范围：

- 发布 WebGL 传播版，并定稿浏览器认证与会话传递；
- Unity CI、Windows 安装包与构建 smoke；
- 补齐 token 刷新联调和 `sim.*` conformance；
- 用 Profiler 固化性能基线，而不只依赖顶栏 FPS；
- 真 LLM 模式下完成可重复的 5+ tick 观看验证。

是否投入 macOS 构建，在 Windows/Web 入口验证后再决定。

### Gate 2：第二场景与通用层验证

**目标**：用第二场景证明当前小镇特化能力可以上提为通用模拟能力。

**2026-07-13 更新**：AI 恋综已定案为实际推进中的第二场景（新增交互类型、赛制状态机、期编排、导播产物；见 [AI 恋综场景提案](AI恋综场景提案.md)）。博弈/经济沙盘退为第三场景候选：

- 博弈论湿实验：规则清楚、结果容易比较，适合验证交互协议；
- 简化经济沙盘：更接近长期研究价值，但市场与指标工程更重。

本阶段才评估：

- 从小镇特化代码提取稳定的场景接口；
- 新增市场或博弈协议；
- 同一初始状态的 A/B 分叉与差异高亮；
- Run Manifest、种子和模型配置的一键复现。

### Gate 3：开放场景与规模化

在两个场景验证通用层后，再考虑：

- 第三类场景；
- 场景模板或 DSL；
- 参数网格与批量实验；
- 100+ Agent 的分层激活和成本治理；
- 对外 API、可复现包与场景生态。

## 六、核心风险

| 风险 | 主要表现 | 当前方向 |
|---|---|---|
| 行为漂移 | 长运行后忘记人设、目标稀释 | 世界状态对账、关键事实记忆、低频反思 |
| 可复现性 | 同配置多次运行结论相反 | 固定并记录可控变量；报告方差而非伪造确定性 |
| 成本与时延 | 多 Agent × 多 tick 推理量过大 | 分层激活、规则背景角色、关键决策用强模型 |
| 验证困境 | 模拟结果被误当现实预测 | 定位为机制实验和反事实比较，不做点预测承诺 |
| 观看价值不足 | 指标完整但内容无聊 | 独立的人评观看门；必要时增强场景节拍 |
| 过早通用化 | 接口抽象脱离真实场景 | 两场景后再冻结通用层 |

## 七、已确认决策与未决问题

### 已确认

- 在 AgentCore monorepo 内演进，不另开后端产品线；
- AI 小镇是首个锚定场景；
- 3D 观测客户端采用 Unity，Web 传播能力是关键原因；
- 核心引擎与场景生态的开源/商业边界以后续产品验证为前提；
- AI 狼人杀不作为首发方向，AI 辩论也不作为模拟平台标杆场景。

### 未决

- Gate 0 的“值得观看”采用何种稳定人评方法；
- 第三场景选择博弈实验还是经济沙盘（第二场景已定为恋综，2026-07-13）；
- WebGL 传播版的认证、部署与公开访问边界；
- 研究工具与大众观看产品是否需要不同的观测界面；
- 何时具备足够证据投入规模化和开放场景定义。
