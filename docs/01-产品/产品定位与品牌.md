# 产品定位与品牌

> **状态**：✅ 已确定（产品定位、核心理念、差异化、品牌体系、角色策略）

→ 运行时术语见 [/docs/01-产品/术语表.md](/docs/01-产品/术语表.md)

---

## 核心问题

AgentCore 是什么？为谁解决什么问题？凭什么区别于 ChatGPT / Cursor / Codex / Coze？

---

## 一、产品定位 ✅ 已确定

面向大众的 Multi-Agent AI 工作台，对标 Cursor / Codex / Claude，但以 **Agent 团队协作**为核心差异点。

现有产品本质是「单 Agent + 子任务派发」，缺少真正的团队协作。AgentCore 让多个 AI Agent 像团队一样分工、协商、互审，共同完成复杂任务。

| 维度 | 说明 |
|------|------|
| 品类 | 协作智能平台（Collaborative Intelligence Platform） |
| 对标 | Cursor / Codex / Claude / Coze |
| 核心差异 | 真正的 Agent 团队协作，而非「单 Agent + 子任务派发」 |
| 目标用户 | 全量知识工作者：开发者、研究人员、写作者、分析师、小型团队等，不限定垂直人群 |

---

## 二、核心理念 ✅ 已确定

> **协作，是更高级的智能。**

人类文明的突破从来不是因为某个人变得更聪明，而是因为我们学会了分工与协作。AI 也一样——单个模型的智能有天花板，协作智能没有。

用户心智模型是「**掌管一支由 AI CEO 带队的 Agent 团队**」——你是老板，定目标、拍板，团队替你跑，而非「和一个助手聊天」。差异化在于协作、分工、可观测，而非单会话体验。

---

## 三、差异化定位 ✅ 已确定

> **AgentCore — 协作智能平台（Collaborative Intelligence Platform）**

不是「AI 助手」，不是「AI 代码编辑器」，而是一个让多个 AI Agent 协作完成复杂任务的平台。

### 定位体系

| 层级 | 内容 | 使用场景 |
|------|------|----------|
| 品牌理念 | 协作，是更高级的智能 | 品牌叙事、关于页面 |
| 品类定义 | 协作智能平台 | 产品介绍首句、官网标题 |
| 产品标语 | AI 的下一步不是更聪明的个体，而是更好的协作 | 官网副标题、宣传素材 |
| 功能标语 | 多 Agent 协作 · 全程可见 · 你是领导者 | 功能页、仓库首页 |
| 竞品对比 | 单个模型的智能有天花板。协作智能没有。 | 对比页、PR 回应 |

### 用户角色定义

AgentCore 重新定义用户与 AI 的关系——从「使用者」升级为「领导者」：你是老板，连 AI CEO 都替你带队，你只管定目标、拍板。

| 竞品 | 用户是… | AgentCore |
|------|---------|-----------|
| ChatGPT / Claude | 提示者（Prompter） | 领导者（Leader） |
| Cursor / Codex | 指令者（Commander） | 老板（Boss） |
| Devin / Manus | 委托者（Delegator） | 决策者（Decision-maker） |

### 竞品差异化方向

| 维度 | 说明 |
|------|------|
| Agent 身份 | 动态角色分配（CEO 按需 `delegate` 分配）+ 用户级跨会话记忆 |
| 协作模式 | Agent 间协商、互审，非仅父任务派发 |
| 场景覆盖 | 编码 + 研究 + 设计 + 写作等通用知识工作 |
| 场景连续性 | 一个工作台 + 多 Agent 团队跟随**同一用户**跨「写代码」与「研究 / 写作 / 分析」两类活；竞品各守一半（Cursor 只「改仓」、ChatGPT 只「聊」） |
| 扩展生态 | MCP（工具层）+ A2A（Agent 层）开放协议 |

### 赛道判断

AgentCore 与 Codex / Claude / Cursor 不在同一赛道——不在「通用 AI 助手」或「代码 Agent」赛道正面对抗。

| 产品 | 本质定位 | 核心用户 |
|---|---|---|
| Codex (OpenAI) | 自主式代码 Agent（异步任务、沙箱执行、PR 闭环） | 开发者 |
| Claude (Anthropic) | 通用对话 AI + 工具使用 | 泛知识工作者 |
| Cursor | IDE 内嵌交互式编码助手 | 开发者 |
| Devin | 自主软件工程 Agent | 工程团队 |
| Coze / Dify / GPTs | 低代码 Agent 构建平台 | Agent 创作者 |
| **AgentCore** | **协作智能平台**（长期延伸至 Tool/Skill/Rule/Agent/Team 生态） | **终端用户 + 创作者** |

更接近 **Coze/GPTs 的生态位 + Codex/Devin 的运行时深度**，但以 Multi-Agent 协作为核心差异。

### 三维竞争壁垒

竞争力在三个方向的交叉地带——该交叉点目前无人占据：

| 壁垒 | 说明 | 竞品对比 |
|---|---|---|
| **Multi-Agent 原生架构** | 委派一等公民、层级编排、统一执行路径 | Codex/Claude/Cursor 本质单 Agent |
| **行业垂直深度** | 平台核心行业无关 + 垂直能力可叠加 | 竞品无行业垂直维度 |
| **生态平台闭环** | Tool/Skill/Rule/Agent/Team 五类资产市场 | GPTs Store 仅有 Agent 一类 |

### 关键差距与应对

| 差距 | 说明 | 应对 |
|---|---|---|
| **底层模型能力** | DeepSeek vs GPT-4/Claude | Gateway 已抽象，切换工程成本低；预留多模型混合策略 |
| **代码执行 / Git** | 无 Docker 沙箱和 Git 闭环 | P2 规划，MVP 用受限 subprocess |
| **异步自主执行** | ✅ 回合级续跑已落地（`paused_turns` + `POST /resume`）；⏳ 跨进程 Redis、Fork 等余项 | 见 [`执行引擎架构设计.md` §暂停与恢复](/docs/03-AI核心/执行引擎架构设计.md) |

### 演进优先级

| 时间段 | 方向 | 理由 |
|---|---|---|
| 短期（0-3月） | 多模型 Gateway + 核心体验打磨 | 消除模型短板，强化差异化 |
| 中期（3-6月） | 跨进程挂起 Redis + Fork + 第二垂直行业 | 续跑余项与可插拔架构复制（→ 远期规划 §三；详细提案不在公开仓 / 维护者本地） |
| 长期（6-12月） | 开放 Agent 通信协议 + 代码沙箱 + 多表面统一 | 建立生态壁垒 |

## 四、Agent 角色策略 ✅ 已确定

不做预制 Agent 角色，采用「**动态角色分配 + 用户可选行为模板**」模式。

| 原则 | 说明 |
|------|------|
| 无预制身份 | 系统中没有「代码 Agent」「写作 Agent」这种固定角色 |
| 动态专精 | CEO 根据任务自动为协作 worker 分配临时角色 / 工具集 |
| 行为模板（可选） | 用户可保存「我的代码审查工作流」作为可复用配置，但不是固定角色 |
| 用户自定义 | 高级用户可创建 Agent 配置（system prompt + 工具集 + 记忆偏好），作为 power feature |

### 为什么不做预制角色（被否决方案）

1. 预制角色把路由决策推给用户，与「管理团队」心智模型矛盾
2. 真实任务跨域，预设边界僵硬
3. LLM 能力增长会让专精角色过时
4. 竞品数据表明无产品因预制角色而赢得市场

> Day 1：CEO 按需 `delegate` 自动分解任务、决定 worker 数量/角色/工具集、单多 Agent 自适应。行为模板属 Day 2（见 §七）。

---

## 五、决策理由

1. 「协作智能」创造新品类，避免在「更强模型」维度与巨头直接竞争
2. 与产品技术架构完全对齐——多 Agent 协作是真实能力，不是营销包装
3. 中英文双语自然（协作智能 / Collaborative Intelligence），利于国际化
4. 为未来品牌扩展留空间（协作智能生态、协作智能开发者平台等）

---

## 六、行业趋势与演进原则 ✅ 已确定

### 行业走向（2026）

1. **交互 + 自主双模共存**：交互式（Cursor/Claude Code）和自主式（Codex/Devin）不互斥，多数团队组合使用
2. **编排框架收敛**：LangGraph 是生产级主流，但 AgentCore 自研以保持架构自由度
3. **协议标准化**：MCP（工具层）+ A2A（Agent 层）三层协议格局形成

### 现有优势（保持并强化）

| 优势 | 行业对比 |
|---|---|
| Multi-Agent 原生（委派 + DAG/Sequential/Parallel） | 比 Codex/Cursor 更完善 |
| 统一执行路径（单 Agent 和 Team 走同一代码路径） | 架构干净 |
| Marketplace 生态（工具/技能/规则市场） | 有生态基础 |
| 基建完备（PostgreSQL + Redis + SearXNG；NATS/MinIO 等为旧版/未来组件，本仓不依赖） | 接入成本低 |

### 演进原则（不变）

渐进兼容、复用基建、Multi-Agent 优势最大化、先跑通再优化。

## 七、产品迭代边界（Day 2+）✅ 已确定

MVP Day 1 全部 6 个核心模块全量交付。下列为 Day 2 及以后迭代方向：

| 模块 | Day 2 迭代 |
|------|-----------|
| 基础聊天 | 富文本（表格/图表/LaTeX）、多模态输入、对话分支/编辑、语音 |
| 多 Agent 执行 | 智能汇总（LLM 综合多 Agent 结果） |
| 动态角色分配 | 手动调整角色、行为模板、用户自定义 Agent 配置、对话中逐步升级 |
| 工具接入 | MCP、数据库查询、第三方 API、用户自定义工具 |
| 任务进度展示 | 5 层信息披露、minimap |
| 基础记忆 | 语义检索（pgvector）、记忆重要性分级、遗忘机制 |
