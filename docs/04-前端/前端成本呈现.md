# 前端成本呈现（成本规格 §七 · 团队工资单 + 账户仪表盘 + BYOK 估算）

> **定位**：成本规格的 **§七**——前端 VIEW 层现状说明书，承接后端/读侧 [`../05-平台与运维/成本配额与计费.md`](/docs/05-平台与运维/成本配额与计费.md)（§〇–六：定价不变量、per-run 台账、读端点、决策①②③④）。本文只记录前端呈现的决策与约束，实现细节见代码指针。
>
> **数据层（✅ 已落地）**：`services/usage.ts`（REST 读：工资单/仪表盘）、`stores/usage.ts`（汇率单一源 + per-turn 缓存）、`lib/format.ts`（金额/紧凑数/时长格式化）、`execution` 的 `RunNode.{cost,usage}`（SSE 实时投影）。

## 7.1 信息分层（恒展示，无粒度开关）

**没有「用量明细 / Power」粒度开关**（早期 `usageDetail` 已下线）——token / 成本明细与 run-detail「资源消耗」**恒展示、默认展开**（`UsageSettings.tsx` docstring：default-expand are always on）。信息密度靠**位置**分层，不靠用户开关：

- **inline 只做信号**：气泡 meta 行 / 图状态条给「¥ + token + 轮次」摘要；**详情进面板**（run-detail「资源消耗」给全量拆分）。
- **¥ 永远可见**；token / 三价 / 思考 / 缓存拆分在 run-detail「资源消耗」展开即全显（不再有大众 vs Power 之分）。
- **省钱呈现**：前缀缓存节省 = `cache_hit × (miss 价 − hit 价)`，后端 `pricing.cache_savings` 提供，前端在 run-detail「资源消耗」以「缓存省 $X」呈现（`cost.cached`）。
- **与诊断模式正交**：面向开发者的底层诊断（run / trace id 等）是**独立开关** `diagnosticMode`（`stores/ui.ts`，仍在），与「用量 / 成本」呈现无关——详见 [前端 UX §十「诊断 / 开发者模式」](/docs/04-前端/前端UX设计.md)。

→ 见代码：`pages/more/UsageSettings.tsx`（仪表盘）、`components/chat/detail/RunDetailBody.tsx`（`ResourceSection … defaultExpanded` 恒展开）、`stores/ui.ts`（`diagnosticMode`）。

## 7.2 格式化与汇率

- 金额一律整数 nano-USD（1 USD = 10⁹）流转，前端**不写死汇率**：`cnyPerUsd` 单一来源 `useUsageStore`（由 `/usage/summary` 下发的 `cny_per_usd` 刷新，首屏前用后端默认兜底）。
- 格式化函数：`formatCost`（¥）、`formatUsd`（$）、`formatCompact`（token 等大数）、`formatDuration`（用时）。
- **0 成本约定**（与 §7.5 同源）：0 / 无花销显「—」，绝不显「¥0.00」；有花销但折算 < 1 分显「<¥0.01」。

→ 见代码：`lib/format.ts`、`stores/usage.ts`。

## 7.3 三级呈现

落地决策③「大众可见粒度」（见 [`../05-平台与运维/成本配额与计费.md`](/docs/05-平台与运维/成本配额与计费.md) §五）：钱人人可见，token / 技术拆分在详情面板展开即全显（按**位置**分层，非用户开关）。

| 层 | 位置 | inline 摘要 | 详情展开 | 数据源 |
|---|---|---|---|---|
| 7.3A 回合 | 助手气泡 meta 行 / 图状态条 | ¥ + Agent 数 + 轮次(>1) | + token 用量(输入/输出/思考/缓存) | `message_end.{cost,usage,rounds}` / `run_completed` |
| 7.3B 节点/run 成本 | run-detail「资源消耗」（图节点不显钱，仅用时·工具） | 该 run ¥ 合计 | + 档位·思考 / model / 三价 / token 拆分 | `run_*` 成本（`RunNode.cost`，回放自 `message.runs`） |
| 7.3D 账户仪表盘 | MorePage「用量」 | 语义额度条 % + 本月各角色花销 | token/成本拆分明细 | `GET /usage/summary` |

**差异点**：Multi-Agent 把每个 Agent 的 ¥ 透明到 run 粒度——点协作图节点进 run 详情看该 Agent 的 ¥，并在账户仪表盘按角色汇成「本月各角色花销」工资单——单 Agent 竞品做不到。

> **7.3C 对话累计已退役**（编号 A/B/D 故意留空缺 C）：对话头常驻「本对话 ¥X」caption 与「零门槛/零噪音」冲突，且 `<¥0.01` 噪音大、信息量低；成本透明已由 7.3A（回合）+ 7.3B（节点）+ 7.3D（仪表盘）覆盖。后端 `GET /conversations/{id}/cost` 端点保留备用。

### 7.3A 回合成本 + 用量 + 轮次
- 多 Agent：并入内嵌图状态条战绩行（`InlineTeamGraph` 的 `CompletedStrip` / `FailureStrip`）；失败/停止条照常显示「已花 ¥」（无 `message_end` 时经 `resolveTurnCost` 回落到已完成 worker run 之和，下界但仍诚实）。
- 单 Agent：助手气泡底部极淡 caption（`MessageBubble`，仅 `executionId === null` 的回合，避免与状态条重复）。
- 实时用 `message.cost`，回放优先用助手行 **`Message.cost` 列**（finalize 回写，与 title/followups 同辙）；缺列时回落到台账快照（`messageCosts` 缓存，hover 时按需拉 `GET /v1/messages/{id}/cost` 明细）。
- **回合 token 用量 + 轮次（✅ 已落地）**：气泡 hover meta 行随成本展示本回合 **token 用量**（`↑输入 ↓输出`，缓存 / 思考拆分随详情面板）与 **ReAct 轮次**（`N 轮`，仅 >1，避免每条都挂「1 轮」噪音）。
- **与成本不同，所有回合都显（含多 Agent）**：团队卡（状态条）只承载回合 ¥ 合计、不含回合级 token/轮次，故这两项补在气泡 meta 行让多 Agent 气泡不再光秃；¥ 仍按 §7.3A 的 `executionId` 规则——单 Agent 落气泡、多 Agent 归状态条，**不重复展示**。
- 数据：实时 `message_end.usage`（wire 长键 `input_tokens…`）/ `message_end.rounds`；重载经助手行 `usage` 列（长键快照 + `rounds`）投影到 `MessageDetail.usage`（归一化为账本 `UsageBreakdown` 短键，与 run-detail/execution 共用一套 token 词汇）/`MessageDetail.rounds`，`toMessage` 映射回 `message.usage`/`message.rounds`。
- **重载回放（✅ Tier 2）**：`usage`/`rounds` 已随助手行落库——`_persist_turn_result`（及交接 job 路径）把完整 token 拆分（输入/输出/思考/缓存命中·未命中）+ 轮次写进 `usage` 列（**追加**键、不动 `export.py` 读的旧 `{input,output,rounds}`），读路由经上述投影回放，重载后 meta 行与直播一致。**仅无真实花费的回合省略 token**：报错/空回合存零，schema `_usage_from_row` 投影时归零→不显，与直播气泡一致。结局位（`finish_reason` chip / 报错回合 `error` 卡）则随 journal `turn_end` 持久化回放（✅ Tier 2 a+c）。UX 见 [`前端UX设计.md §一B`](/docs/04-前端/前端UX设计.md)。

### 7.3B 节点/run 成本（run-detail 资源消耗）
- 协作图节点 face **保持简洁**：只显**用时 + 工具数**，状态靠图标 + 色环表达，**不再叠 ¥ / token**（`AgentNode`）。**每个 Agent 的钱改由 run 详情承载**：点节点进右侧 run-detail 看该 run 的 ¥。回合合计归状态条（§7.3A），不在别处重复；CEO 收尾被提升为 `synthesis` run 时其成本随该 run 详情呈现。
- **否决·节点 face 直接显钱**（旧实现 `AgentNode.costText`，由 `GraphView` 用 `run.cost.total` 格式化标在节点上）：`<¥0.01` 廉价 run 满屏噪音、且数字与「inline 只做信号、详情进面板」冲突，故 ¥ / token 全部下沉 run 详情；per-Agent ¥ 的差异点改由 run 详情 + 账户工资单（§7.3D）承载。
- **run-detail「资源消耗」是 run 模型与用量的全量明细处**：当前 `model` 名 / 思考强度（原独立「模型与推理」区段并入）/ 成本三价（platform 模式；BYOK 下 ¥ 显「—」）/ token（命中·未命中·缓存率·推理）；**默认展开**（`ResourceSection defaultExpanded`，恒展示）；¥ 合计常驻区段头部（0 / BYOK / 未定价显「—」，与 §7.5 同源）。

→ 见代码 `components/chat/InlineTeamGraph.tsx`、`MessageBubble.tsx`（7.3A）、`components/chat/detail/RunDetailBody.tsx`（7.3B）

### 7.3D 账户仪表盘

- **语义额度条**：与后端 `enforce_quota` 配额维一一对应（本月额度 / 今日额度 / 今日 token / 今日请求）；≥80% 转 `warning`；某维 0=不限则不画进度——内测计费翻转（[成本配额与计费 §〇·六](/docs/05-平台与运维/成本配额与计费.md)）后 `quota_*` 默认组为「本月额度 + 今日额度（日成本维）+ 今日请求」，日 token 维置 0 自然隐藏。
- **本月各角色花销（团队工资单）**：¥ 大众可见，不受 §7.1 开关控制。服务端按 `COALESCE(persona, role)` 分组——新人设行显示「调研员 / CEO / …」，缺 `persona` 的老行仍回落 captain/member 粗分桶；前端 `roleLabel` 对未知键原样展示人设名。
- **近 7 日成本趋势**：柱状 sparkline；后端分桶与窗口常量见 [`../05-平台与运维/成本配额与计费.md` §四](/docs/05-平台与运维/成本配额与计费.md)；前端呈现见 `pages/more/UsageSettings.tsx`。
- 明细（token / 缓存命中率等）**恒展示**（无粒度开关，见 §7.1）。

→ 见代码 `pages/more/UsageSettings.tsx`；金额工具 `lib/cost.ts`（`resolveTurnCost`）。

## 7.4 BYOK 呈现（`billing_mode=byok` 且非免费档）：≈ 估算金额

内测默认 BYOK：用户自备 OpenAI 兼容端点，记账恒 0（该 call 凭据来源 `user` → `cost_total_nano=0`）、token 照常记。✅ 2026-07-15 起 BYOK 不再「¥ 恒显 —」：后端按三层价卡（自填单价 → 社区价目快照 → unpriced，见 [`../05-平台与运维/成本配额与计费.md` §〇·五](/docs/05-平台与运维/成本配额与计费.md)）出**估算金额**（SSE `cost.estimated_total` / REST `estimated_cost` / 工资单行 `cost_estimated_total`），前端呈现铁律：

- **估算金额一律「≈¥X」+ 轻量「估算」标注**（tooltip 说明「按社区价目/自填单价估算，非上游账单」），视觉上不得与平台记账 ¥ 混淆；
- `pricing_source=unpriced`（自填/社区表都没有）金额位维持显「—」，绝不冒充数字；**但有真实 token 花费时必须挂「自带密钥·未计价」显式标注**（拍板 2026-07-20）——静默省略费用段会被读成「免费」，而供应商正在扣用户的钱。图状态条（Completed/Failure strip 经 `hasUnpricedUsage`）、run-detail、单 Agent 气泡 caption 同口径（`COST_UNPRICED_LABEL`，tooltip 指明「实际费用以上游供应商账单为准」）；移动端同口径落地：`TeamView` 资源块区分未计价/估算标注、气泡 caption（live 读 `cost.pricing_source`、重载经 `getMessageCostDisplay` 上报 `unpriced`）；
- 记账钱与估算钱**永不相加**——分别读 `cost.total` 与 `estimated_total`/`cost_estimated_total` 标量（`lib/cost.ts::pickCostMoney` / `resolveTurnDisplayMoney`）。

| 区域 | BYOK 行为 |
|---|---|
| 7.3A 回合 meta | `↑输入 ↓输出` token 照旧；有估算值显 `≈¥`，unpriced 显「自带密钥·未计价」标注（金额不出数） |
| 7.3B run-detail | 展示用户配置的 `model` 名；¥ 合计显 `≈¥`（估算标注）或「N tok · 自带密钥·未计价」；token 拆分照常 |
| 7.3D 仪表盘 | 语义额度条仍「自带 Key 不限额」；「本月各角色花销」= 各角色 token 汇总 + **估算 ¥ 列**（≈ 标注） |
| 配置面（ModelSettings） | 价卡三字段**挂每个服务商**（✅ 2026-07-20 多服务商）：输入/输出单价必须成对填、缓存命中价可选（缺省=输入价），作该端点下模型估算兜底；后台便宜模型改为账号级「后台默认」跨服务商指针（`PUT /users/me/llm-providers/defaults`，可整体换服务商）；编辑服务商走 PATCH 部分更新（省略 key 保留密文），无旧「整表替换须回带价卡」的坑 |
| 委派 / 辩论入口 | `supports_tools=false` 时软提示（可交互、不硬禁用；与后端 preflight warning 一致） |

**为何是估算而非不显**：「看不到具体金额」是 BYOK 用户的头号成本痛点；诚实的估算（来源可解释、≈ 标注、unpriced 不出数）优于「—」。admin 端同构（全站/用户明细的估算列带同一语义标注）。

**免费档例外（`free_tier_active`，无 key 用户平台代付）**：呈现走 **platform 语义**（¥ 可见、真算价）——切换跟随 call 级凭据来源落到的账本数字，气泡/详情读账本即自然正确，前端不二次判定。仪表盘：「本月额度」条标签改「**本月免费额度**」+ 已用 %，≥80% 告警文案换转化语境（「接近本月免费额度，用完后请接入自己的模型继续」）；页头描述同语境（「免费额度」文案仅此月度条 + 耗尽错误条，**不**进 `ModelPicker`）。**判定**：`byok 分支 = billing_mode==="byok" && !free_tier_active`——免费档用户绝不进「自带 Key 不限额」分支。`billing_mode` / `free_tier_active` 由 Usage / 配额面消费；`ModelPicker` 同 id 双来源徽标统一「平台额度」（见 [前端 UX §二 / §十三](/docs/04-前端/前端UX设计.md)）。

→ 见代码 `pages/more/UsageSettings.tsx`。

## 7.5 边界与约定

| 场景 | 处理 |
|---|---|
| 实时 vs 回放 | 执行中 `run_completed.cost` / `message_end.cost` 点亮；回放优先助手行 `Message.cost` 列（finalize 回写），缺列回落台账快照（与 §7.3A 同源） |
| 流式期间 | 成本是**完成时事实**（usage 只在末 chunk）；未完成不显，完成即替换为 ¥ |
| 0 成本 | 显「—」，不显「¥0.00」（与 §7.2 同源） |
| 颜色 | 仅 `primary`（占比/进度条）/ `warning`（额度告警）/ `muted`（次要文本）；遵 `color-tokens.mdc`·`desktop-layout.mdc`（成本数字 `text-xs`，条 `rounded-full`） |

## 7.6 配额/限流拒绝（✅ 已落地）

限流 / 配额都在 SSE 开始前返回纯 JSON 429（非事件流），前端在对话输入上方弹错误条并**按 `code` 分流**：

- `QUOTA_EXCEEDED`：展示后端原文（已含重置时间与「联系管理员提额」），**不给重试**——须等窗口重置；附次级「接入自己的 Key」CTA 直达模型配置（byok 回合不查配额，是真正的绕过路径，成本规格 §〇·六 F6）
- `FREE_TIER_EXHAUSTED`：转化语义——后端 CTA 文案 +「去设置」直达模型配置（经共享 `KEY_CONFIG_ERROR_CODES` 目录，与 402 `LLM_KEY_REQUIRED` 同一处置面；见 [前端 UX §二](/docs/04-前端/前端UX设计.md)）
- `RATE_LIMITED`：展示冷却提示（`Retry-After`），**可重试**

拒绝文案以后端 `message` 为**单一来源**，前端原样展示、不另造。后端防线语义见 [`../05-平台与运维/成本配额与计费.md` §一](/docs/05-平台与运维/成本配额与计费.md)。

→ 见代码 `lib/errors.ts`（`describeError` / `errorActionForCode`）、`services/streamConversation.ts`
